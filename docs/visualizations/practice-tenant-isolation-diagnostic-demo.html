409 为什么会扩大成“所有模块不可用”
后端字段映射问题 + 前端初始化耦合，共同形成阻断

    

      
1
数据库已经有学校字段
practice_sessions.school_id = school-A

      
2
Repository 映射曾漏掉字段
数据库行转换成业务对象后，session.schoolId === undefined

      
3
生命周期同步抛出 409
sessionScope() 无法构造学校+用户范围

      
4
Promise.all 整体失败
历史会话失败使模块配置也无法落到 UI 状态

      
5
入口全部消失
角色、场景、道具、分镜、配音看起来都不可用

    
listModules()        ✓ 成功
listProjects()       ✓ 成功
listSessions()       ✕ 409
──────────────────────────
Promise.all(...)     ✕ reject
setVisibleModules()  ✕ 未执行
UI 模块入口           = 空
真正的产品级问题不是只出现一条 409，而是历史数据请求与核心模块能力被绑定在同一个失败域里。

已定位问题卡片
按实际用户影响排序

    
P0 · 已修直接根因
Session schoolId 映射丢失
SQL 有字段，业务对象没有字段，生命周期同步直接返回 409。

    
P0 · 尚未修复
历史请求拖垮全部模块
listSessions 失败后模块能力不写入状态，所有入口消失。

    
P1 · 项目隔离
Canvas / Drama 详情只按用户
转校后仍可能通过旧项目 ID 访问学校 A 数据。

    
P1 · 历史归属
NULL 项目自动对当前学校可见
列表里的 OR school_id IS NULL 与“不自动归属”规则冲突。

    
P1 · Script
旧剧本链路只按 owner
项目、版本、实体、阶段和 Agent 操作没有完整学校过滤。

    
P1 · Task
任务 API 只校验 userId
练习任务读取、恢复、取消没有重新验证当前学校。

    
P1 · Schema
旧剧本自动回填当前学校
转校后可能把旧项目错误归属到新学校，违反最终存量策略。

    
P1 · 未提交代码
排队分支判断时机错误
queuePractice 在 createTask() 前判断，绕过并发的分支不会生效。

  


  
建议分阶段修复
每阶段独立测试、提交和部署，避免再次形成 14,000 行混合变更

  • 保留 schoolId 映射修复

  • 修正排队控制流
  • 真实 PostgreSQL 回归

    
PHASE 2

  • Canvas 详情/写操作
  • Drama 详情/写操作

PHASE 3
Task / Result
  • 读取重验学校
  • 恢复/取消重验学校
  • 结果关联校验学校

    
PHASE 4
Script 统一
  • 旧 Repository 改 Scope
  • 导入写 schoolId
  • 移除错误自动回填

    
PHASE 5
跨校 E2E
  • A 校创建
  • 转入 B 校
  • 不可读写旧数据
  • B 校新数据正常
