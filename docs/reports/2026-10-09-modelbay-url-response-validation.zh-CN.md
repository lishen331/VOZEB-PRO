# 2026-10-09 ModelBay 图片 URL 响应能力验证

## 结论

**支持。**在测试服务器内使用现有 ModelBay 渠道凭据（仅在容器内解密、不输出）直接请求 `POST https://api.modelbay.io/v1/images/generations`，指定 `response_format: "url"`，分别以1024×1024及课堂实际16:9中画质参数得到HTTP 200、约448字节JSON，`data[0].url`存在、没有 `b64_json`。测试服务器随后可访问返回URL，成功读取PNG。没有修改平台渠道配置或生产环境。

| 参数 | 模型响应 | URL取图 | 图片 |
|---|---|---|---|
| `1024x1024` / `medium` | HTTP 200，18.16秒，JSON 448字节，URL域名 `storage.fonedis.cc` | HTTP 200，1.94秒 | 1,418,440字节PNG |
| `2720x1536` / `medium` | HTTP 200，22.93秒，JSON 448字节，同域名 | HTTP 200，2.35秒 | 6,427,634字节PNG |

对照此前16账号 `b64_json` 同波次：ModelBay上游响应头等待平均26.7秒，之后约6–7MB JSON响应体读取平均14.1秒、最慢19.8秒。URL模式把大JSON变成小JSON，但平台仍需从图片URL下载约6MB PNG并写OSS；从测试服务器直接取图样本为2.35秒。生成本身等待时间不会因URL模式消失。

## 平台接入前的必要验证

现有 `newapi` 分支的 `preferredImageResponseFormat()` 默认硬编码 `b64_json`；当前后台没有经证实的单模型URL开关。因此上面是**上游能力验证，不是平台已改成URL模式**。若实施：

1. 只针对ModelBay这个模型绑定选择URL模式，不影响兔子或其他渠道。
2. 平台解析URL后立即由服务器拉取、验证域名/重定向、MIME/图片魔数、字节数与超时，再持久化OSS；不能把短效上游URL作为最终交付地址。
3. 用同模型文本生图、参考图编辑、不同尺寸、并发和故障注入验证；URL模式不支持或上游URL不可访问时，必须区分安全回退与结果未知，不能在已可能计费的请求上静默再生成。
4. 做ModelBay已付费样本的端到端对账：平台任务终态、上游request ID、OSS对象、最终用户预览、扣费/退款。只有全部通过才可切换生产绑定。

本验证未保存API Key、完整图片URL或签名参数；只记录URL域名与尺寸耗时。未修改生产配置、未推送部署。
