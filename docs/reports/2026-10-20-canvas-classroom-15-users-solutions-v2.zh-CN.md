## 1. 目标与原则

目标不是把前端错误文案改成“成功”，而是让每条任务在“上游生成 → 结果可读取 → OSS/资产登记 → 节点回写 → 刷新可见 → 账务结算”全部成立后才算成功。任何中间阶段失败都必须进入失败态、退款一次、可追踪 request/task ID，并保留原始原因。

执行前保留回滚点：当前部署 SHA、路由/渠道配置 revision、数据库备份/迁移方案；先测试环境验证，再由用户批准生产发布。

## 2. 图一：EasyArt 图片结果媒体读取失败（P0）

### 证据

- 任务 `f60977d1-7df7-410d-8af9-396661db3746`。
- EasyArt `POST /v1/images/generations` HTTP 200，约 95.689 秒，request ID `cb4fd143`。
- 我方授权媒体读取阶段失败，错误“上游图片无法通过授权媒体路径读取”，没有资产，已退款。
- 当前日志缺最终图片 URL、HTTP status、Content-Type、字节数，因此不能判断是上游 URL 过期、CDN 拒绝、媒体代理鉴权还是回源失败。

### 建议方案 A（首选：完善结果收尾与日志）

1. 在上游响应解析阶段仅保存脱敏后的 URL host/path hash，不记录 query 中密钥；记录 `taskId/requestId/model/channelId`。
2. 媒体读取每次记录：DNS/连接/首字节/总耗时、HTTP status、Content-Type、Content-Length/实际字节数、重定向次数、最终 host、失败阶段。
3. 校验：HTTP 2xx + `image/*` + 实际可解码字节 + 尺寸合法，才进入 `result_ready/persisting/success`。
4. 任何 200 但不可读/非图片/解码失败：任务 `failed`，资产不登记，幂等退款，并显示“上游已响应但结果文件无法读取”。
5. 把上游结果 URL立即转存我方对象存储，避免依赖短时 CDN URL；转存成功后只向前端返回我方授权 URL。

### 方案 B（临时兼容，不作为最终修复）

对 EasyArt 只使用其明确支持的 `response_format=url`，并增加 URL 可读性探针与短重试；不能用 `b64_json` 冒充异步 URL模式。该方案不能解决所有 CDN/代理故障，需与 A 同时落地。

### 验收

- 单任务：上游 200、图片实际解码、OSS 对象存在、刷新可见、消费 1 且无退款。
- 故意模拟 URL 403/404/HTML：前端显示失败、资产不存在、只退款一次、无“成功”假象。
- 并发 15：结果读取失败率、媒体 p95、OSS 转存 p95均有监控。

## 3. 图二：兔子视频参考素材下载失败（P0）

### 证据

- 任务 `fba777ad-47e7-418e-90cc-049823a13424`，父任务 `69461447-4baf-4906-ab5b-4d06878592c1`。
- 兔子收到真实参考视频 URL，访问我方媒体端点得到 HTTP 307 → OSS；随后上游 HTTP 400“素材地址未返回可下载文件”，request ID `202610200349488872884368268d9d67ZbgdDp4`，平台转 502。
- 源 OSS 对象存在；签名 URL 跟随跳转时可返回 206 `video/mp4`，但无法从我方日志确定兔子是否跟随跳转/能否访问 OSS/是否拒绝 Range。

### 推荐方案（先兼容、后优化）

1. **上游兼容层**：视频参考提交前，将父视频解析为我方短时授权媒体 URL；为兔子渠道生成一个受限的一次性下载地址。
2. 该地址由同源媒体代理直接返回 `200 video/mp4`（必要时支持 `Range`，`Content-Length`、`Accept-Ranges`、正确 MIME），而不是第一跳 307；代理内部再从 OSS 读取。
3. 保留签名、过期时间、单任务绑定、下载次数/字节限额、来源 request ID，避免公开 OSS。
4. 记录上游下载探针：来源 IP 脱敏、URL hash、首个响应 status、最终 status、Content-Type、Range、字节数和耗时。
5. 与兔子用 request ID 联调，确认是否支持 307、OSS 域名、HTTPS、Range；若确认支持跳转，再逐步恢复直链以降低代理成本。

### 验收

- 兔子视频参考：上游能读取完整 MP4，创建接口不再返回400，任务有 upstreamTaskId，最终视频可刷新播放。
- 负向：过期/错误签名返回401/410，不能访问其他任务素材；失败退款一次。
- 图+视频、多视频参考、首尾帧分别验收，不能用纯文生视频替代。

## 4. 图片绑定、溢出路由和参数契约（P0/P1）

### 证据

- 多条图片任务出现内部 403“该上游模型未绑定可用逻辑模型”；部分任务先出现上游429/504后自动溢出到未绑定模型。
- ModelBay `gpt-image-2-5-flare` 不接受 `response_format`；EasyArt 异步接口只接受 `url`；多图文本 6.8MB 请求返回413。

### 方案

1. 发布前静态校验每个逻辑模型与渠道绑定：模型、能力、输入类型、参数 schema、计费模型必须一致；未通过绑定不允许启用。
2. 路由候选生成时排除未绑定/能力不匹配渠道；溢出仅从已验证候选中选择，内部403不能作为正常运行路径。
3. 为每个渠道维护参数适配器：`response_format`、图片 URL/base64、同步/异步模式、参考图字段分别配置；禁止全渠道共用默认字段。
4. 多图文本改为先上传参考图到受控资产，再传短 URL/asset ID；网关设置明确 body 上限和单图数量限制，413需提前校验并退款。
5. 计费以用户选中逻辑模型为准；路由溢出不能改变扣费模型；新增 billingReceipt 与 task 显式关联。
