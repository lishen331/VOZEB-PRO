### 2.1 A：结果读取、观测与交付闭环（主方案）

**改动边界**：仅图片结果读取/收尾与其日志，不变更用户模型选择、生成提示词、溢出候选、扣费模型或其他业务链路。

1. **建立一条可关联的结果媒体轨迹**：`taskId / attemptNo / clientRequestId / channelId / logicalModel / upstreamModel / upstreamRequestId / mediaReadId`。保留原始所选与实际执行字段，不能继续只存最后模型。
2. **补足读取阶段而非复制完整原始响应**：
   - 生成响应解析：HTTP status、业务码、结果类型（URL/base64/async task ID）、host、path hash；JSON与图片本体字节数分开。
   - 实际媒体 GET：阶段（授权/连接/响应头/响应体/解码/存储）、首跳及最终状态、MIME、声明长度/实际字节数、重定向及最终host、首字节/读取/总耗时、异常类别。
   - DNS/连接/TLS详细耗时仅在现有传输层能真实采集时记录；不可用填空，不用估计值冒充实测。
   - 存储与回写：OSS对象/资产登记结果、节点持久化结果、完成时间；保留失败阶段和原始安全错误码。
3. **让授权读取错误可诊断**：当前 `normalizeSafeImageResult` 最终只知道是否形成 `data:image/`。需让底层读取返回可判定的失败原因，授权范围按当前任务/渠道/媒体URL校验；不靠取消鉴权“修好”。
4. **成功标准是图片实际可用，而非HTTP200**：结果读取完整，真实图片解码/尺寸检查通过，按现有策略完成OSS/资产登记及节点结果持久化，才确认成功。200 HTML、空体、截断、假MIME均不能成功。
5. **避免重复付费**：下载失败仅处理已获得的同一结果URL或同一上游task ID；不得重发图片生成请求作为下载重试。重试与超时遵循现有受测契约/供应商约束/管理员配置，不新增拍脑袋次数或固定等待掩盖问题。
6. **资产与任务状态一致**：中途失败不登记假结果；服务重启/恢复用同task身份处理，最终失败退款幂等。对于尚无法确定是否可恢复的已付费上游结果，沿用项目已有待核查/恢复契约，不凭超时直接抹掉上游身份或强制批量失败。
7. **资源约束**：沿用项目图片尺寸/文件大小保护与OSS机制；避免在多并发时同时持有base64、解码后bytes和多个完整副本。URL转存可在现有安全媒体管道内优化，不能为追求流式而移除图片解码校验。
8. **安全约束**：媒体URL经SSRF防护，每一跳重定向重新校验；不得向第三方CDN转发平台Cookie或上游API Key。签名query、Authorization、原始base64、完整提示词与人像不得写常规日志。

### 3.1 C：针对provider-read的视频直出（推荐）

1. 沿用已有短时签名、资源登记/所有者校验和目的限制；只为经验证的 `purpose=provider-read` 视频读取走直出分支。普通浏览器媒体显示策略保持原状，不把整个媒体路由改成平台回源。
2. 视频请求第一跳：正常完整GET返回 **200 video/mp4**；合法单Range返回 **206**，保持 `Content-Range / Content-Length / Accept-Ranges` 等语义；无效范围按现有契约返回416。内部从OSS或受控本地文件流式读取，不向供应商回307。
3. **不使用“读一次即作废”的下载令牌**：供应商可能先HEAD、再GET、再Range或重试；应按现有签名有效期、所有者与媒体绑定、并发/字节配额保护，避免合法探测耗尽令牌。若增强任务绑定，需要兼容上游多次读取而非单次消费。
4. 采用流式背压、AbortSignal和并发许可；客户端中止、上游源失败或响应流关闭时释放许可。不能 `arrayBuffer()` 整个视频再返回，避免原来内存/堆问题重现。
5. HEAD真实反映已登记文件元数据并尽可能核对对象存在；HEAD200仍不是完整GET成功证据。过期/错误签名沿用统一鉴权语义，无跨账号泄露或降级公开访问。
6. 观测字段：关联task/mediaReadId、脱敏URL标识、签名用途、Range、首跳status、源状态、MIME、预期/实际字节、耗时、客户端取消/源读取失败阶段。IP若需关联只在受限运维记录保存，报告外发脱敏。
7. 保留既有素材大小、访问并发与速率保护，不自行设置新的固定小超时/随机重试。大视频或无效输入在提交前按现有能力契约校验并给明确错误，不让上游付费后才发现。

**验收**：

- 从供应商可访问公网位置对同一个签名URL验证：HEAD→完整GET200→Range206→再次Range；非跳转响应、字节数/文件头/内容长度正确。
- 过期/错误签名、不存在对象、非视频、空对象、被撤销资源、其他用户资源、416、中途断流、源403/5xx、客户端断连，均按安全及资源契约处理。
- 真实画布：成功视频作为后继视频参考，原生POST请求可看到视频URL及引用角色，供应商创建成功且有真实upstreamTaskId，最终完成、节点刷新可播放、扣费准确。
- 图片+视频、多视频、首尾帧只对明确支持的模型各自验收。纯文生视频通过不能代替上述验证；不支持的能力要明确标记，而不是误测。
- 回归普通用户看图/看视频/下载、Canvas图片像素读取、其他渠道图片参考不变；多个并发媒体读取时内存、网络、并发许可都不泄漏。
