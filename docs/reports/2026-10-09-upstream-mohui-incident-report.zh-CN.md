## 4. 平台侧责任与归因边界

1. **结果不确定的保守处理**：缺乏可查询任务 ID 时进入 needs_review、停止自动重提，目的是避免重复生成/扣费，不是证明供应商未执行。人工关闭不是供应商最终结论。课堂已经结束，本次不新建请求以替代追回。
2. **等待与响应体中止**：约 600 秒平台请求等待/信号中止和部分 HTTP 200 体中止属于平台链路/端到端契约问题，应由平台复核总等待、体读取和可恢复机制；不能向上游报成 HTTP 504。没有当前代码及配置独立验证，本报告不承诺“改长超时即修复”。
3. **身份留存缺口**：408 诊断含 requestId 而任务列为空，需要平台统一持久化与协查关联；但 requestId 不天然等于生成 taskId，不能猜测查询路径。监控也记录 updated_at 未同步反映异步诊断，事件增量应以诊断 at/事件游标而非旧 updated_at 为准。
4. **403 的确定性失败分类**：已知额度不足应单独展示为“渠道账户额度不足”，从暂时网络故障/审核拒绝中区分。及时阻断不可用绑定及恢复机制是平台配置/运维改进建议，不等于本报告已改库或证明所有入口 503 都由模汇造成。
5. **连接超时定位**：平台出站网络/解析/连接池与上游接入端共同核对；现有一条 UND_ERR_CONNECT_TIMEOUT 未提供 DNS、TCP、TLS 分段证据，不能单方定责。
6. **禁止跨供应商归因**：OSS、登录、其它供应商、平台内存等同期问题不放入本次模汇供应商故障集合；入口 503 未携带请求模型/响应体，不能按同期发生强行归于模汇。
