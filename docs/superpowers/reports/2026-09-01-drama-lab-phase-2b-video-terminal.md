# 短剧实验室 Phase 2B 视频任务终态阶段报告

日期：2026-09-01
范围：仅限短剧实验室（`/drama-lab` 与 `/api/drama-lab/*`）的视频任务终态、剧集级恢复和批量等待。普通 Canvas、教师/学生管理、学校/商单算力及平台通用生成链路不在本阶段变更范围。

## 已实现

- 为短剧视频任务建立明确的执行阶段映射：`created`、`submitting`、`submitted`、`polling`、`result_ready`、`persisting`、`needs_review` 和终态。`success` 只有在任务结果包含可播放媒体地址时才算成功；缺少地址会进入明确失败，未知提交结果保留原任务并进入待检查，不会自动创建第二个任务。
- `sync-generation` 返回短暂的 `generationExecutionPhase`，供工作台展示“提交中/处理中/结果待保存/保存中/待检查”等状态；该调度器内部字段不会写入项目 JSON，普通项目保存仍只保存业务字段。
- 新增剧集级 `recover-generation` 服务和 Route。恢复只读取当前用户、`surface=drama`、项目、剧集和镜头完整坐标一致的任务；优先使用镜头已持久化的任务 ID，再发现带完整上下文的任务。发现任务会先持久化绑定，再调用既有单镜同步；不会凭提示词、名称或 foreign task 猜测归属。
- 任务 Store 的 PostgreSQL 查询兼容持久化列、payload 顶层和 `payload.context` 的旧记录，统一清理空白值，并在 SQL `LIMIT` 前及 JavaScript 映射层拒绝来源冲突，避免跨项目或冲突任务占用恢复结果。
- 工作台打开剧集时自动执行一次受项目/剧集隔离的恢复；批量视频生成会等待恢复完成、复用已有任务 ID，并在所有子任务进入终态后才结束。快速重复点击由同步互斥锁阻止；切换剧集或卸载页面会中止批量、恢复、同步和镜头操作，旧请求不会回写新剧集。
- 新增批量视频状态汇总 helper，区分成功、失败、取消、待检查和仍在处理；轮询上限、提交失败、任务替换、Abort 均保留可操作的部分结果，不把 `result_ready` 或仅有上游地址的中间状态误报为完成。
