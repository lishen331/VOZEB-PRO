# 短剧实验室 Phase 2A 帧连续性阶段报告

日期：2026-09-01
范围：仅限短剧实验室（`/drama-lab` 与 `/api/drama-lab/*`）。普通 Canvas、教师/学生管理、学校/商单算力和平台通用生成链路不在本阶段变更范围。

## 已实现

- 扩展短剧帧契约，持久化 `source`、`storageKey`、源视频任务/镜头/历史 ID、锁定状态及下一镜 `firstFrameCandidate`。
- 从当前用户拥有且已成功的视频任务下载视频，使用 FFmpeg 提取真实末帧，经参考媒体登记后写回当前镜头；同一源任务重复请求复用已登记媒体并保持候选 ID 稳定。
- 增加末帧提取、下一镜首帧候选确认、首/关键/尾帧上传和逐帧锁定/解锁 API。候选 ID、媒体登记、项目/用户归属均由服务端校验；默认不覆盖已有首帧，显式替换会保留历史。
- 生成帧和上传帧均拒绝覆盖已锁定帧；用户显式上传、锁定和候选确认遇到项目版本冲突返回 `409`，不自动重放。
- 视频任务引用区分 `first_frame`、`last_frame` 和 `reference` 角色；模型不支持尾帧时返回明确降级信息。实际引用和参数通过 `videoFrameSnapshot` 写入现有 `generation_tasks` payload/context，无新增共享任务表。
- 同步接口保留帧来源、候选和历史，已锁定帧不被任务状态同步覆盖。
- 工作台已接入逐镜头动作回调和独立 busy key；最终按钮、候选预览和锁定/上传控件仍需浏览器人工确认其完整渲染。

- 真实图片/视频供应商是否按预期接收首帧、尾帧和普通参考图顺序，以及上游实际生成质量。
- 生产等价 PostgreSQL 下的并发版本冲突、刷新恢复、媒体登记和任务快照持久化。
- 工作台在桌面、390px/430px、浅色/深色主题下的候选预览、确认/保留、上传、锁定按钮和错误提示。

## 人工验收步骤

1. 在已安装 FFmpeg、启用真实视频渠道的登录态项目中完成一镜视频，刷新项目后确认任务仍为成功，再点击“提取末帧”。
2. 确认当前镜头尾帧图片可预览，下一镜出现候选及来源标签；分别测试“应用候选”“保留现有首帧”和已有首帧的显式替换，确认历史记录不丢失。
3. 分别上传 PNG/JPEG/WEBP、非法 MIME、空文件和超过 20MB 文件，确认错误可读；锁定每种帧后尝试生成、上传和同步，确认服务端拒绝覆盖，解锁后才可修改。
4. 用真实图片/视频供应商提交视频任务，在上游日志核对首帧、尾帧、普通参考图及 `videoFrameSnapshot` 的顺序和参数；中途刷新并重复点击，确认不重复创建任务或扣费。
5. 在生产等价 PostgreSQL 中制造并发版本冲突，确认显式用户操作返回 `409`，而后台同步只保护锁定帧并保留来源字段。
