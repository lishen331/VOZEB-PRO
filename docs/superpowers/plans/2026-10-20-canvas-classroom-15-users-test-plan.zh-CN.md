# 15人真实课堂画布测试实施方案（2026-10-20，修订版v2：能力矩阵与准备核查）

**目标：**15个独立普通学员账号从真实登录开始，在真实画布完成文本、图片、视频生成；覆盖执行时已开放的全部相关模型，并监控平台、Worker、数据库、存储及上游链路。

**执行方式：**先审核方案，再准备账号并启动真实付费测试。浏览器驱动业务操作，接口与服务器只读诊断辅助取证；不使用模拟视频代替本轮真实视频，不直接调上游绕过平台。

**工具：**Playwright浏览器隔离上下文、平台正常管理/用户接口、SSH只读采样、脱敏JSONL和Markdown。执行时遵循浏览器技能及项目AGENTS；本方案不要求新增业务代码。

## 1. 当前确认与边界

- **目标环境暂按生产** https://gammatv.gammablue-x.com/；用户若指定测试站则整体切换，不能在两个环境混跑。实际提交前核对域名、服务器、App/Worker镜像和账号所属环境。
- 用户数为15，不是15个共享同一登录态的标签页。至少15个独立账号、15个隔离会话、15个独立测试画布。
- 本轮是15人课堂演练与模型覆盖，**不能以此宣布80人或120并发容量通过**。
- 文本、图片、视频都走真实上游。所有“当前开放模型”必须列入覆盖矩阵，不再只测默认模型；失败也如实占一条测试结果，不能跳过后声称全覆盖。
- 原v1只生成计划；v2已获账号等准备工作授权。当前已核实SSH、部署/配置和管理员认证结果，未创建服务器账号、未充值、未付费生成；详见第15节。10月10日的IP、凭据、镜像、额度、默认模型、限流和启用绑定都不是今日已核实事实。
- 不修改现有学生项目、默认模型、限流、渠道、模型绑定、生产数据库；不重启、不部署、不推GitHub。账号通过正常管理流程准备，不伪造会话或绕过登录。需增配积分/学校算力时列明数量和额度，按本次批准范围操作，不能沿用旧任务的改库授权。
- 仅允许明确命名的新测试画布及测试素材；不触发对外发布或视频合成；不删除历史成果。

## 2. 账号准备与登录测试

### 2.1 准备15个账号

- [ ] 优先使用负责人批准的闲置培训测试账号；先核查归属/用途，不能直接占用正在上课的真实学生会话。
- [ ] 不足15个时，正常管理员新建/导入15人计划中的缺额。使用独立账号名、随机不同密码，报告仅显示U01—U15。
- [ ] 15人权限、套餐/学校角色及扣费主体按正式培训设置；管理员仅负责准备，不能用管理员无限额度替代15个学员。
- [ ] 核对每人的文本/图片/视频额度、学校算力池、并发限制和模型权限；余额不足记为前置条件不满足，不记作上游故障。
- [ ] 账号密码和会话只放本机私密运行目录，控制访问；仓库/截图/报告不含密码、Cookie、API Key或签名URL。
- [ ] 输出脱敏账号清单：别名、班级/权限、是否可登录、可见模型数、测试前余额、画布ID。15个都准备好才宣布“账号就绪”。

### 2.2 从真实登录开始

15个隔离上下文共用真实测试出口，不伪造X-Forwarded-For、不更换IP躲限流；保留相同浏览器特征，贴近机房场景。

- 第一轮：15人通过登录页在约10秒窗口完成一次登录，记录服务端实际登录到达跨度和结果。
- 正常成功后复用各自会话，不在每个请求前重新登录；检验刷新/会话恢复/退出后重新登录。
- 另用1个指定测试账号测一次错误密码→正确密码，记录为负向测试；不密集重复失败触发锁定。
- 记录登录耗时、HTTP状态、响应原因、Retry-After、账户/设备/IP维度（以实际证据为准），区别错误密码、权限不足与错误共享IP限流。
- 账号已登录但目录401、跳回登录或刷新丢会话，都单列缺陷。

## 3. “所有开放模型”的覆盖定义

执行前抓取普通学员模型目录与脱敏管理配置，形成不可变基线 `model-manifest.json`，记录时间、配置revision与部署SHA。

| 覆盖层级 | 实施规则 |
|---|---|
| 学员可选择逻辑模型 | 文本、图片、视频各模型至少一次**真实画布发起+终态+结果验收**。不得用历史成功代替本轮 |
| 后台启用但学员不可见 | 按角色、能力、渠道状态、页面过滤逐项解释。原本应开放却不可见算问题，不能静默剔除 |
| 启用模型的多个渠道绑定 | 尽量覆盖正常路由实际可选的每个启用绑定，保留实际channel/upstream ID；仅选逻辑模型不等于全部绑定测到 |
| 无法通过正常UI/路由选中的绑定 | 标记“未触达/待验证”，说明缺少什么条件；不擅自关主渠道、改权重或制造故障强迫切换 |
| 能力限制 | 支持多图、图生视频、参考视频、音频等的模型按声明能力分配；不支持多模态的文本模型不能强塞图片制造假失败 |
| 自动溢出 | 核对用户所选模型与实际执行模型是否变化、代理是否认可、计费身份是否正确；没有触发则标未覆盖 |

模型清单必须包含：逻辑ID、学员可见性、渠道/上游ID、协议、已配置能力、分辨率/时长、价格单位、并发/速率/突发配置与默认值来源、query/cancel能力、可查询身份与供应商时限。

**覆盖计数原则：**用户选择A实际溢出到B，不算A的上游执行已经成功。矩阵分别记录“选中、被接受、外部执行、终态、用户可见”，并补测未执行的A或标记阻断。未知/未测不得写通过。

如果可见模型因15人权限不同而有差异，按权限组的并集列矩阵；某模型必须由有权的普通账号验证，不能管理员强行测试后代表学员可用。

## 4. 负载、真实任务量及预计耗时

### 4.1 15人基础课：90项基线任务，不是最终覆盖上限

每人一个真实画布，依次创建和连线：

1. 文本T1：生成原创产品/场景创意、短提示词（1次文本）。
2. T1→图片I1：文生图（1次图片）。
3. I1+一张预置授权参考图→文本T2：多图分析（1次文本，分配有视觉能力模型）。
4. I1+预置参考图+T2→图片I2：多图参考编辑（1次图片；若模型不支持则该步骤选支持的模型）。
5. I2→视频V1：生成5秒或该模型**最短合法时长**视频（1次真实视频），使用各模型允许的画幅、质量与素材输入。
6. 文本T3：修改原文本要求后再生成/润色（1次文本，保留旧结果及关联）。

合计 **45次文本、30张图片、15条视频**，每次只请求1个结果。素材用原创、无真人隐私、无商标/版权角色的风景、几何小物/原创玩具，降低内容拒绝对容量判断的干扰；仍然记录真实内容拒绝，不靠换词绕过政策。

正常课堂节奏有编辑、观看、拖动、保存的间隔；思考时间用于模拟用户操作，不写入业务代码，不以脚本限速掩盖平台吞吐问题。

### 4.2 两个互补负载窗口

- **齐步窗口：**同一种能力下15人各点击1次；分别覆盖15人文本、图片、视频近同时提交。只在合法单用户额度内发，不人为把15视频串行成单人演示。视频等前一个任务结束才安排该用户第二条，除非专项验证限额。
- **混合窗口：**其余步骤错峰穿插，维持15个会话，约5人编辑/生文、5人生图、5人生视频或预览，轮换，持续20—30分钟。用请求时间线证明真实重叠，不能仅以15个浏览器已打开称为15并发任务。
- 记录计划点击跨度、浏览器实际点击跨度、服务端接受跨度、外部POST跨度、在途峰值。浏览器资源不足导致提交变慢应标为**客户端瓶颈**，不能据此宣称服务器削峰生效。
- 若当前突发上限为10，15个集中请求可验证是否出现超额度后的实际路由行为，但令牌补充/已有占用会改变实际放行数，不能死认第11个必切换；不自动扩大为30/90/120人。

### 4.3 补齐模型与复杂素材

90项按模型清单轮转、尽量均匀分配。在基础任务之外补覆盖：

- 文本模型数为M_t、图片为M_i、视频为M_v；基础名额45/30/15不是模型覆盖上限。
- 缺哪个模型/绑定/支持的输入路径就安排指定用例，不随机碰运气。基础数量至少分别为 `max(45,M_t)`、`max(30,M_i)`、`max(15,M_v)`，复杂素材用例可能额外增加，不将公式误当全部最终费用。
- 对实际声明支持参考视频的各视频模型，用短原创已有视频+图片+提示词各测1次；支持首尾帧的路径单独测；需要asset://入库的渠道跟踪入库/审核/转换/提交。无能力声明的不强制。
- 同一逻辑模型多绑定、取消、少量错误输入/恢复用例纳入追加清单。不会为重复验证已终态的任务无上限生成。
- 执行前交付**精确任务清单和按当前模型价格估算的总费用**：T/I/V任务数、分辨率/时长、各模型价格、可能的系统自动重试成本。旧图文预算授权不自动扩展到本轮视频；批准开跑时确认具体执行清单，超出清单再确认。

预计准备20—30分钟；登录和基础画布10分钟；生成/混合及覆盖约40—90分钟；收尾对账15—30分钟。模型较多或上游队列很慢会延长，不能为赶时间把未终态记成功。

## 5. 画布功能与结果验收

- [ ] 每个用户真实创建画布与文本/图片/视频节点，提示词、模型、参数、连线均由页面保存；生成入口使用页面按钮/正常前端处理链路。
- [ ] 拖动、缩放、切换节点、修改标题/提示词、连续保存与刷新；旧成功图/视频不应被新请求空状态覆盖。
- [ ] 文本流式首字、后续增量、完成正文、中文不乱码；历史保留，刷新仍有结果。
- [ ] 图片：1图与2—3图参考至少覆盖，检查最终请求的引用数量、顺序、类型和可读取性。要求白底/透明背景时按能力区分，PNG不等于透明。
- [ ] 视频：播放加载metadata、时长>0、跳播、加载结束状态；真实画幅/时长符合选择。参考视频必须真传入，不只显示附件标识。
- [ ] 15人所有成功节点均刷新检查；图片实际解码、视频metadata/播放抽样+每条资源状态检查，文本内容一致。若其中任何项未核实，分别报“后台成功/前端未验”。
- [ ] 3个测试账号在任务进行中刷新、1个关闭页面后重新打开，验证**只恢复原task**而非再次POST付费生成。
- [ ] 一个账号在两个独立会话打开同一测试画布，验证不同节点保存及同节点冲突：允许明确409/合并流程，不能静默覆盖；正常单会话连续保存不应要求每次刷新。
- [ ] 双击生成/网络请求提交后断开只在指定测试用例做，检查clientRequestId去重，未知结果先查询不自动新建任务。
- [ ] 有取消能力的模型选1个取消案例，验证后台终态、上游是否取消与积分；不能将“不再显示”当真正取消。
- [ ] 跨账号访问只针对这15人新建的私有测试项目/任务/媒体，按实际权限契约应拒绝；不访问其他学生对象。

**禁止重复上一轮缺口：**不能只建空画布+后台task；不能脚本把结果手写进节点后宣称“原生自动回写通过”。若某部分只能API合同驱动，应另立标签，不替代本次15人完整浏览器课堂链路的验收。

## 6. 明确测试接口及方式

下列路径来自当前本地源码；正式执行先与实际部署版本和浏览器Network核对。未知路由不猜测、不批量发送。

| 能力 | 已知接口/入口 | 检查内容 |
|---|---|---|
| 登录/会话 | `POST /api/auth/login`、`GET /api/auth/session`、`POST /api/auth/logout` | 正确登录、一次负向、刷新、隔离、退出 |
| 模型目录 | `GET /api/model-catalog` | 普通用户可见性、默认/手选、能力、权限 |
| 画布 | `GET/POST /api/canvas/projects`、`GET/PATCH /api/canvas/projects/{id}` | 创建/读取/版本保存、连线、刷新、并发保存 |
| 素材上传/读取 | `POST /api/reference-assets`、`GET/HEAD /api/reference-assets/...` | MIME/大小、OSS地址、权限、签名过期、重复上传 |
| 生文 | `POST /api/text-tasks`、`GET /api/text-tasks/{id}`及页面实际使用的流式入口 | 原生入口若不是text-tasks按抓包登记；TTFT、正文、错误、保存 |
| 生图 | `POST /api/image-tasks`、`GET /api/image-tasks/{id}` | 接受/实际路由/全体读取/持久化/退款 |
| 生视频 | `POST /api/video-generation-tasks`、`GET /api/video-generation-tasks/{id}` | 素材入库、任务ID、轮询、终态、时长 |
| 图片/视频交付 | `GET/HEAD /api/generation-log-assets/...`、实际`/api/media-proxy`/系统媒体代理、OSS/CDN | Range、有效文件、解码、403/429、跨域、回源/下载 |
| 运维/扣费 | 实际后台任务/日志/账务只读入口及定向DB查询 | 同task的消费/退款、历史一致、成功未回写 |
| Worker/健康 | 已部署health/maintenance路径及现有Worker | 只监控，不手动POST维护接口驱动状态改变 |

只读API容量从15真实会话产生的画布加载/保存/轮询测量；额外API探针限制为1个/用户/秒、5分钟，单独计数，不与业务任务数量混淆。生成绝不按探针频率循环调用。轮询遵守前端策略/Retry-After，不高频空转制造错误。

## 7. 全链路监控和证据

### 7.1 关联ID与成功层次

每项任务保留：`runId/userAlias/caseId/projectId/nodeId/clientRequestId/taskId/attemptNo/selectedLogicalModel/actualChannelId/actualUpstreamModel/upstreamRequestId/upstreamTaskId`。

分开记录：用户点击→请求到平台→内部鉴权/准入→外部POST→响应头→响应体完整→结果地址→OSS/资产注册→生成历史→节点保存→浏览器刷新。查询GET不算新增生成；系统自动重试也要计外部POST次数。

- HTTP200内`status=failed`、HTTP5xx、400业务拒绝、平台429、内部403分开归因。
- header request ID不是异步task ID，只有明确查询契约才追回。
- 每条失败保存原始错误的脱敏文本和必要请求参数摘要，不输出提示词中的个人信息/密钥/大块base64。
- 失败后不默认点击重试；先关联任务及账务，防止上游成功却重复付费。

### 7.2 监控维度

| 层 | 频率/来源 | 指标 |
|---|---|---|
| 浏览器 | 连续网络/console/error记录 | 登录、流式断开、CORS、UI状态、资源加载、页面性能 |
| 平台/Worker | 日志增量实时读取，任务状态约15秒 | 心跳、lease、阶段耗时、result_ready/persisting积压、worker重试 |
| CPU/内存/磁盘/网络 | 约5秒采样（现有工具可用时） | CPU、RSS、已暴露heap/GC、MemAvailable、磁盘/容量/inode、I/O吞吐与等待、网络吞吐/错误/TCP重传 |
| 数据库 | 约15秒定向聚合 | 连接、活跃查询、锁等待、长事务、任务队列；不全表dump |
| Nginx/健康 | 增量日志；health约15秒 | 4xx/5xx、长连接中断、请求耗时、来源维度脱敏 |
| 上游/OSS | 每任务阶段日志 | 创建/查询、429/限额、TTFB/体下载/上传耗时、字节数、重试和存储request ID |
| 测试机自身 | 约5秒 | CPU/RAM、浏览器崩溃、自动化积压、出口/网络时延，防止把客户端不足误判服务端 |

没开放的V8 heap、供应商内部CPU/队列/错误栈标为无法直接观测，不拿RSS代替heap、不把供应商错误正文当我方采样值。无iostat等工具不擅自安装或重启，列出缺失指标并选择已有/proc统计。

监控先于任何生成启动，完成全部收尾后再停；采样更新时间和进程心跳单独校验，超过2个计划间隔未更新标为采样缺口。先记录空档，再恢复，禁止重复上一轮“后台进程死了还声称一直监控”。

## 8. 通过标准、分母和异常决策

以下是本轮预先约定的验收目标，不是当前系统已达到的承诺，也不拿它们改变生产限额。

- 登录：15/15正确凭据通过正常页面登录；无错误共享IP/设备限流；账号角色和会话隔离正确。
- 覆盖：冻结清单中所有可选文本/图片/视频模型至少1条完整链路案例；失败明确标红；尚未触达的模型/绑定不得标“全模型通过”。
- 功能：基础课所有节点和连线保存正确；全部成功结果刷新可见；无跨用户泄露、无丢结果、无重复任务/重复净扣费、无错误显示成功。
- 请求：非刻意负向用例不应出现平台5xx、意外429或内部代理403。出现受配置限制的429可说明保护正确，但若妨碍正常15人课程，则课堂可用性仍不通过。

### 14.1 真实原因分层

- E0前端表现：错误文案、红色节点、浏览器异常。仅是症状，不是根因。
- E1平台接入：HTTP状态/结构化body、鉴权/权限/校验/用户限流/幂等键；拒绝未建task也纳入分母，留下requestId，不能因“没有任务”忽略。

- E3供应商：真实发出参数摘要、实际模型/端点、请求/任务ID、创建/轮询HTTP状态及body.error、原始内容拒绝/额度/限流/素材报错。

### 14.2 自我对抗审查：发现并修正的12个漏洞

1. 原来“每模型一次”无法覆盖多输入模式：改为全部可见模型×适用能力×实际绑定矩阵。

4. 文生图成功不能推断图生图/真人成功：拆分I1—I5、V1—V10。

7. 无task的400/403/429漏分母：客户端requestId与接入日志记录所有提交意图和平台受理数。
8. 路由切到B但给A计成功：按选中/执行/计费身份三列，原渠道未触达不能通过。

10. 历史待确认污染本轮失败率：使用runId+账号别名+caseId过滤；旧积压单列前置风险，不改状态清空。
