# 短剧实验室 Phase 2C：音频与 TTS 闭环计划

> 建立日期：2026-09-01
> 范围：仅短剧实验室（`/drama-lab`、`/api/drama-lab/*` 及短剧专属服务）。
> 目标：把对白、旁白、角色声线、音频任务和按节奏拆镜接入 VOZEB PRO 的真实任务链路。

## 1. 目标与边界

短剧镜头的音频必须成为可恢复的业务数据，而不是工作台本地状态：

```text
镜头对白/旁白 + 角色声线
  -> 服务端创建 audio generation task
  -> generation_tasks / Worker / 上游音频渠道
  -> 媒体登记与结果回写
  -> 页面刷新或进程中断后恢复
  -> 按音频时长/节奏生成候选镜头
```

本阶段不修改普通 Canvas、教师/学生管理、学校/商单算力或平台通用音频接口的业务语义。平台通用 `/api/audio-tasks`、计费、退款、媒体存储和恢复服务只复用，不复制一套短剧任务基础设施。

## 2. 并行工作包

### A. 短剧音频任务服务

- 新增短剧专属创建/同步/恢复入口，或为现有音频入口增加明确的 `surface=drama` 业务适配层。
- 请求上下文必须包含 `projectId`、`episodeId`、`shotId`、用户和幂等 `clientRequestId`。
- 从镜头 `utterances` 生成对白/旁白输入；角色存在 `voiceProfile` 时使用其声线、速度和指令。
- 仅接受当前项目内镜头，成功后原子写入 `audioStatus/audioTaskId/audioUrl/audioError`。
- 重复点击不重复提交或扣费；任务状态和媒体结果可通过服务端恢复。
- 添加服务、Route 和任务状态回归测试。

### B. 按音频节奏拆镜

- 先复用现有 `drama-analysis` 的时长估算与拆分原则，补充音频时长/节奏输入的纯函数契约。
- 保留对白/旁白顺序、说话人和完整文本，不截断句子或删除台词。
- 只对 AI 生成的候选镜头拆分；已有用户手工创建/编辑的镜头必须保持不变。
- 输出候选结果和来源范围，服务端校验后才写入剧集版本。
- 添加边界、连续对白、无音频和人工镜头保护测试。

### C. 短剧工作台音频 UI

- 在分镜工作台独立封装音频控制，展示对白/旁白、角色声线、任务状态、错误和恢复入口。
- 调用短剧 API，不在前端用 `setTimeout` 模拟完成；轮询可取消且切集/卸载不回写旧镜头。
- 结果成功后显示可播放媒体，失败显示服务端原因；`needs_review` 不自动重建任务。
- 尽量不大范围修改主工作台；若必须接入，保持变更集中在音频区域和已有项目更新回调。

## 3. 主线集成工作

- 统一音频字段和 API 响应契约，兼容既有 `DramaShot` 数据。
- 校验项目/剧集/镜头归属、版本号和幂等键，拒绝跨项目任务回写。
- 将音频结果纳入渲染输入和导出已有链路，但不提前实现完整批量编排。
- 统一文件 Provider 与 PostgreSQL 的任务上下文读取，确保刷新/重启后仍能恢复。
- 编写跨服务集成测试，运行 typecheck、lint、diff 检查和本阶段定向测试。
- 输出 `docs/superpowers/reports/2026-09-01-drama-lab-phase-2c-audio-tts.md`，并更新 `pending-test.mdx` 的待人工验收项。

## 4. 阶段完成定义

1. 一条镜头对白/旁白可以创建真实音频任务，平台任务记录、计费和媒体登记可查。
2. 刷新页面、切换剧集或服务进程中断后，原任务可继续查询，不创建重复上游任务。
3. 成功、失败、取消和 `needs_review` 均能持久化并在工作台正确显示。
4. 角色声线配置只影响其对应镜头；无角色匹配时使用短剧默认配置并保留可追溯快照。
5. 按音频时长拆镜不覆盖手工镜头，台词顺序和文本完整性通过自动化测试。
6. 真实供应商、生产等价 PostgreSQL、FFmpeg 和浏览器人工回归按总计划延后统一验收；本阶段不得把未做人工验证标记为完全交付。
