# 工作流项目归档范围修复

本次只修复工作流选择当前/部分剧集却归档全部剧集的缺陷，不代表成片模块完成，也不新增视频渲染服务。

- 归档服务增加可选 episodeIds；省略时保持全项目归档（包括空项目）原行为。
- 显式指定空列表或不存在的剧集时拒绝，避免静默导出错误范围。
- 只导出选中的剧集、镜头、镜头媒体与任务引用；保持项目原剧集顺序。
- 项目级角色、场景、道具、线索、来源素材保持完整：它们不属于单集，不能根据当前镜头白名单删除尚未绑定但剧本仍需要的素材。
- 活动剧集必须在选中范围；否则回退第一选中集。归档版本和导入契约不变。
- 工作流明确传入持久化的 episodeIds。

验证：先建立失败测试，覆盖范围、输入拒绝、全项目兼容、归档往返及工作流透传，再修改实现并运行专项回归和类型检查。线上部署和真实下载验收由总架构师统一执行。

范围语义是选中剧集镜头归档 + 项目公共资产，不是对所有原始剧本作信息隔离：sourceAssets 中项目级原始全文仍保留。未选中集的镜头视频、尾帧和音轨不进入媒体读取、清单或归档；已用注册表调用断言覆盖。

## 本轮验证结果

- RED：首次专项回归 6 failed / 32 passed；错误分别为选集仍全量、非法选集未拒绝、工作流未透传。
- GREEN：归档/工作流服务及导出、导入、工作流、产物下载路由共 6 files / 57 tests passed。
- `pnpm run typecheck` 通过；四个修改源码/测试的 ESLint 通过。
- 生产构建、全量回归、部署和浏览器下载验收尚未执行，由总架构师在集成版本统一验收。
- 已有 includeMedia=false 且项目含引用媒体的归档不能往返导入，测试中发现该独立历史缺陷；本修复工作流始终 includeMedia=true，不在本轮扩大修改。
