# 单项练习「表情参考」修复开发文档

## 目标与证据

用户在表情参考里完成「选图 → 自动识别或手动框选 → 选表情 → 生成」。以生产 `v0.8.46` 为复现基线：Edge 下 `fetch(data:)` 被 `connect-src` 拦截；用浏览器图片解码代替后，原 Worker 在原安全策略下对猫图正常返回零候选。已框选时弹窗能产生有效指令，但工作台在请求之前误校验空白的局部编辑说明。

## 实现范围

1. `web/src/app/(user)/canvas/utils/canvas-face-detection.ts`：复用浏览器图片加载，交给 `createImageBitmap`，继续使用现有 Worker 与取消机制；同步短剧画布镜像。CSP、模型文件和原生检测优先级不变。
2. `web/src/app/(user)/practice/components/practice-image-tool-workbench.tsx`：表情参考只接收弹窗确认产生的指令；没有指令不发请求，局部编辑仍要求说明。沿用 `/api/practice/image-tools`、练习模型池和计费契约。提交后仍在右侧查看进度和结果，失败可重用原图上的表情指令。
3. 共用表情弹窗：明确没有目标时按钮为何不可用；单项练习对同源已确认的表情草稿保留框选、表情、强度及情绪，换图丢弃草稿与重试指令、清理该图的结果和请求诊断。其他画布调用保留原先重开即重置的行为。

## 验收条件

- 猫图检测成功为零：显示「未自动识别到人脸，请手动框选」。真实检测异常仍显示「自动识别不可用，请手动框选」，能手动操作。未选脸时提示原因且不提交。清晰人像仍可自动选框。
- 框左侧正脸并选微笑：不要求说明，单次提交携带目标与表情指令，结果回到当前页。生成错误后，同源重试复用这条指令；重新打开能看到上次的已确认设置。换图后不得沿用上一张图的框和指令。
- 先跑失败回归，再修复；覆盖真实 CSP 下图片解码与 Worker，提交及换图/重试用本地模拟检查。不向生产模型提交，不改定价、数据库或安全配置，不推送、不部署。

## 本地验证记录

- 两个专项用例先在旧行为下失败，改动后专项分组 8 个测试文件、42 项通过；全项目 TypeScript 检查通过，改动文件 ESLint 无错误（既有 `<img>` 性能警告），Prettier 通过。
- 生产同款 CSP 下用 Edge（1440 px）和 Chrome（390 px）运行实际工作台组件和识别 Worker；使用本地模拟上传与生成 API。两端均验证：猫图返回零候选并提示，未框选不提交，选择左侧脸部和微笑后仅一次提交，失败后重开保留框选与表情，重试复用指令并展示模拟结果，换图后清空。
- 未测试真实练习模型生成质量、线上积分或部署环境。没有推送、合并或部署。
