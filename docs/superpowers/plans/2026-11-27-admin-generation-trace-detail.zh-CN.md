# 管理后台生成日志：调用链路详情

## 范围

在现有「生成日志详情 → 调用链路 → 查看原始事件」内增加可展开、可复制的上游请求与响应。沿用已有画布图片/视频任务诊断采集、管理员鉴权、七天留存及每任务 20 KiB 事件预算，不扩展到原本未采集诊断的入口，不修改生成、重试、计费和节点 JSON。

## 实现顺序

1. 用 Vitest 固化脱敏快照契约：真实上游最终参数、引用数组顺序、响应任务 ID、状态、结果地址及错误保留；密钥、签名、媒体二进制不进入快照。旧日志缺字段显示未记录。
2. 在系统渠道代理最终发送的请求处采集，在既有响应读取完成时采集 JSON 数据；沿用真实任务关联，不用前端提示词代替。按渠道操作分别标识提交和查询；HTTP 状态与业务结果分开。
3. 复用管理员 trace API 和原有事件面板。显示可复制的上游任务 ID、脱敏 JSON 和业务错误；把已有保存结果链接放在调用链路里，区分上游地址与平台结果。轮询细节默认折叠，不用重复轮询挤掉首次提交的关键证据。
4. 验收：提交获得任务 ID、查询处理中的 HTTP 200、查询成功/失败、平台保存失败、历史记录缺失、脱敏及预算回归；运行专项 Vitest、TS、ESLint 和 Prettier；能启动本地夹具时走浏览器。

## 验证记录

- 7 个专项测试文件、86 项通过。系统代理覆盖提交与查询的独立关联、请求采集和上游响应原样交付；Blue Cloud 用例覆盖外层 HTTP 200 / `msg: ok`、内层失败、等待与成功结果。
- Chromium 本地组件夹具覆盖 1280px 和 390px 下的展开、剪贴板、两类结果链接和失败信息。未连接真实渠道或测试环境，未做完整应用端到端验收。
- TypeScript、ESLint、Prettier 通过。首次全量 Vitest 捕获了新增的 Blue Cloud 失败用例（其余 6583 项通过，42 项跳过）；修复后已重跑并通过专项套件，尚未重跑全量。
- 非 JSON 或超过采集预算的正文不持久化为原文；仍显示可用的状态、任务身份等证据。上游地址去掉签名参数，不保证可直接打开；平台保存后使用站内资源地址。
