# 无限练习查询与历史恢复修复

## 已确认根因
- 用户运行时将 RunningHub 查询拼为 GET /openapi/v2/query/{id}，与后台测试专用 POST 查询契约不一致。
- 系统代理只在创建请求中注入渠道 apiKey，查询未注入。
- 模块入口不带 sessionId 时不恢复最近记录；query-string 切换重载表单，导致提示词与素材状态丢失。
- 轮询 effect 依赖整个 current 对象，重设定时器且错误重试没有明确停止状态。
- 角色/场景/道具丢失任务关联后的恢复查询误归为 audio。
- 只填写主配音文本时，空台词行被过滤，其音色和情绪未提交。

## 本轮修改
- [x] 图片/视频/音频统一 RunningHub 查询解析，保留同一 taskId、输出节点匹配与站内鉴权代理。
- [x] 查询体注入服务端 Key，验证 POST 查询不扣生成费用。
- [x] 页面恢复最近运行/最新记录；历史加载与表单解耦；旧响应不能覆盖新的选中结果。
- [x] 轮询按稳定 taskId 串行执行；网络错误停止自动查询并提示手动刷新。
- [x] 历史时间、加载更多、删除确认、新建练习。
- [x] 视频增加配音来源（上传/历史）、去配音和刷新配音记录。
- [x] 六维情绪滑杆 0–1.4、步长0.01、实时值；主文本作为空首行台词使用，保留情绪和音色。
- [x] 提示词请求携带模块和当前用户编辑内容，不再始终使用旧设定；浏览器逐模块回填验证。
