# AI 扩图练习 · 开发与验收

仅替换 `/practice` 最后一张「超分放大」卡片为「AI 扩图」；新增 `/practice/ai-outpainting`，保留原超分路径、其他卡片、练习和无限画布。

- 左栏上传/选素材、四边四角扩展、比例、1K/2K、重置与生成；中栏对比、下载、保存和扩图诊断，**诊断下面**展示结构化提示词（扩图目标、补全区域、画面延续、禁止事项）和复制完整版本；右栏最近 20 次成功生成的历史。点击历史恢复原图、四边、比例、分辨率、提示词和结果，不提交任务。
- `POST /api/practice/image-tools` 接受 `toolId: ai-outpainting`、源图、像素边距、比例、输出档位、请求 ID。服务端核对图片归属与真实尺寸，按扩图框等比确定输出长边，制备带源图的画布和外围透明、中心不透明的 PNG 蒙版；业务提示词与学习卡共用同一构造函数。1K/2K 指最终长边，必要时等比缩放整幅画，原图不被二次生成或拉伸；结果落盘前按确定像素坐标把原图区域覆盖回去。比例不匹配的上游结果判失败，不用普通图生图、超分或镜像伪造结果。
- 只使用练习池中支持 OpenAI 文件蒙版编辑的默认渠道，不回退生产渠道。队列、归属校验、重复请求处理、计费及媒体存储沿用已有基础设施。没有兼容渠道时明确提示。一次提交冻结配置，教学提示词来自同次提交；历史复用任务 JSON 和保留期，按账号与学校隔离，不新增数据库表。

## 实现顺序

- [x] 几何与提示词 Vitest：比例、非对称边距、无有效扩展、字段顺序及教学/提交文本一致；实现 `web/src/lib/practice-outpainting.ts`。
- [x] 服务端 Vitest：PNG 蒙版像素、合成后中心保护、错误比例拒绝；利用 `practice/image-tools`、图片任务存储与结果服务，仅在 `practiceOutpainting` 标记下进入扩图逻辑。
- [x] 新增独立工作台及入口，以 DOM 交互核对桌面三栏、窄屏、历史恢复和结构化提示词；不调用真实渠道。
- [x] 专项测试、TypeScript、格式、接口索引和开发地图验证；不推送、不部署。

## 本地验收与上线前条件

- 通过结构化提示词、蒙版与 RGBA 合成、历史归属、重复提交和本地 TCP multipart 契约测试；浏览器使用本地固定夹具验证桌面及两个手机宽度，点击历史不触发重新生成。
- 本机没有 Docker。Webpack 生产构建通过，浏览器回归使用该构建与隔离的文件数据库；未验证 Docker、真实模型出图、实际扣费或全站浏览器矩阵。源码及本次 E2E 的 TypeScript 检查通过；构建后包含 Next 生成声明的全量检查仍有三个未修改的后台页面/接口导出错误，本次未改它们。
- 优先使用练习默认模型中明确支持 `/images/edits` 文件蒙版和目标尺寸的渠道。上线前以实际渠道验证 1K、2K、横屏和自由比例；不接受悄悄忽略蒙版或改动尺寸的渠道。没有可用渠道时页面会提示，提示词仍可用于学习。
