# 短剧实验室 Phase 2B 视频任务终态实施计划

> 日期：2026-09-01
> 范围：仅限 `/drama-lab` 与 `/api/drama-lab/*` 的视频任务状态、恢复和批量语义。普通 Canvas、教师/学生管理、学校/商单算力及平台通用生成链路不在本阶段修改范围。

## 目标

让分镜视频从“请求已发出”到“结果已落库/明确待检查/明确失败”形成可恢复闭环：

1. 服务端保留并校验原任务 ID，能够在刷新、离开页面或旧状态缺失时重新发现并同步任务。
2. `submitted`、`polling`、`result_ready`、`needs_review`、`success`、`error`、`cancelled` 的语义不混淆；待检查任务不重复提交、不重复扣费。
3. 批量生成只有在全部子任务进入终态后才结束，并返回成功、失败、待检查和取消的汇总。
4. 所有恢复和汇总按 `userId + surface=drama + projectId + episodeId + shotId` 隔离，跨项目任务不能被读取或写回。

## 分阶段实现

### 2B-1 终态映射与恢复

- 复用 `generation_tasks`、视频任务 Store、Worker recovery 和单镜 `sync-generation` 路由。
- 为只有任务 ID、缺少旧 UI 状态的镜头恢复可识别状态；服务端不凭名称或前端状态猜任务。
- 上游提交身份不明时进入 `needs_review`，保留原任务记录并停止自动重试。

### 2B-2 剧集范围恢复入口

- 新增短剧专属恢复函数/Route，扫描当前用户当前项目/剧集绑定的任务 ID。
- 逐镜调用现有同步逻辑，严格校验任务上下文；不创建第二个任务表。
- 返回每个镜头的同步结果和可继续轮询的任务集合，供页面刷新接管。

### 2B-3 批量视频终态聚合

- 工作台批量请求只创建缺失任务，随后等待每个视频任务的服务端终态。
- 轮询复用单镜同步/恢复，不重新提交；遇到 `needs_review` 立即计入待检查，不把批次标记为成功。
- 批次状态可在刷新后从任务集合重建，避免仅存在内存中的 `batchRunning` 假完成。

### 2B-4 工作台展示

- 明确展示提交中、处理中、结果待保存、待检查、成功、失败、已取消。
- 批量结束提示包含成功/失败/待检查/取消数量及可操作入口。
- 错误和待检查提示不覆盖已有媒体或锁定帧。

### 2B-5 验证与交付

- 增加服务端、路由和纯函数测试：状态缺失恢复、跨项目隔离、全部终态聚合、失败/取消/待检查汇总、重复点击幂等和刷新恢复。
- 运行定向 Vitest、`npm run typecheck`、`npm run lint`、`git diff --check`。
- 真实供应商、生产 PostgreSQL、FFmpeg 和浏览器人工验收记录到统一阶段验收，不在本阶段宣称通过。
- 独立提交：`feat(drama-lab): complete phase 2b video task terminal flow`。

## 完成定义

- 不依赖前端 `setTimeout` 把批量请求标为完成。
- 任务 ID、终态、错误原因和批量汇总均可从服务端重建。
- 不影响普通 Canvas 和其他业务域；所有新增测试及文档明确范围。
