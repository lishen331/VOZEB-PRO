# 开发计划：修复生成日志里的历史图片预览

- **日期：** 2026-11-25（北京时间）
- **状态：** 修复开发与验收记录；上线状态以生产工作流和实际站点核验为准。
- **目标：** 生产后台「生成日志」的图片列表缩略图、移动端卡片和详情预览，不再因自建渠道返回的临时签名过期而破图。

## 1. 问题与证据

生产排查时运行 `v0.8.45`（`888419cc`）。样例来自画布 `gpt-image-2` 自建生图渠道；生产任务标识、用户信息和链接仅保留于内部排障记录。以下时间为北京时间。

| 时间 / 检查项 | 实际结果 |
| --- | --- |
| 11 月 24 日 13:48:56 → 13:49:48 | 任务提交并成功完成。`result_media_complete` 记录 `200`、`1813534` 字节，随后出现 `result_persist_complete`。 |
| OSS 与数据库 | 自建网关直接写入我们自己的 OSS（`aiservice/images/` 对象）。日志资产同时有临时签名 `remoteUrl` 和平台 `/api/generation-log-assets/...` 地址；画布副本与日志副本均登记为对象存储、`permanent`，不使用该临时 URL 作为读取凭据。 |
| 11 月 24 日 13:55:18 → 11 月 25 日 09:14 | Nginx 记录同一 `remoteUrl` 的代理请求先 `200`，次日两次 `403`。签名 11 月 24 日 15:49:47 到期；原签名 URL 复核返回 OSS `403 AccessDenied: Request has expired.` |
| 已登录浏览器 | 从平台接口分别读取画布原图和后台日志原图，均为 `200 image/png`、`1813534` 字节，SHA-256 一致；原图 `1672×941`，后台副本的 `960×540` 预览也能加载。 |

**根因：** `generationLogAssetAccessUrl()` 对所有媒体优先选 `remoteUrl`，忽略已保存的平台图片地址。签名过期后浏览器走 `/api/media-proxy` 仍只能拿到 `403`。这是**后台取址错误**，不是生成失败、OSS 丢图或画布回写失败。

## 2. 修复范围

- 本次只改后台生成日志的**图片预览**。不改画布、生成路由、积分、任务状态、视频或音频取址。不迁移数据、不改 OSS 权限/签名时长、不重启上游、不重跑历史任务。
- 保持自建渠道直接写 OSS 的流程。优先使用已登记的平台资产 URL，沿用 `/api/generation-log-assets/...` 原有鉴权和现签机制。不要把完整签名 URL、查询参数、密钥写进日志、报告或测试夹具。
- 不通过修改 `browserReadableMediaUrl()` 的全局规则或修改 OSS Bucket ACL 兜底。

## 3. 实现步骤

**改动点：** `web/src/components/admin/admin-generation-log.tsx`。`GenerationLogAssetPreview` 同时服务桌面/移动端；详情用 `GenerationLogDetail` 内的结果区域。`web/src/lib/media-image-url.ts` 和 `web/src/app/api/generation-log-assets/[...path]/route.ts` 只复用现有能力，原则上不改。

1. [ ] 先新增 `web/src/components/admin/admin-generation-log.test.tsx`。构造图片同时拥有平台地址和 `remoteUrl` 的记录，断言桌面/移动列表与详情生成的 `src` 都指向平台路径，旧逻辑应使回归用例失败。使用虚构地址，不依赖生产或签名等待。
2. [ ] 图片取址：依次检查 `serverUrl`、`url`，优先取明确指向**本站** `/api/generation-log-assets/` 的非空资产地址；不要把任意外站同名路径当作平台资产。命中后分别走现有 `imagePreviewUrl(..., 256)` / `imagePreviewUrl(..., 960)`。没有明确的平台地址时保留旧版 URL 解析和代理行为；视频、音频继续走旧取址逻辑。
3. [ ] 图片请求失败后显示「图片暂不可预览」，不要显示浏览器破图图标；当有确切的签名过期证据时才明确写「链接已过期」，不能仅靠 `<img onError>` 判断。错误状态按资产/实际 URL 隔离，换图或 URL 变更不继承失败状态。不要做自动无限重试，不用已知过期的签名掩盖本地资源缺失或访问被拒绝。错误提示不改变「生成成功」或统计数据。
4. [ ] 按下方用例验证。代码改动和提交只包含该缺陷，不夹带其他工作区修改。

## 4. 测试与验收

| 用例 | 预期 |
| --- | --- |
| `serverUrl` 与过期 `remoteUrl` 同时存在 | 优先平台路径；列表、移动端、详情都不请求旧 `remoteUrl`。 |
| `serverUrl` 缺失或为普通远端 URL，但 `url` 是平台资产路径 | 仍优先 `url` 的平台资产，不被 `serverUrl` 遮挡。 |
| `serverUrl` 为 `https://example.invalid/api/generation-log-assets/...` | 不把外域同名路径识别为平台资产。 |
| 旧数据只有可读的外部 `remoteUrl` 或 `url` | 沿用原代理行为，仍可显示。 |
| 仅外部签名 URL 且读取失败；或者已登记的资产暂不可读 | 清晰占位，无破图；任务状态仍是成功，不作越权回退。 |
| 同一列表行换资产，或同一详情切换记录 | 新资产可正常加载，不继承上一张图的失败状态。 |
| 视频、音频、无资产记录及无权用户 | 视频/音频行为不变；无资产保留原空态；无权限用户不能读取平台资产。 |

- [ ] **测试环境真实浏览器验收**：用准备好的「上游签名已过期 + 平台副本可用」样例，逐一打开列表、移动端卡片、详情。确认本站资产路径成功，需要跳 OSS 时应由平台新签；图片解码成功，未向旧地址发请求。不能用一张刚生成、签名仍有效的图替代。
- [ ] **经批准发布后生产验收**：在管理员会话查内部记录所指的事发历史任务，确认同一历史记录的列表与详情都能打开，并核对生成状态仍为成功。抽查一条历史外链图与一条视频记录。记录实际版本、验证时间、请求状态及解码结果，不导出签名 URL。
- [ ] **回滚**：若出现管理员图片预览/权限回归，按项目发布流程回滚本次应用版本；没有数据库迁移或 OSS 修改需要逆操作。

## 5. 可选后续：直接复用自建网关对象，不与本次修复绑定

现状已是自建网关先写 OSS，但平台另存了受平台管理的副本。本次可直接使用现有副本恢复预览。若要省去后续重复存储，另行设计「自建渠道返回受信任的 OSS 对象键 → 平台按权限登记资产 → 展示时鉴权并签发短链」。开发前须确认对象所在 Bucket 和允许前缀、对象归属、平台读权限、保留时间以及多处引用下的删除责任。不能把任意上游 URL/对象键直接登记为平台资产，也不能假定自建网关上的对象与平台副本具有相同生命周期。
