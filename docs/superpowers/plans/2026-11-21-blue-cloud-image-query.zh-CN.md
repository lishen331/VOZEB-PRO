# blue-cloud 图片异步查询修复开发文档

## 范围与基线

- 生产 `a768dc5f` 中已保存上游任务 ID，但生成了 `/aiservice/images/tasks/detail/<taskId>`；允许的路径是固定 `/aiservice/images/tasks/detail`，ID 在 POST JSON 正文内。生产原始事件及离线复现见同日事故记录。
- 基于 `origin/develop` 的自建网关集成功能修复；同时继承生产已验证的 `queryMethod`、`queryBodyTemplate`、`successCodes` 字段在配置规范化和任务快照中的保留，防止测试环境退回 GET 或误判 `code=1`。

## 实施 / 验收

1. 对图片查询：POST 无路径占位符保持固定路径；有显式占位符照常替换；GET 与未指定方法保留旧行为。不改代理授权、视频运行时或路由权重。
2. 对显式 POST 异步图片契约：先判任务状态，成功只从声明的结果字段读图；不取回显输入图。终态失败优先返回任务自己的错误，不把外层 `ok` 当成错误或结果。已成功但缺结果、详情业务查询失败或状态不符合契约时进入待确认，保留 ID；只有上游明确生成失败沿用原有终态失败处理，取消不触发自动重提。保留同步和旧 GET 渠道的兼容解析。
3. 本地 TCP 夹具覆盖模型级配置保存、创建任务、排队、POST 路径与正文、状态和 OSS URL 解析，以及详情查询走现有归属校验。覆盖文生图、图生图、终态失败、旧 GET 与占位符路径。真实画布既有媒体校验、保存和稳定预览地址不变；签名 URL 不作为永久地址。
4. 本轮仅本地开发和验证。不提交生产任务、不改数据库/渠道、不推送、不部署。发布需另外批准，先测试、再生产；上线后从“检查状态”查询此前已保存的上游 ID，不重新提交；若上游原任务不可用则保留事实，不宣称已追回。

## 本地验证记录

- TCP 夹具先复现 `ok` 被当作失败；补回配置字段后复现 `/detail/<taskId>` 被站内代理拒绝；修正后验证固定 POST URL、原任务 ID、归属校验及图片结果读取。查询失败和成功但缺图的场景验证为查询契约异常，不当成生成失败。已恢复的既有 GET/路径占位符行为也在回归范围内。
- 17 个测试文件、334 项通过；TypeScript、改动文件的 ESLint/Prettier、Git 差异检查通过。开发地图与接口索引校验通过（78 个页面、447 个 API Route、147 张表）；本修复未增删接口或表。
- 未跑登录态画布浏览器和真实 blue-cloud 生产验收；未部署，未追回现存生产任务，未触发实际计费调用。生产的旧 `502` 与目标网关地址仍是分别需要核对的事项。
