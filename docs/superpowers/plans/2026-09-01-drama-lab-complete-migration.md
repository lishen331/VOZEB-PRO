# 短剧实验室完整融合迁移计划

> 建立日期：2026-09-01
> 目标：在不影响普通 Canvas、教师/学生管理、商单算力和现有平台生成链路的前提下，把 LocalMiniDrama 的真实业务编排逐阶段迁入 VOZEB PRO。
> 验收口径：以服务端业务行为、持久化、任务终态和恢复能力为准；页面入口、字段存在或定时器演示不算完成。

> 统一验收安排（2026-09-01）：真实图片/视频/音频供应商、生产等价 PostgreSQL、FFmpeg 运行环境以及浏览器人工交互/E2E 验收，统一延后到 Phase 0-4 全部开发阶段完成后集中执行。本安排只调整验收时点，不把未验证能力标记为已完成；各阶段仍须先通过可重复的服务端/单元测试并保留独立 Git 回滚点。

## 1. 总体目标

短剧实验室最终必须形成一条可恢复的生产闭环：

```text
故事梗概/小说
  -> 多集剧本任务与逐集保存
  -> 角色/场景/道具提取与真实 ID
  -> 分镜结构化提取与增量恢复
  -> 首/关键/尾帧提示词规划
  -> 绑定资产参考图生成分镜图
  -> 关键帧/首尾帧连续的视频任务
  -> 音频/TTS 与节奏编排
  -> 审核、批量终态与导出
```

所有长任务使用 VOZEB PRO 的 `generation_tasks`、Generation Worker、模型路由、计费/退款、日志和媒体登记。短剧领域只负责业务上下文、契约和结果回写。

## 2. 已有基线

- 平台原生融合架构、短剧接入关系和完成度矩阵见 `docs/architecture/2026-09-01-vozeb-pro-drama-lab-integration-architecture.md`。
- 项目、剧集、资产、分镜主数据在 `drama_projects.project_json`。
- 项目版本在 `drama_project_versions`。
- 图片/视频任务使用平台 `generation_tasks`，并已有单镜创建、同步、重试保护。
- 九套短剧模板已进入部分真实调用链。
- 一集一个短剧 Canvas 已通过 `sourceHandoffId` 隔离绑定。
- 旧迁移差异基线见 `docs/audits/2026-08-23-localminidrama-storyboard-migration-audit.md`；该报告中的 Canvas 缺失结论已过时。

## 3. 分阶段路线

### Phase 0：架构和契约基线（已完成）

**结果**

- 明确短剧是 VOZEB PRO 内部原生业务域，不是外挂应用。
- 明确平台基础设施与短剧领域服务的边界。
- 明确一集一个 Canvas、普通 Canvas 保留、受控复制同步和返回定位规则。
- 建立本计划及架构说明文档。

**验收**

- 架构图可渲染。
- 相关短剧服务测试通过。
- 本阶段独立提交，不混入用户其他工作区文件。

### Phase 1：P0 故事和分镜基础闭环（代码已完成，待人工验收）

#### 1A. 多集故事生成任务

**范围**

- 将故事生成从同步请求升级为平台文本任务或等价的可恢复服务端任务。
- `episodeCount` 必须真正创建/更新目标集数，不得只作为提示词字段。
- 逐集原子保存：单集成功不覆盖其他集；失败保留已成功结果和错误原因。
- 支持任务状态查询、取消、恢复、去重和页面刷新后继续轮询。
- 任务上下文必须包含 `surface=drama`、`projectId`、请求身份和尝试号。

**验收**

- 请求 3 集会产生 3 个可追踪集结果或明确失败项。
- 进程/页面中断后可从已保存集继续，不会重新创建已提交的上游任务。
- 重复点击使用同一幂等身份，不重复扣费或创建重复任务。

#### 1B. 小说导入与分集解析

**范围**

- 支持 TXT/MD 文件导入和长度限制。
- 识别常见章节标题，保留章节原文范围。
- 支持把章节映射为剧集草稿，并可交给 AI 改写任务。
- 导入失败不得清空当前项目；用户确认后才写入剧集。

**验收**

- 导入后服务端存在可编辑剧集和 `sourceRange`。
- 无章节标题时有确定的整文/长度分段策略。
- 刷新页面后导入结果仍存在，且项目外用户不能读取。

#### 1C. 分镜结构契约与恢复

**范围**

- 补齐 L 需要的段落、摄影、灯光、景深、全能模式等字段，并保留兼容旧数据。
- 分镜 JSON 强制返回真实 `sceneId`、`characterIds`、`propIds`；服务端只接受项目内 ID。
- 增量保存、截断续写、部分结果恢复和明确的失败分段。
- 分镜结果必须按剧集版本/请求身份关联，旧任务不能覆盖新版本。

**验收**

- 模型返回幽灵 ID 时请求失败并退款/记录原因，不写入项目。
- 100 个镜头中途失败时，已成功镜头可继续使用并可从断点重试。
- 刷新后能看到上次已保存的镜头和任务状态。

**实现记录（2026-09-01）**

- **1A 故事生成**：已使用平台 `text` 任务和 `generation_tasks` 事实源；`episodeCount` 真实创建目标集数，`storyBatch` 记录目标集、逐集持久化进度和终态。服务端已实现请求幂等、项目级运行中去重、任务查询/取消/恢复、Worker 恢复、页面刷新后自动发现活动任务，以及完成任务后的逐集物化。集数不足、编号不连续和无效剧本会明确失败，保留已成功前缀。
- **1B 小说导入**：已实现 TXT/MD 的 JSON 与 multipart 入口、2MB 限制、章节识别/无章节分段、预览与确认导入；确认前不写剧集，确认时创建恢复版本并仅替换剧集，保留资产与项目配置并保存 `sourceRange`。
- **1C 分镜契约**：已实现 `shots`/`storyboards` 兼容、snake_case 兼容、真实项目资产 ID 白名单、摄影/段落/灯光/景深/全能模式/提示词/continuity 字段、JSON 截断修复、最多三次续写、增量检查点、已有分镜恢复和重复镜号保护。
- **自动化验证**：`npm run typecheck` 已通过；故事生成、故事 Route、小说导入、小说 Route、分镜提取和分镜任务相关定向测试已通过（包含 multipart 导入覆盖）。

**Phase 1 阶段状态**

代码路径已完成并保持在短剧实验室边界内，但尚未将真实供应商、生产等价 PostgreSQL 和浏览器人工回归视为完成。正式验收必须覆盖：多集真实生成与失败退款、刷新/进程中断恢复、小说预览确认与版本回退、长剧本分镜截断续写、无效资产 ID 拒绝、并发版本保护，以及桌面/390px 移动端的任务状态与错误提示。Phase 2A 已完成服务端代码和定向自动化测试，工作台控件与真实媒体链路仍待验收；Phase 2B 的完整视频终态、Phase 2C 的音频/TTS 和批量编排仍未开始。

### Phase 2：P1 视觉连续性和音频闭环

#### 2A. 首帧、关键帧、尾帧和跨镜连续性

- 接通 L 的三类帧模板与完整空间/角色白名单约束。
- 支持首帧、尾帧上传、历史恢复和布局锁。
- 默认将上一镜尾帧作为下一镜首帧候选，由用户确认后复用。
- 服务端保存实际发送给图片模型的 prompt、参考图和模型参数快照。
- 生成后清洗非本镜角色，避免人物乱入、道具夸大和时代错乱。

**Phase 2A 实现记录（2026-09-01）**

- **帧契约与提取服务**：`DramaShotFrameState` 已保存来源、持久化媒体键、源视频任务/镜头/历史 ID 和锁定状态；`DramaShot` 已保存下一镜的 `firstFrameCandidate`。`extractDramaLabTailFrame` 只接受当前用户拥有且已成功的视频任务，使用平台媒体下载、FFmpeg/ffprobe 和参考媒体登记提取真实末帧；同一源任务重复调用复用已登记媒体并保持候选 ID 稳定。
- **候选与人工控制路由**：已增加末帧提取、下一镜首帧候选确认、首/关键/尾帧上传以及逐帧锁定/解锁接口。候选只能从项目内服务端状态解析，默认不覆盖已有首帧；显式替换会保留历史。上传格式/大小、项目和用户归属、锁定帧修改及版本冲突均在服务端校验。
- **视频引用和快照**：视频准备结果将首帧、尾帧和普通参考图标记为角色化引用；不支持尾帧的模型会记录明确降级原因。创建视频任务时把不可变的 `videoFrameSnapshot` 写入现有 `generation_tasks` 的 payload/context，未新增独立任务基础设施。
- **同步保护**：任务同步不会覆盖已锁定帧，并保留来源字段、候选和历史；生成帧/上传接口也拒绝对锁定帧的隐式覆盖。用户显式上传、锁定和候选确认在项目版本冲突时返回 409，不自动重放。
- **自动化验证**：Phase 2A 服务、帧/图像/视频/同步路由、视频引用、项目/任务存储及工作台控件回归测试已通过（本轮定向套件 12 个测试文件、125 项测试）；`npm run typecheck`、`npm run lint` 和 `git diff --check` 均已通过。工作台 UI 控件、真实 FFmpeg、真实图片/视频供应商及生产等价 PostgreSQL 仍需人工验收，不能据此标记为阶段完全交付。

#### 2B. 视频任务完整语义

- 视频只读取当前镜头绑定的主参考图/关键帧。
- 保留上游任务 ID，明确区分 `submitted`、`needs_review`、`result_ready` 和终态失败。
- 批量视频必须等待全部子任务终态后再报告批次结果。

**2B 验收时点说明**：本阶段先完成任务状态契约、剧集范围恢复和批量终态聚合的代码及自动化测试；真实供应商状态映射、生产 PostgreSQL 并发/重启恢复和浏览器批量操作留待全阶段统一验收。

#### 2C. 音频和 TTS

- 对白、旁白、角色声线和音频状态持久化。
- 复用平台音频任务、计费、媒体登记和恢复机制。
- 支持按音频时长/节奏拆镜，且不覆盖用户手工镜头。

### Phase 3：P1/P2 工作流编排和导出

Phase 3 拆为四条独立主线。团队协作审批的业务范围以
`docs/superpowers/specs/2026-09-02-drama-lab-team-approval-requirements.md`
为准；用户身份体系、教师/学生管理和 Canvas 本身不在本阶段重新设计。

#### 3A. 一键全流程

- 把前端 `setTimeout` 演示替换为服务端父任务/子任务编排。
- 每一步保存输入快照、输出引用、失败原因和可恢复状态。
- 一键流程复用平台 `generation_tasks`、计费、轮询、取消和恢复机制。

#### 3B. 真实审核与团队审批

- 内容审核使用真实模型或明确的规则服务，状态持久化并可重试。
- 短剧项目创建时建立项目组，创建者默认为项目管理员。
- 通过邀请链接/二维码提交加入申请，由管理员确认后加入；不得检索项目外账号。
- 支持项目内成员/申请搜索、移除成员、主动退出、副组长和管理员交接。
- 审批配置、提交、通过、驳回、意见、历史记录和权限校验必须在服务端持久化。
- 审批记录保存集数、阶段和资源定位，点击后至少进入对应短剧实验室页面。

#### 3C. Canvas 双向应用边界

- 继续保留普通 Canvas 与短剧专属 Canvas 的代码隔离。
- Canvas 结果默认留在 Canvas；用户显式点击“应用到资产/分镜”时才回写。
- 回写请求必须携带项目、剧集、镜头、资产/目标字段和版本号。
- 回写失败不得静默覆盖短剧数据。

#### 3D. 完整项目导入导出

- 导出项目元数据、剧集、资产、分镜、任务引用和媒体索引。
- 导入时校验版本、真实 ID 和媒体权限，禁止生成幽灵资产。
- 当前剪映草稿导出继续保留。

### Phase 4：平台收敛和发布验收

- 清理或明确未接入运行链路的 `drama_lab_*` 兼容表。
- 将真正运行需要的短剧配置统一到平台全局配置，避免管理员私有模板来源不确定。
- 完成普通 Canvas、短剧 Canvas、教师/学生、商单算力、个人积分的回归矩阵。
- 补齐 Playwright 真实点击、API 契约、任务恢复、媒体权限和部署冒烟测试。
- 每个阶段独立提交、独立回滚点，阶段完成后更新 `pending-test.mdx` 和变更记录。

## 4. 当前协作拆分

| 责任人 | 当前工作 | 允许修改的边界 | 不应修改 |
| --- | --- | --- | --- |
| 子智能体 A | Phase 1A：多集故事任务和逐集保存 | 故事生成服务、故事生成 Route、对应 Store/任务测试 | 分镜服务、Canvas 运行时、学校权限 |
| 子智能体 B | Phase 1B：小说导入、章节识别、剧集草稿 API | 新的小说导入服务/Route/解析测试；必要时只新增独立 UI hook | 故事任务状态机、分镜字段、普通 Canvas |
| 子智能体 C | Phase 1C：分镜契约、增量保存和恢复 | 分镜服务、分镜 Route、分镜契约/测试；不得改故事生成 | Canvas、音频、平台通用任务 Runtime |
| 主智能体 | 计划、跨模块契约、集成、冲突处理、Phase 2/3、最终测试和提交 | 共享契约、集成测试、文档和未分配模块 | 不回滚其他协作者改动 |

子智能体先修改代码和测试，不直接提交 Git；由主智能体在集成测试通过后按阶段提交。若某条线必须扩展共享契约，先在消息中说明涉及文件和兼容策略。

## 5. 阶段完成定义

每个阶段必须同时满足：

1. 业务路径真实可运行，不能只存在按钮或 mock 定时器。
2. 数据、任务、媒体和错误均可在服务端恢复。
3. 所有输入按当前用户、项目、剧集和镜头权限校验。
4. 相关 Vitest/API/Playwright 测试通过。
5. 文档说明当前已完成、仍缺失和测试方式。
6. 独立 Git 提交，提交信息能说明阶段和回滚范围。

## 6. 风险和决策

- 不为故事生成另建 `drama_lab_async_tasks` 主链路；平台 `generation_tasks` 是唯一任务事实源。
- 不把多集故事结果塞进一次巨大 JSON 后最后统一保存；必须逐集原子持久化。
- 不让模型按名称猜测资产；ID 白名单由服务端最终裁决。
- 不把 Canvas 自动双向覆盖短剧；必须显式应用并做版本校验。
- 不因后台 CRUD 存在就宣称配置已接入；每项配置必须有运行时调用证据。
- 不改变普通 Canvas、学校租户、教师学生和商单算力的既有边界。
