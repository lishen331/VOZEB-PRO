## 阶段二补充执行方案：实时结果与保存确认
- SSE 写入前在实际最新节点上比较本次提交时的正文/类型；不使用过期 React 渲染快照。只保护画布后台 Agent，不改变本地桥或主 Agent。

- Canvas模型可提出delete_nodes或disconnect，必须返回精确ID；服务端按当前项目真实节点/连线及选中范围验证，只保存待确认方案，不执行删除。布局保持原闭环。

- Canvas Agent 可提出精确的 `delete_nodes` / `disconnect` 待确认方案；仅 Canvas 契约放行，主 Agent 仍拒绝。ids 必须真实、非空、非通配符；运行中任务节点、内部节点不能删除；选中范围限制由服务端校验。
- 方案只持久化，不在模型完成时删除。前端消息显示“查看影响并确认”，弹窗列出目标节点、节点类型、ID及关联连线，并提供取消/确认按钮和滚动区域。
- 确认时重新读取当前图并比较预览快照；目标、内容、类型、关联边改变则拒绝执行。取消零变化；确认只改当前画布节点/连线，不删除素材库文件、不取消上游任务。
- 已确认/已取消决策写入对话并通过既有版本保存；重复确认、事件重放、刷新恢复只保留决策，不重复删除。布局操作仍走既有非破坏性路径。
- 画布历史保留 Agent 操作/确认回执，撤销只恢复图内容，不能使已处理的待确认方案再次执行。
- 分组核对完成：普通 Canvas 无通用分组容器或分组 CRUD；`imageLayer.groupId` 只是图片分层字段，本阶段不伪造分组能力。
