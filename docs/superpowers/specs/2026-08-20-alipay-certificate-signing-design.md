# 支付宝证书签名方式设计规格

## 背景

当前支付宝渠道已经支持两种支付产品：官方电脑网站支付和当面付。两种产品都使用应用私钥签名，并使用支付宝开放平台公钥验签。支付宝还提供证书签名方式，要求同时配置应用公钥证书、支付宝公钥证书和支付宝根证书。证书签名是另一套加签方式，不应被实现成第三种支付产品，也不能覆盖现有普通公钥配置。

## 目标

- 在支付宝渠道中增加独立的“加签方式”选择：普通公钥、证书模式。
- 官方电脑网站支付和当面付都能使用两种加签方式。
- 证书模式覆盖下单、当面付预创建响应验签、退款、交易查询和异步回调验签。
- 未选择证书模式时保持现有配置、请求参数和验签行为不变。
- 证书内容可通过后台加密保存，也可继续使用服务器环境变量指定文件路径。
- 管理后台能明确显示当前加签方式、证书必填项和配置状态，不展示私钥或证书正文。

## 非目标

- 不新增支付宝支付产品，不改变官方支付与当面付的订单状态流程。
- 不自动上传证书到支付宝开放平台。
- 不把证书私钥写入日志、审计 metadata、API 响应、订单 metadata 或浏览器持久化存储。
- 不回收或迁移现有普通公钥配置；已有配置缺少新字段时按普通公钥模式解释。

## 配置契约

支付宝保留现有 `mode` 字段作为支付产品选择：

- `official`：官方电脑网站支付。
- `face_to_face`：当面付二维码。

新增 `signatureMode` 字段作为加签方式选择：

- `public_key`：应用私钥 + 支付宝公钥，默认值，兼容现有配置。
- `certificate`：应用私钥 + 应用公钥证书 + 支付宝公钥证书 + 支付宝根证书。

支付宝普通公钥模式字段：

- `appId`
- `privateKey` 或 `VOZEB_PRO_ALIPAY_PRIVATE_KEY_PATH`
- `publicKey` 或 `VOZEB_PRO_ALIPAY_PUBLIC_KEY_PATH`

支付宝证书模式字段：

- `appId`
- `privateKey` 或 `VOZEB_PRO_ALIPAY_PRIVATE_KEY_PATH`
- `appCert` 或 `VOZEB_PRO_ALIPAY_APP_CERT_PATH`
- `alipayCert` 或 `VOZEB_PRO_ALIPAY_ALIPAY_CERT_PATH`
- `rootCert` 或 `VOZEB_PRO_ALIPAY_ROOT_CERT_PATH`

后台保存的字段继续沿用 `payment-config.json` 或 PostgreSQL settings 的加密 secret 字段。证书字段使用与私钥相同的加密保存和留空保留原值规则。环境变量优先级与现有渠道一致：后台保存值覆盖同名进程环境变量，字段的路径环境变量用于服务器本地文件读取。

证书模式下不得把 `publicKey` 当作支付宝证书的替代配置；普通公钥模式下不得因为存在证书字段而改变请求。`signatureMode` 缺失、空值或历史配置没有该字段时按 `public_key` 处理。

## 证书解析与签名

新增共享支付宝签名凭据解析器，供 checkout、refund、transaction verification 和 webhook adapter 使用。解析器返回私钥、验签公钥、加签方式以及证书序列号，不向调用层暴露证书正文以外的敏感诊断信息。

证书模式初始化时：

1. 读取应用证书、支付宝公钥证书和根证书，支持后台文本和服务器路径。
2. 从应用证书计算 `app_cert_sn`，从根证书计算 `alipay_root_cert_sn`。序列号使用支付宝证书模式的 `MD5(issuer DN + serial number)` 规则，结果为小写十六进制字符串。
3. 从支付宝公钥证书提取 RSA 公钥作为响应和回调验签公钥。
4. 根证书文件允许包含多个 PEM 证书；必须找到可用于支付宝根证书序列号的 RSA 根证书，否则配置不可用。
5. 任一证书格式错误、无法提取 RSA 公钥、证书模式缺少必填项或序列号无法计算时，配置保存或运行时检查返回明确的配置错误，不降级到普通公钥模式。

证书模式的支付宝网关参数在普通参数之外增加：

- `app_cert_sn`
- `alipay_root_cert_sn`

这两个参数参与与其他业务参数相同的 RSA2 签名排序。普通公钥模式不发送这两个参数。官方支付和当面付共用该参数构造；当面付预创建响应使用支付宝公钥证书验签。

## 退款、交易查询和回调

- 支付宝退款和交易查询统一复用共享凭据解析器；证书模式请求附带两个证书序列号参数并使用同一应用私钥签名。
- 支付宝异步回调在证书模式下使用支付宝公钥证书验签；普通公钥模式继续使用现有支付宝公钥。
- 回调验签必须先校验 `app_id`、`sign_type` 和签名内容，证书模式不得因为普通公钥字段存在而接受错误证书。
- 订单金额、订单号、交易号和状态校验保持现有逻辑，不因加签方式改变。

## 管理后台交互

支付宝配置面板保留“接入方式”字段，并新增“加签方式”字段。选择证书模式后：

- 展示应用私钥、应用公钥证书、支付宝公钥证书、支付宝根证书四项必填检查。
- 隐藏普通公钥字段或明确标记为“不适用于当前证书模式”，避免管理员误以为两套配置需要同时填写。
- 为证书字段提供粘贴 PEM 文本和服务器路径的说明，提示证书下载、保管和更新方式；不在页面上传或回显私钥、证书正文。
- 证书模式与普通公钥模式的保存、启用和状态刷新保持读后写一致；保存后立即重新读取配置摘要。
- 面板的 checkout/webhook readiness 必须根据当前 `signatureMode` 的真实必填项计算。

## 错误与安全

- 证书配置错误使用现有支付配置错误映射，不能伪装成上游订单失败。
- 证书读取路径只能读取服务端已配置路径；浏览器提交的路径不直接读取。
- 证书正文、私钥、派生公钥和签名原文不得写入日志、审计 metadata、错误消息或公开 DTO。
- 证书模式和普通公钥模式互斥，任何一套凭据不完整时禁止启用支付宝渠道。

## 测试验收

- 配置类型和保存测试：默认兼容普通公钥，证书模式字段校验、加密保存、部分更新和错误输入。
- 证书解析测试：PEM 文本、文件路径、应用证书序列号、根证书序列号、支付宝公钥提取和 malformed certificate 拒绝。
- checkout 测试：官方支付与当面付分别验证普通公钥和证书模式，断言证书参数、签名和响应验签。
- refund/query 测试：证书模式发送证书序列号并验证响应签名。
- webhook 测试：证书模式使用支付宝公钥证书验签，普通公钥模式行为保持不变，错误证书签名被拒绝。
- 管理后台组件和 API 测试：加签方式切换、动态必填项、保存后状态立即可见且不泄漏 secret。
- 真实 PostgreSQL 配置读写回归、`pnpm typecheck`、相关 Vitest、`pnpm check:release` 和支付宝支付配置页面的桌面/390/430 浏览器验收。
