# IP 库设计

> 状态：已确认
>
> 初版日期：2026-08-19
>
> 本次修订：2026-08-31

## 1. 背景与目标

平台需要把已经在线下完成提交和审核的 IP 内容整理成可授权的完整内容包，通过公共发布或学校授权提供给用户。IP 库不是个人资产库，也不是线上投稿社区：个人资产用于保存用户通过 AI 生成或自行上传的通用创作素材，IP 库则负责组织具有统一世界观和内容体系的文本、图片、音乐、声音及视频参考。

第一期目标是让平台管理员能够从本地上传、预览、发布和维护 IP，按多校或独家方式授权学校；学校管理员决定是否把整套 IP 向本校成员开放；用户可以在线查看和下载有权访问的 IP 内容，用于线下教学和创作。

第一期用户界面只做展示与下载，不开放 IP 接入 Canvas、短剧或无限练习的入口，不扩展项目引用、线上版权审核、作品发布限制、商单使用限制、版权结算或学校结算。现有 IP 引用领域契约、服务和持久化字段作为后续能力保留，但默认关闭且不在任何用户界面展示。

## 2. 已确认的产品决策

### 2.1 用户端入口

IP 库位于用户端：

```text
社区
└─ IP库
   ├─ 公共 IP
   └─ 本校 IP
```

用户端不展示“多校授权 IP”目录。学校 IP 统一显示为“本校 IP”；当前学校获得独家授权时，额外显示“独家授权”标签。多校授权信息只在平台管理员后台展示。

### 2.2 角色边界

- 平台内容管理员：创建 IP、上传文件、预览草稿、编辑草稿、发布版本和下架 IP。
- 平台教育管理员：创建、暂停、恢复或撤销学校授权，并查看授权历史。
- 学校管理员：不能上传或修改 IP，只能对平台已授权的整套 IP 执行“向本校成员开放/关闭”。
- 学校老师和学生：只能查看、预览和下载当前学校已经开放的 IP。
- 普通 C 端用户：只能查看、预览和下载公共 IP。

平台管理员的 `admin` 身份不自动等于学校成员。平台管理员可以在后台管理和预览全部 IP，但用户端角色预览不产生真实学校身份或下载记录，也不能借此绕过学校授权。

### 2.3 访问范围

- 公共 IP：所有已登录用户可以查看、预览和下载，不经过学校授权或学校开放开关。
- 本校 IP：同时满足“平台授权有效”和“学校已经开放”后，当前学校的 active teacher、active student 及学校管理员才能查看、预览和下载。
- 一个用户属于多所学校时，以当前学校上下文判断“本校 IP”，下载记录同时绑定当前学校。
- 学校之间不能读取、搜索、预览或下载对方的本校 IP。
- 没有有效学校身份的普通 C 端用户不显示“本校 IP”；直接请求无权 IP 的详情、媒体或下载接口时按学校隔离规则返回 403 或 404。

### 2.4 授权模式

授权模式与“公共/本校”展示范围分开：

- `multi_school`：同一 IP 可以同时授权给多个学校。
- `exclusive`：同一有效授权时间内只能有一所学校获得授权。
- 公共 IP 不需要学校授权模式。

独家授权冲突必须同时在 service 和数据库约束层拒绝。多校授权信息不出现在用户端。

### 2.5 学校二次开放

平台向学校授权后，不直接向学校成员开放。每一条新学校授权的校内开放状态默认关闭，完整流程为：

```text
平台发布 IP
→ 平台授权学校
→ 学校管理员整套开放
→ 本校全部有效成员可以访问
```

学校开放以整套 IP 为最小单位，不增加班级、角色、老师、学生或个人级授权。

- 学校关闭开放后，成员立即不能继续预览或下载，但平台授权记录不受影响。
- 平台暂停授权、撤销授权、授权到期或下架 IP 时，校内开放状态即使为开启也不生效。
- 暂停后恢复同一条授权时，恢复学校原来的开放状态。
- 撤销后重新授权属于一条新授权，校内开放状态重新默认为关闭。
- 所有授权、暂停、恢复、撤销、开放和关闭操作记录操作者、时间、学校和 IP。

### 2.6 内容录入与审核

IP 由平台在线下完成提交和审核，线上不提供版权方、创作者或学校投稿流程。审核完成后，由平台管理员在后台创建、编辑和发布 IP。学校和普通用户只能查看、预览和下载。

IP 内容必须由平台管理员从本地上传，不再从个人素材库选择文件。IP 内容不属于上传管理员个人，也不写入个人资产库。

### 2.7 发布版本

IP 使用不可变发布版本：

```text
IP
├─ v1 已发布（只读）
├─ v2 已发布（只读）
└─ v3 草稿（可编辑）
```

- 草稿版本可以编辑、替换和删除内容项。
- 发布时冻结版本标题、简介、封面、标签、来源说明和内容清单。
- 编辑已发布 IP 时，从最新发布版本创建新草稿；发布后形成新版本。
- 未变化的内容文件可以被新版本继续引用；替换内容必须产生新的 IP 内容文件。
- 新版本发布后，IP 列表、新预览和新下载自动使用最新发布版本。
- 已授权且已经开放的学校不需要重新授权或重新开放，即可看到最新发布版本。
- 旧版本、旧文件和历史下载记录保留为只读追溯数据，不因新版本发布而覆盖。

### 2.8 下载与线下创作

IP 详情页支持单项原文件下载和完整 IP 包下载：

- 上传的 TXT/MD 保留原始格式下载；后台手工录入的正文生成 TXT 文件。
- 图片、音频和视频下载原始文件，网页预览使用受控预览地址或现有媒体变体。
- 完整 IP 包为 ZIP，包含原始内容文件、封面、目录、版本信息、来源/署名说明和 `manifest.json` 清单。
- 学校可以把下载内容用于线下教学和创作，第一期不要求回传平台。
- 授权、学校开放或 IP 状态失效后，禁止新的在线查看、预览和下载。
- 已经下载到本地的文件不做技术回收；现有项目和已经生成的成果不级联删除。
- 每次下载记录用户、学校、IP、版本、下载对象和时间。

## 3. IP 内容与文件模型

### 3.1 内容结构

一个 IP 是完整内容包，不是单个素材文件。第一期按四个大类组织：

```text
IP 内容
├─ 文本
│  ├─ 故事简介
│  ├─ 世界观
│  ├─ 人物小传
│  ├─ 剧本
│  ├─ 二创剧本
│  └─ 场景设定/创作说明
├─ 图片
│  ├─ 角色
│  ├─ 场景
│  ├─ 道具
│  ├─ 特效
│  └─ 风格参考
├─ 音乐与声音
│  ├─ 背景音乐
│  ├─ 主题音乐
│  ├─ 角色声音
│  ├─ 旁白
│  └─ 音效
└─ 视频参考
   ├─ 预告片
   ├─ 动作参考
   ├─ 表演参考
   ├─ 镜头参考
   └─ 成片片段
```

图片分类在“图片”大区中作为子分类展示；文本、音乐与声音、视频分别集中展示，不拆分成额外顶层菜单。

### 3.2 独立 IP 内容文件

IP 库新增独立内容文件模型，底层复用现有对象存储、媒体访问、预览变体和签名下载能力，但不复用个人资产记录。

每个 IP 内容文件至少保存：

- 文件类型：`text | image | audio | video`
- 原始文件名、扩展名、真实 MIME、字节大小和校验值
- 对象存储位置及预览所需元数据
- 文本提取正文，或图片尺寸、音视频时长等媒体信息
- 上传管理员、创建时间和处理状态

内容文件没有个人 `ownerUserId`，版本内容项通过稳定 `fileId` 引用它。内容文件只有在未被任何草稿、已发布版本或下载记录引用时才允许清理。

### 3.3 本地上传和预览

- 文本第一期支持 `.txt` 和 `.md`，保存原文件并严格按 UTF-8 提取正文用于在线阅读。
- 后台手工录入正文时生成 `.txt` 原文件，并使用相同文件模型管理。
- 图片、音频和视频沿用项目现有媒体格式白名单、上传配置和存储供应商限制，不增加拍脑袋的固定大小限制。
- 图片生成缩略图；音乐支持试听；视频支持在线播放；长文本支持只读预览。
- 格式不支持、正文无法解码、上传失败或预览处理失败时显示明确状态；未处理完成的内容项不能发布。

## 4. 数据与状态

第一期领域对象包括：

```text
IP 主体 ip_packages
├─ 稳定 IP 身份
├─ public / school 展示范围
└─ 整体可用状态

IP 版本 ip_versions
├─ 版本号与发布状态
├─ 标题、简介、封面、标签和来源说明快照
└─ 发布时间与发布管理员

IP 内容文件 ip_content_files
├─ 原文件与存储信息
├─ 类型、格式、校验值和处理状态
└─ 提取正文或媒体预览元数据

版本内容项 ip_items
├─ versionId + fileId
├─ 类型、分类、标题、摘要和排序
└─ 发布后不可修改

学校授权 ip_school_grants
├─ 学校、multi_school / exclusive 授权模式、有效时间与授权状态
├─ memberAccessEnabled 校内开放状态
└─ 开放/关闭操作者及时间

下载记录 ip_download_records
├─ 用户、学校、IP 和版本
├─ 单项文件或完整资源包
└─ 下载时间和结果
```

新版本内容不再使用 `assetId` 关联个人资产，也不扩展 Canvas、短剧或无限练习的 IP 引用字段或关联表。既有 `IpReference`、引用 service、项目字段和历史使用记录保留为休眠能力，由统一功能开关控制可见入口；本期不删除、不迁移、不新增调用。业务代码直接使用新的独立文件领域契约，不为个人资产旧字段增加双读双写；已有持久化 PostgreSQL 必须通过幂等增量 Schema 升级先补齐新表和新字段，旧列在新结构完成验证前保留，后续只能按明确清理任务处理。

## 5. 页面与交互

### 5.1 用户端 IP 列表

`社区 → IP库` 沿用现有用户端、Ant Design、Tailwind 和卡片模式。列表提供“公共 IP”和“本校 IP”两个视图，以及关键词、内容类型和标签筛选。

卡片展示封面、名称、简介、内容数量、公共/本校范围、最新版本和授权标签。多校授权不作为用户端文案。

### 5.2 用户端 IP 详情

详情页采用“资源全集”布局：

```text
IP 基本信息
├─ 封面、名称、版本、更新时间和简介
├─ 公共 IP / 本校 IP / 独家授权
└─ 操作：下载资源包

文本
图片
├─ 角色
├─ 场景
├─ 道具
├─ 特效
└─ 风格参考
音乐与声音
视频
```

每个内容区展示摘要卡、真实预览、数量和“查看全部”。文本只读，图片可查看缩略图和放大预览，音乐可以试听，视频可以播放。页面不显示“一键使用”，不提供导入创作项目或平台内编辑入口。

### 5.3 学校管理入口

学校管理员仍作为老师使用用户端。在现有学校管理页面中增加“IP 开放”区域，列出平台已经授权给本校的 IP、授权状态、有效期、授权类型和校内开放状态。学校管理员只能整套开启或关闭，不能编辑内容、改变授权模式或选择部分成员。

### 5.4 平台管理后台

后台“内容运营 → IP 库管理”包含三个职责区：

```text
IP 内容
学校授权
下载记录
```

`IP 内容`采用现有“列表/卡片 + 创建按钮 + Modal/Drawer”模式。拥有 `content.manage` 的管理员可以创建草稿、本地上传内容、预览草稿、编辑草稿、发布新版本、下架 IP 和查看历史版本。后台预览必须展示真实正文、图片缩略图、音频播放器和视频播放器，不能只显示标题、类型和分类。

`学校授权`由 `education.manage` 控制，支持多校/独家授权、有效时间、暂停、恢复、撤销和备注。`下载记录`支持按 IP、版本、学校、用户、下载对象和时间分页查询。

第一期不新增平台管理员权限类型。同一后台分区可以对拥有任一相关权限的管理员显示，但每个职责区和服务端操作仍按对应权限校验。

## 6. 服务边界与数据流

服务端沿用项目现有分层：

- Route Handler：处理 Session、HTTP 入参、调用 service 和 `{ code, data, msg }` 响应映射。
- IP 内容 service：处理草稿、上传、预览、版本发布和文件引用校验。
- IP 授权 service：处理多校/独家授权状态和学校开放状态。
- IP access service：统一判断公共范围、当前学校上下文、授权状态、学校开放状态和版本状态。
- IP 下载 service：重新校验访问权限，返回单项原文件或生成完整 ZIP。
- Repository：按 IP、版本、学校、状态、时间和分页执行 PostgreSQL 定向查询；文件 Provider 继续作为项目既有回退实现。

学校身份必须从当前 Session 和学校上下文派生，不接受客户端提供的授权用 `schoolId`。预览和下载每次重新校验权限，页面只得到受控或短期媒体地址，不暴露对象存储密钥和长期源地址。

## 7. 状态与异常处理

- 未登录返回 401。
- 无学校身份、学校未开放或授权失效返回 403。
- 跨校或无权资源按现有隔离规则返回 404。
- 独家授权冲突、重复发布或版本状态冲突返回 409。
- 文件格式错误、正文编码错误或发布内容不完整返回 422。
- 上传失败不产生可发布内容项；无任何版本引用的孤立文件才允许清理。
- ZIP 中任意授权文件读取失败时，整个下载失败并记录公开原因，不返回缺失内容但表现为成功的资源包。

版本发布、独家授权冲突和学校开放状态更新必须使用事务及数据库约束保证一致性。管理员授权、学校开放和下载事件都写入现有审计或对应业务记录，不保存文件密钥、长期签名 URL 或完整私密正文。

## 8. 非目标

第一期不建设：

- 版权方、创作者或学校线上投稿
- 线上版权审核流程
- IP 商城、订单、支付和学校结算
- 作品公开发布、首页推荐或商单使用规则
- 下载文件的远程回收
- 对用户开放“一键使用”或导入 Canvas、短剧、无限练习
- 扩展 Canvas、短剧、无限练习与 IP 的项目引用关系；现有引用能力仅隐藏保留
- Canvas 与短剧之间的项目转换
- 复杂的逐内容项、班级、角色或个人授权
- 多学校之间的协作编辑

## 9. 验收条件

1. 用户端入口为 `社区 → IP库`，列表只有“公共 IP”和“本校 IP”。
2. 平台管理员可以从本地上传 TXT、MD、图片、音频和视频，并在草稿中真实预览。
3. IP 内容使用独立 IP 文件记录，不属于管理员个人，也不引用个人资产。
4. 用户端详情按文本、图片及其子分类、音乐与声音、视频四个区域展示。
5. 普通 C 端用户只能看到公共 IP；本校 IP 只有在平台授权有效且学校已经整套开放时才对当前学校 active 成员可见。
6. 独家授权在本校 IP 卡片上显示；多校授权不在用户端显示。
7. 新学校授权默认关闭；学校管理员可以整套开放或关闭，不能按班级、角色或个人授权。
8. 新版本发布后自动成为最新展示和下载版本，原版本、文件和下载记录仍然可追溯。
9. 用户可以下载单项原文件和完整 ZIP；TXT/MD 保留上传格式，手工正文下载为 TXT。
10. 授权、学校开放或 IP 状态失效后，新的在线预览和下载被拒绝，历史下载不被删除。
11. 用户端不存在“一键使用”，Canvas、短剧和无限练习的 IP 引用入口默认隐藏；既有引用契约与服务仍保留供后续启用。
12. 不同学校无法读取本校 IP、媒体源文件或下载地址。
13. 相关测试、类型检查、Mandatory Testing、浏览器回归和 UTF-8/乱码检查全部通过。
14. 数据结构和接口变化同步更新数据库文档、接口索引和开发地图。
