# 无限练习单项工作台修订设计

## 1. 文档定位

本文档补充并修订以下既有文档中关于无限练习单项模块的部分：

- `docs/superpowers/specs/2026-08-18-infinite-practice-pull-film-design.md`
- `docs/superpowers/specs/2026-09-01-runninghub-workflow-practice-design.md`
- `docs/superpowers/plans/2026-08-18-infinite-practice-pull-film-implementation.md`
- `docs/superpowers/plans/2026-09-01-runninghub-workflow-practice-implementation.md`

本次修订只针对无限练习的单项练习页面和会话状态，不改变短剧实验室。短剧实验室仍是替换当前短剧生产模块的正式生产项目，使用 `production` 执行档案；无限练习中的短剧项目仍是独立的 `open-source-practice` 项目类型。

## 2. 现状问题结论

### 2.1 页面问题

当前 `practice-module-workbench.tsx` 把剧本、分镜图、分镜视频、配音和音乐全部放在同一套表单中：统一的提示词输入、素材 ID 文本框、统一的“开始练习”按钮和按结果类型分支的结果区。这个抽象只适合接口演示，不适合真实练习任务。

具体问题：

1. 分镜图练习没有明确的“文字 → 图片”输入和图片结果区域。
2. 分镜视频练习缺少模型选择、必需的参考图片和视频专用提示词输入。
3. 配音练习没有配音文本、音色/模型等输入。
4. 音乐练习没有音乐需求和音频参数输入。
5. 剧本练习被错误地当成模型生成任务，但一期可能没有开源文本模型。
6. 所有按钮都叫“开始练习”，用户无法预期会生成图片、视频、音频还是保存文本。
7. 首页和模块页都把除“已完成”和“失败”之外的状态显示为“处理中”。

### 2.2 503 与历史记录问题

当前服务端在找不到可用开源模型或启用工作流时返回 503。会话已经先写入 `queued`，随后模型解析失败又被恢复为 `queued`，错误原因没有落盘。前端把 queued 映射成“处理中”，所以一个根本没有提交上游任务的会话会长期显示“处理中”。

这不是 RunningHub 正常耗时，而是会话状态建模和错误落盘错误。已有测试覆盖正常 dispatch 和幂等，但没有覆盖“模型不可用 → 不创建任务 → 历史显示配置失败”的路径。

截图中的 `reportAllChanges`/`startTime` 报错来自 DevTools 或浏览器扩展注入脚本的可能性较高，与业务 503 分开处理；验收以 `/api/practice/sessions` 的真实响应和 session/task 数据为准。

## 3. 产品目标和边界

### 3.1 目标

- 每个单项练习都明确说明输入、输出和主操作。
- 剧本练习在没有开源文本模型时仍然可用，作为人工写作工具。
- 图片、视频、配音和音乐练习只使用平台后台配置的开源模型/工作流。
- 同一能力存在多个开源模型时，用户可以选择；只有一个时不制造无意义的选择步骤。
- 生成前能知道将产生什么结果，生成后直接展示对应媒体。
- 练习失败、模型未配置、任务排队和真实生成中必须显示不同状态。
- 复用现有任务、worker、轮询/恢复、媒体落盘和结果组件，不创建第二套生成系统。

### 3.2 不在本次范围

- 不把短剧实验室接入无限练习。
- 不允许无限练习调用正式生产模型或正式生产渠道。
- 不在用户端显示 RunningHub、provider、Workflow ID、节点 ID、请求模板或内部提示词。
- 不在本期实现完整动态表单编辑器；首期由平台固定模块表单，并读取后台允许的模型选项及必要参数。
- 不新增“待测试”状态；工作流测试信息仍属于后台配置元数据。

## 4. 单项练习信息架构

所有模块共用页面外壳：返回入口、模块标题、模块说明、当前练习、历史练习。但中间的工具面板和结果面板必须按模块独立实现。

### 4.1 剧本练习：人工写作模式

定位：练习剧本结构和文字表达，不依赖开源模型。

界面：

- 剧本标题。
- 多行剧本编辑器。
- 可选的场景/人物备注，第一期不强制结构化。
- 主按钮为“保存剧本”或“保存草稿”，不叫“开始练习”。
- 保存后在当前区域继续编辑，并在历史记录显示文本摘要。

数据：

- 使用 `practice_sessions` 的 `mode: "manual"`，不创建 text generation task。
- session 状态为 `draft` 或 `success`，内容保存在受控的公开练习正文中。
- 不读取 `practiceDefaultModels`，不会因为没有文本模型返回 503。

### 4.2 分镜图练习：文字生成图片

定位：练习分镜画面描述、构图、景别和视觉重点。

界面：

- 必填“画面描述”文本框。
- 可选参考图片/已有资产/IP 内容选择器，不再要求用户手写素材 ID。
- 模型选择：后台配置多个开源图片模型时显示下拉；只有一个时显示当前模型名并锁定；没有可用模型时显示“当前练习尚未配置”，禁用生成。
- 主按钮为“生成分镜图”。
- 结果区固定为图片结果容器，生成前显示“等待生成分镜图”的可见占位，生成后显示真实图片，失败时显示错误和重试。

提交字段只包含 `module`、用户描述、公开引用、用户选择的练习逻辑模型 ID 和 request ID；服务端仍重新校验模型属于 `open-source-practice/shared`。

### 4.3 分镜视频练习：图片 + 提示词生成视频

定位：练习从静态分镜图推进到动态镜头。

界面：

- 必选开源视频模型。
- 必选一张参考图片，支持上传或从已有资产选择，显示真实缩略图。
- 必填视频提示词。
- 时长、比例、清晰度等仅当当前工作流的参数契约声明支持时显示。
- 主按钮为“生成分镜视频”。
- 结果区固定为视频播放器，生成前显示视频任务占位，生成后显示真实视频，失败时显示错误和重试。

不能只传一段 prompt 让后端猜图片，也不能把同一张图片同时作为多个角色引用。缺少参考图片时在创建任务前阻止提交。

### 4.4 配音练习：文本生成音频

定位：练习对白、旁白和人物声音表现。

界面：

- 必填配音文本。
- 开源配音模型选择；多个时可选，单个时只读显示。
- 如果工作流的输入契约提供音色、角色、语速或情绪选项，则显示对应控件；没有声明则不凭空增加。
- 主按钮为“开始配音”。
- 结果区为音频播放器和文本摘要。

### 4.5 音乐练习：需求生成音频

定位：练习场景情绪、音乐风格和配乐需求表达。

界面：

- 必填音乐需求/场景情绪。
- 开源音乐模型选择；多个时可选，单个时只读显示。
- 时长、风格、格式等仅在工作流契约支持时显示。
- 主按钮为“生成音乐”。
- 结果区为音频播放器、时长和失败重试。

## 5. 开源模型选择规则

### 5.1 用户可见范围

用户只能看到平台管理员在后台绑定到无限练习的开源逻辑模型显示名，例如“分镜图模型 A”“分镜视频模型 B”。不得看到：

- RunningHub 名称或 API URL。
- system channel ID。
- Workflow ID。
- 节点 ID、请求模板和内部版本细节。

### 5.2 选择策略

| 模块 | 是否需要开源模型 | 多个开源模型时 | 只有一个时 | 没有时 |
| --- | --- | --- | --- | --- |
| 剧本 | 否 | 不显示 | 不显示 | 仍可人工写作 |
| 分镜图 | 是 | 用户选择 | 默认/只读 | 禁止提交，显示未配置 |
| 分镜视频 | 是 | 用户选择 | 默认/只读 | 禁止提交，显示未配置 |
| 配音 | 是 | 用户选择 | 默认/只读 | 禁止提交，显示未配置 |
| 音乐 | 是 | 用户选择 | 默认/只读 | 禁止提交，显示未配置 |

模型选项由服务端根据 `practiceWorkflowModels` 和当前启用工作流生成，不由浏览器读取整个渠道配置。用户本轮选择的逻辑模型只用于本次练习；服务端保存实际 workflow key/version/Workflow ID 供追溯。

## 6. 能力预检与后端会话状态

### 6.1 能力预检

增加或扩展练习能力读取接口：

```text
GET /api/practice/modules
```

每个模块返回：

```json
{
  "module": "storyboard-video",
  "mode": "workflow",
  "available": true,
  "models": [{ "id": "practice-video-a", "label": "分镜视频模型 A" }],
  "inputSchema": [
    { "key": "prompt", "type": "textarea", "required": true },
    { "key": "referenceImage", "type": "image", "required": true }
  ]
}
```

不返回 API Key、请求模板、Workflow ID、节点映射或完整渠道 JSON。模块页先读取能力，再渲染提交控件；服务端 POST 仍必须再次校验。

### 6.2 会话模式和错误

`PracticeSessionRecord` 增加：

```text
mode: manual | workflow
errorCode?: string
errorMessage?: string
selectedLogicalModelId?: string
```

约束：

- `mode=manual` 只用于剧本人工写作，不产生 generation task。
- `mode=workflow` 在提交前完成能力和模型预检。
- 没有可用工作流时不创建 session。
- 已创建 session 后，只有真实 task 已提交才允许进入 running。
- 模型解析、参数校验或媒体准备失败时，session 写入 `failed + errorCode/errorMessage`，不能回到无错误的 queued。
- 上游已经提交但 taskRef 写回失败时，保留现有 needs-review/用户检查状态，不能重新创建任务或重复扣费。

## 7. 历史练习和结果刷新

### 7.1 状态显示

统一使用显式状态映射：

```text
draft       草稿
queued      排队中
running     生成中
success     已完成
failed      失败
cancelled   已取消
```

“处理中”不再作为兜底文案。只有 queued/running 且存在真实任务或明确调度状态时，才允许显示生成中状态。

对于旧数据中 `queued` 且没有 `taskRefs` 的记录：

- 服务端读取时识别为 `PRACTICE_DISPATCH_NOT_STARTED`。
- 返回“配置失败/未开始”，同时提供一次性数据修复或在下一次写入时落盘为 failed。
- 不删除用户输入，允许在模型配置完成后点击重试。

### 7.2 历史卡片

- 图片模块显示图片缩略图。
- 视频模块显示视频封面/视频标识。
- 配音和音乐显示音频图标、时长和文本摘要。
- 剧本显示文本摘要和草稿/已保存状态。
- 失败卡片显示简短错误原因和“重试”。
- 首页点击历史记录时携带 `sessionId`，模块页打开对应 session，而不是只打开空表单。

### 7.3 状态刷新

第一期不新建固定次数的轮询协议。提交后结果区立即显示模块对应的生成占位；模块页打开、切换历史记录、重新获得焦点和用户点击“刷新状态”时读取 session detail API，服务端从现有 generation task 获取真实状态。未来如果统一任务变更信号稳定，再增加事件驱动通知，不改变前端 session/result 合约。

## 8. 与现有模块和短剧实验室的关系

### 8.1 Canvas/无限短剧项目

无限练习 Canvas/短剧项目继续使用现有项目身份和组件。项目内部的脚本、分镜图、分镜视频、配音和音乐动作，可以分别调用对应单项练习业务 code；不把项目整体当成一个“短剧实验室工作流”。

### 8.2 短剧实验室

短剧实验室是当前短剧生产模块的替换项目，单独使用正式生产配置、正式权限和正式计费策略。本次单项练习改造不得修改 `drama-lab` 页面、生产路由、生产默认模型或生产任务来源。未来若短剧实验室需要 RunningHub，另行设计生产 workflow binding。

## 9. 验收条件

- 剧本练习在没有任何开源文本模型时仍可新建、编辑、保存和查看历史。
- 分镜图练习可以输入文字并得到图片结果，页面始终有图片结果区域。
- 分镜视频练习必须选择开源模型、参考图片和提示词后才能提交，并得到视频结果。
- 配音练习可以输入文本并得到音频结果；音乐练习可以输入音乐需求并得到音频结果。
- 多个开源模型时用户可以选择，只有一个时不显示无意义的多选步骤。
- 用户端不出现 RunningHub、Workflow ID、节点映射或 API Key。
- 未配置开源模型时不创建新的 queued session，页面显示清晰的未配置状态。
- 旧的 queued 且无 taskRef 历史记录不再显示为“处理中”。
- 任务真实 pending/running、success、failed、cancelled 在历史和当前结果区准确显示。
- 生成结果继续使用现有图片、视频、音频和文本结果组件。
- 正式 Canvas、正式短剧、短剧实验室、积分和学校算力池逻辑不受影响。
