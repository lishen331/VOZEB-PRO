# 学校课程章节、课时与课程资料设计

## 1. 背景

平台课程已经支持课程基本信息、章节/课时和课程附件，但当前章节与附件都保存在课程级 JSON 中，学校补充资料又保存在班级课程安排的 `supplementalResources` 中。资料没有稳定的章节或课时归属，平台课程也无法在学生端按课程树展示。

学校课程需要形成一条清晰链路：

```text
平台制作标准课程 -> 发布 -> 分配学校 -> 学校补充资料 -> 班级教学 -> 学生学习
```

本期学校补充资料按学校课程共享。同一学校内所有使用该课程的班级都可以看到学校补充资料，班级差异由老师的教学任务和作业控制。

## 2. 目标

- 建立独立的课程、章节、课时和课程资料数据结构。
- 平台管理员可以制作标准课程，并把资料精确绑定到章节或课时。
- 已分配课程的学校可以在对应章节或课时下补充本校资料。
- 学校补充资料对本校所有使用该课程的班级可见。
- 学生可以按“课程 -> 章节 -> 课时”查看平台资料和本校资料。
- 继续复用现有文件上传、对象存储、本地媒体登记和鉴权下载能力。
- 课程资料与作业、课堂安排和商单实训任务保持独立，但教学任务可以关联具体章节或课时。
- 平台管理员可以对课程执行停用（软删除）或永久删除。

## 3. 非目标

第一期不建设以下能力：

- 班级级课程资料可见性。学校资料统一按学校课程分配共享。
- 学校修改平台标准课程内容。
- 版权方或老师提交课程供平台审核。
- 课程在线 Office 编辑或 ZIP 自动解压。
- 独立的课程版本发布系统。
- 把课程资料改造成作业提交记录。

## 4. 核心概念

### 4.1 平台标准课程

平台标准课程由平台管理员创建和维护，包含课程基本信息、章节、课时和平台资料。课程发布后才能分配给学校。平台资料为只读内容，学校不能编辑或删除。

### 4.2 章节与课时

课程固定采用两级内容树：

```text
课程
└─ 章节
   ├─ 章节资料
   └─ 课时
      └─ 课时资料
```

章节用于组织教学单元，也可以直接挂共用资料；课时是学生实际学习的最小教学单元，也可以挂资料。章节和课时都有稳定 ID，资料和教学任务不使用标题或数组下标作为引用。

### 4.3 课程资料

课程资料是课程内容的一部分，不是作业资源。平台资料和学校补充资料使用同一资料模型，通过来源和归属字段区分。

首期支持 Word、PPT、Excel、图片、视频和 ZIP。浏览器可以处理的图片和视频支持预览；Office 文件和 ZIP 展示文件信息并提供下载，不承诺在线编辑或预览。

### 4.4 学校补充资料

学校补充资料绑定到 `school_course_assignment`，再绑定到该学校课程下的章节或课时。它对该学校所有使用这门课程的班级可见，不属于某一个班级课程安排。

学校管理员和负责该课程的老师可以上传、编辑和删除本校补充资料；学生和其他学校成员只能查看、预览和下载。学校补充资料不会覆盖或修改平台资料。

## 5. 数据结构

### 5.1 课程表

保留 `platform_courses` 存储课程基本信息，移除课程级 `chapters` 和 `attachments` 字段。课程保留 `content` 作为课程介绍或正文扩展字段。

停用（软删除）使用现有课程状态 `disabled`，并记录删除元数据：

- `deleted_at`：停用（软删除）时间，未停用为空。
- `deleted_by_user_id`：执行停用（软删除）的管理员。

课程状态只保留草稿、已发布和停用。页面上的“停用”就是可恢复的软删除，不再单独提供“软删除”按钮或独立状态。

### 5.2 章节表 `platform_course_chapters`

主要字段：

- `id`
- `course_id`
- `title`
- `description`
- `sort_order`
- `created_at`
- `updated_at`

同一课程内按 `sort_order`、`id` 稳定排序。章节只能属于一个平台课程。

### 5.3 课时表 `platform_course_lessons`

主要字段：

- `id`
- `course_id`
- `chapter_id`
- `title`
- `description`
- `sort_order`
- `created_at`
- `updated_at`

课时同时保存 `course_id` 和 `chapter_id`，服务端和数据库外键都校验两者属于同一课程，避免跨课程引用。

### 5.4 课程资料表 `course_materials`

主要字段：

- `id`
- `course_id`
- `chapter_id`，章节资料时填写
- `lesson_id`，课时资料时填写
- `source_scope`：`platform` 或 `school`
- `school_course_assignment_id`，学校资料时填写，平台资料为空
- `title`
- `file_name`
- `mime_type`
- `bytes`
- `storage_key`
- `download_url` 或现有受保护媒体引用
- `sort_order`
- `status`
- `created_by_user_id`
- `created_at`
- `updated_at`

每条资料必须且只能绑定一个章节或课时。平台资料必须属于平台课程；学校资料必须同时属于对应学校课程分配，且分配的课程与资料的 `course_id` 一致。该约束在 service 层校验，并在数据库通过外键和检查约束保证。

现有课程附件上传接口可以复用上传和存储链路，但返回结果改为创建或更新 `course_materials` 的输入，不再把文件追加到课程根级 `attachments` 数组。学校上传同样复用同一文件类型识别、存储和鉴权下载能力。

### 5.5 课程分配与课程安排

现有 `school_course_assignments` 继续表示平台课程分配给学校，`school_course_offerings` 继续表示学校把课程安排给班级和老师。

学校补充资料挂在 `school_course_assignments`，不挂在 `school_course_offerings`。因此同一学校的多个班级会看到相同的学校资料。

`school_course_offerings.supplemental_resources` 不再作为课程资料存储。新结构直接使用 `course_materials`，实现时移除该字段及其相关读写逻辑。

### 5.6 教学任务关联

现有 `teaching_assignments` 继续保存课堂安排、作业和商单实训任务。增加可选的章节或课时引用：

- `chapter_id` 可选
- `lesson_id` 可选

任务可以不绑定具体节点，表示整个课程安排级任务；绑定时必须校验节点属于该课程。首期学生可以从对应课时进入已发布任务，但不改变现有提交和批改流程。

## 6. 平台后台流程

### 6.1 创建和编辑

平台管理员在课程管理页：

1. 创建课程基本信息。
2. 在课程树中创建章节。
3. 在章节下创建课时。
4. 选中章节或课时，上传一项或多项平台资料。
5. 保存草稿并检查资料数量。
6. 发布课程。
7. 将已发布课程分配给学校。

课程列表显示课程、章节数、课时数、资料数、状态、更新时间和操作。课程编辑页左侧显示树形目录，右侧显示当前节点资料；平台资料可编辑标题、排序和替换文件，但不能由学校端修改。

### 6.2 删除操作

列表操作调整为：

```text
编辑
发布 / 停用 / 恢复
更多
└─ 永久删除
```

停用（软删除）：

- 课程从普通平台列表、学校课程列表和学生学习中心隐藏。
- 学校不能创建新的课程安排或教学任务。
- 课程、章节、课时、资料、学校分配、教学任务和学生提交全部保留。
- 平台管理员可以在“已停用课程”中查看并恢复。
- 不删除实际文件。

永久删除（技术实现为数据库和文件的物理清理）：

- 允许删除草稿、已发布、已分配和已有教学记录的课程。
- 级联删除课程、章节、课时、平台资料、学校补充资料、学校课程分配、班级课程安排、教学任务和学生提交。
- 删除课程专属文件；如果文件被其他业务共同引用，只删除课程资料引用，不删除公共文件。
- 数据库删除在一个事务中完成，文件清理在事务提交后执行。

永久删除必须使用危险操作弹窗：展示将删除的课程、章节、课时、资料、学校、班级安排、教学任务和提交数量，并要求管理员输入完整课程名称后确认。永久删除完成后课程不可恢复。

## 7. 学校后台流程

学校管理员在课程安排页选择平台分配的课程，为课程安排班级和负责老师。进入课程详情后看到完整课程树：

```text
第一章
├─ 平台资料
├─ 课时 1
│  ├─ 平台资料
│  └─ 本校补充资料
└─ 课时 2
```

学校管理员和负责老师可以在章节或课时下添加本校补充资料。资料列表明确显示来源标签“平台资料”或“本校资料”。平台资料为只读；本校资料可编辑、删除和重新排序。

学校补充资料的上传、删除和下载都必须检查当前用户的学校上下文、课程分配关系和资料来源，禁止跨校访问。

## 8. 学生端学习流程

学生通过所属班级进入学习中心，服务端只返回：

- 学生所在学校已分配的课程。
- 学生所在班级正在使用的课程安排。
- 该课程的章节和课时树。
- 平台资料和本校补充资料。
- 已发布或已关闭的教学任务。

页面按课程树展示资料。图片和视频可在资料卡片中预览；Word、PPT、Excel 和 ZIP 显示类型、文件名、大小和下载按钮。资料下载继续经过受保护的媒体路由，不能把存储地址直接暴露为公开文件地址。

学生不能看到未分配给本校的课程，也不能看到其他学校的补充资料。课程停用（软删除）后，学生端不再展示该课程；永久删除后相关记录和专属文件均不存在。

## 9. 接口边界

所有接口继续使用 `{ code, data, msg }` 响应结构，Route Handler 只负责入参、鉴权、调用 service 和响应映射。

平台端建议提供：

- `GET /api/admin/courses/:id/tree`
- `POST /api/admin/courses/:id/chapters`
- `PATCH /api/admin/course-chapters/:id`
- `POST /api/admin/course-chapters/:id/lessons`
- `PATCH /api/admin/course-lessons/:id`
- `POST /api/admin/courses/:id/materials`
- `PATCH /api/admin/course-materials/:id`
- `DELETE /api/admin/course-materials/:id`
- `PATCH /api/admin/courses/:id`，将 `status` 设置为 `disabled` 即停用（软删除）
- `POST /api/admin/courses/:id/restore`
- `DELETE /api/admin/courses/:id`

学校端建议提供：

- `GET /api/school/courses/:assignmentId/tree`
- `POST /api/school/courses/:assignmentId/materials`
- `PATCH /api/school/course-materials/:id`
- `DELETE /api/school/course-materials/:id`

教学端在现有课程和任务接口上增加章节、课时和资料树字段；学生端和老师端使用同一套可见性服务，区别仅在于老师可以管理本校资料和教学任务。

接口索引和开发地图需要在实现接口、页面、service、repository、schema 或 worker 发生变化的同一提交中同步更新。

## 10. 权限与数据隔离

### 平台管理员

- 创建、编辑、发布、停用（软删除）、恢复和永久删除平台课程。
- 管理平台章节、课时和平台资料。
- 查看所有学校课程分配和删除影响范围。

### 学校管理员

- 查看平台分配给本校的课程。
- 安排班级和负责老师。
- 管理本校课程补充资料。

### 负责老师

- 查看负责班级的课程。
- 管理本校课程补充资料。
- 创建和管理教学任务。

### 学生

- 查看所属班级可见课程。
- 查看、预览和下载平台资料及本校资料。
- 使用现有作业提交流程。

所有 PostgreSQL 查询必须带课程、学校、成员、班级或课程分配条件，禁止先读取完整课程或资料表再在 Node.js 过滤。

## 11. 错误处理

- 课程未发布时不能分配给学校。
- 章节或课时不属于目标课程时返回 404 或 400，不创建资料。
- 学校资料必须属于当前学校的有效课程分配。
- 已停用课程不能新增章节、课时、资料、课程安排或教学任务。
- 平台资料不能由学校端编辑或删除。
- 不支持的扩展名、空文件、存储失败沿用现有课程附件上传错误契约，课程资料记录不落盘。
- 永久删除数据库事务失败时不清理文件；数据库成功但文件清理失败时保留待清理记录并报告失败，不把未清理文件伪装成已完成。
- 课程永久删除后的旧资料 URL 必须返回不存在或无权访问，不得继续下载。

## 12. 测试与验收

### 服务与持久层

- 课程树可以创建、排序、读取和更新。
- 资料只能绑定一个章节或课时，不能跨课程或跨学校。
- 平台资料和本校资料的可见范围正确。
- 学校资料对本校多个班级均可见。
- 停用（软删除）隐藏课程但保留全部数据，恢复后可以继续读取。
- 永久删除级联清理全部课程业务记录，并只清理不再被引用的文件。
- 已发布、已分配、有教学任务和学生提交的课程也可以永久删除。
- PostgreSQL 集成测试使用定向查询；共享测试库文件级并行关闭，避免锁冲突。

### API 与权限

- 平台管理员可以创建和删除课程，普通用户不能调用平台管理接口。
- 学校管理员和负责老师只能操作本校、本课程分配下的资料。
- 学生不能上传、编辑或删除资料，不能跨学校读取资料。
- 停用、恢复和永久删除接口均验证管理员 Session；永久删除额外要求课程名称确认字段。
- 所有响应符合 `{ code, data, msg }`。

### 浏览器验收

- 后台课程树可以创建章节、课时并在节点下上传 Word、PPT、Excel、图片、视频和 ZIP。
- 学校端可以在章节或课时下上传本校资料，其他班级能看到同一资料。
- 学生端按课程、章节、课时展示资料，图片和视频可预览，Office 文件和 ZIP 可下载。
- 课程资料、作业和商单实训任务的入口和状态互不混淆。
- 课程列表中的停用、恢复和永久删除操作符合确认流程。
- 桌面端、390px 和 430px 宽度下课程树、资料列表、上传弹窗和删除确认无横向溢出。

## 13. 后续扩展

以下能力不纳入本期，但数据结构预留扩展空间：

- 课程版本和学校锁定版本。
- 班级级补充资料。
- 资料预览转换服务。
- 资料使用统计和下载统计。
- 课程完成度和章节学习进度。
