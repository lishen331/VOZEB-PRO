# 调用记录补上练习运维信息

日期：2026-11-05
范围：只读展示。改后台「调用记录」的列表与详情，不改任务、不改路由、不改采集。
只推 `develop`，先上测试服。生产等明确批准。

## 背景

`2026-11-02-practice-canvas-test-permission.zh-CN.md` 第四节第 5 条把「后台调用日志增强」写成另案。现在这个案子做展示层。

测试服已核实：每次生成任务在 `vozeb_pro_generation_tasks.diagnostic_events` 里存完整时间线（建任务、随机选中的模型与渠道、每次上游请求的状态码与耗时、上游错误原文、故障转移）。近 7 天 28 条调用记录全部带 `task_id`，能一对一连到任务表。后台没有任何页面读这些字段，所以运维看不到。

## 改什么

1. 调用记录列表加两列。
   - 执行环境：任务的 `execution_profile`，显示「练习」或「生产」。
   - 渠道：任务的 `channel_id` 对应的渠道名。
   - 筛选区加「练习 / 生产」下拉。
   - 数据按 `task_id` 从任务表关联，不改 `generation_logs` 表。

2. 调用记录详情加「调用链路」。
   - 展示该任务的 `diagnostic_events`：每个候选的模型、渠道、上游状态码、耗时、错误原文，以及故障转移记录。
   - 上游错误原文只在这里显示。前台用户仍只看到「网络异常，请点击重试」。

3. 没有关联任务的记录（旧数据或非任务入口）两列显示「-」，详情不显示链路。

## 不改什么

- 不改 `generation_logs` 表结构，不加列、不回填。
- 不改任务采集、不改 `diagnostic_events` 的写入与保留策略。
- 不改练习路由、随机选择、故障转移。
- 不向前台接口或前台页面暴露渠道名与上游错误。
- 不动生产环境。

## 验证

1. 单测：列表接口按 `task_id` 关联出执行环境与渠道名；筛选「练习」只返回练习记录。
2. 单测：详情接口返回该任务的诊断事件，并去掉凭据与媒体内容（沿用现有脱敏）。
3. 测试服：调用记录能按「练习」筛选，失败记录的详情能看到上游状态码与错误原文。
