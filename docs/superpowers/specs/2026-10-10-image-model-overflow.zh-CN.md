# 图片模型满载时随机切换到其它启用模型（开发文档）

日期：2026-10-10　状态：待确认，确认后再改代码

## 需求

1. 用户选了模型 A。A 的渠道没满就用 A，绝大多数请求都是这样。
2. A 满了（同时在跑达到上限，或这一秒的发送名额用完），立刻随机换到前端下拉里另一个启用的图片模型，不等待、不排队。
3. 换到的也满了，继续随机换下一个，已经试过的不重复。
4. 换到的模型不支持这次的参考图、比例或分辨率，跳过，继续换。
5. 全部都试过还不行，才报错退款。
6. 计费按用户选的 A 算；偶尔出的图和 A 不完全一样，可以接受。
7. 满不满按"渠道 + 模型"算（不改成整个渠道共用名额）。

## 现状

- 候选只来自 A 自己绑定的渠道。A 只绑了一个渠道时，满了没得换，等 2 秒后报"当前模型暂时不可用"。
- `web/src/lib/server/logical-model-router.ts` 和它的测试已经有**未提交**的改动（没有先写本文档），按下面方案调整，或者先撤回。

## 方案

1. 候选列表（`logical-model-router.ts`）：先放 A 自己的渠道（按原优先级），后面接其它启用图片模型的渠道。后面这部分**每个请求单独随机打乱**。停用的模型、冷却中的渠道不放进来。
2. 下发（`image-task-runtime.ts`，逻辑不变）：按顺序逐个尝试，先占同时在跑名额，再取这一秒的发送名额；任一项不满足就马上试下一个。全部不满足才每 200 毫秒重试一轮，最多 2 秒。
3. 能力检查（`app/api/image-tasks/route.ts`）：
   - A 自己的渠道没有一个支持本次参数 → 直接报错，不借别的模型。
   - 借来的模型不支持本次参数 → 从候选里去掉。
4. 计费：借来的候选仍记为 A。
5. 不变：504、超时这类结果不确定的失败不切换（避免同一张图在两个上游各扣一次费）。

## 报错（只有 5 种）

| 情况 | 提示 |
| --- | --- |
| 所有模型都满 | 当前模型暂时不可用，请切换模型后重试 |
| A 不支持本次参考图 / 比例 / 分辨率 | 当前模型暂时不可用，请切换模型后重试（替换现在的"当前模型能力不满足参考素材、比例或分辨率参数"） |
| 内容安全 | 内容未通过安全审核，请修改描述或更换参考图后重试 |
| 积分不足 | 积分不足，请充值后重试 |
| 真人人脸 | 参考图包含真人人脸，请更换图片后重试 |
| 其它 | 网络异常，请点击重试 |

## 测试

- 单测：A 有空位只用 A；A 满切到其它模型；切到的也满继续切；借来的不支持参数被跳过；A 自己不支持参数直接报错；全满等 2 秒后报错；计费模型是 A；多次请求随机顺序不同。
