# 短剧实验室专属画布: 按一级隔离复制与受控同步

**状态:** 已确认并实现（2026-08-25）。

**日期:** 2026-08-25

## 1. 本轮新增结论

### 1.1 画布粒度改为“一级一个”

本文将短剧实验室中的“一级”定义为项目下的一级剧集/工作单元。第一阶段采用：

```text
一个用户 + 一个短剧项目 + 一个一级剧集 = 一个专属画布
```

同一短剧项目的不同一级剧集拥有不同的 CanvasProject、不同的画布布局、视口、自由节点和画布会话。角色、场景、道具等项目级资产可以投影到多个一级画布，但每个画布中的节点位置和画布创作内容相互隔离。

### 1.2 采用截图中的“复制画布 + 受控同步”方案

不再把短剧实验室和普通 Canvas 强行放进同一套正在演进的页面实现中。普通 `/canvas` 保持作者的原始实现和独立运行；短剧实验室维护一份隔离的 Canvas 页面/运行时副本。

副本不是永久手工分叉，而是有明确来源版本的受控镜像：

1. 先合并作者的更新到普通 Canvas。
2. 在普通 Canvas 上完成测试和验收。
3. 记录已验证的 Canvas 源版本。
4. 用同步脚本把作者 Canvas 的上游代码更新到短剧复制版。
5. 只重新应用短剧适配层，不把短剧业务代码反向写回普通 Canvas。

这样可以让短剧实验室的改动隔离，避免短剧逻辑影响原画布；同时作者的新 Canvas 能力经过验证后可以进入短剧画布。

## 2. L 的真实业务逻辑

LocalMiniDrama 的入口是：

- `/film/:dramaId`
- `/film/:dramaId/canvas?episode=:episodeId`

L 的用户体验是按剧集筛选和定位的：进入时带 `episode`，返回时保留 `episode`，双击分镜时带 `#sb-<storyboardId>` 回到对应位置。

但需要区分用户体验和底层存储：L 当前画布布局读取整部短剧的 `metadata.canvas_layout`，工作流组也存整部短剧的 `metadata.workflow_groups`，因此它底层更接近“一部短剧一个布局容器 + 剧集筛选”，不是真正的一剧集一个独立 CanvasProject。

本项目按用户确认的目标，在 V 中将其升级为“一级一个专属 CanvasProject”，同时保留 L 的进入、筛选、返回和定位逻辑。

### 2.1 L 的资产投影与真实 ID

L 不是靠名称猜测关系，而是把业务实体投影成固定类型的节点区块：

| 业务对象 | L 节点 ID 示例 | 真实关系来源 |
| --- | --- | --- |
| 角色 | `char:<characterId>` | 分镜 `characters` |
| 场景 | `scene:<sceneId>` | 分镜 `scene_id` |
| 道具 | `prop:<propId>` | 分镜 `prop_ids` |
| 剧本 | `script:<episodeId>` | 剧集 ID |
| 剧集 | `episode:<episodeId>` | 剧集 ID |
| 分镜 | `sb:<storyboardId>` | 分镜 ID |
| 分镜文字/图片/视频/音频 | `sbtxt:*`、`sbimg:*`、`sbvid:*`、`sbaud:*` | 同一分镜 ID |

角色、场景、道具到分镜的连线来自真实字段。L 还有另一种工作流分组，保存选中的分镜 ID 和批量执行管线；这与资产投影区块不是同一概念。

## 3. 为什么选择隔离复制，而不是共享重构

### 3.1 当前不采用的方案

1. 复制页面后长期手工维护、完全不记录来源版本。这样会产生不可控的代码分叉。
2. 现在就把普通 Canvas 全量重构成大型共享内核。作者仍会持续改 Canvas，这会扩大后续合并冲突。
3. 把短剧布局、自由节点和生成结果塞入 `DramaProject`。Canvas 的高频 mutation 保存会和短剧整项目保存产生覆盖、竞态和体积问题。

### 3.2 采用的方案

普通 Canvas 是“上游验证区”，短剧 Canvas 是“隔离运行区”。两者使用同一套上游来源版本，但物理代码目录和运行入口分开：

```text
上游作者代码
    -> 普通 /canvas 更新与验证
    -> 记录 CANVAS_RUNTIME_SOURCE_COMMIT
    -> 同步到短剧 Canvas 副本
    -> 应用独立的短剧适配层
    -> /drama-lab/:projectId/canvas?episodeId=:episodeId
```

约束如下：

- 普通 `/canvas` 不导入短剧项目、资产、权限或回写逻辑。
- 短剧 Canvas 的复制目录不直接修改普通 Canvas 文件。
- 复制目录中的上游文件禁止临时手改；短剧差异放在独立适配目录、配置和补丁文件中。
- 同步脚本只覆盖上游镜像文件，保留短剧适配文件和测试。
- 每次同步都记录源 commit、同步时间、同步结果和需要人工处理的差异。

这不是“两个版本永远各自发展”，而是“上游先验证，短剧再受控吸收”。

## 4. 一级画布绑定与路由

### 4.1 绑定键

第一阶段每个一级剧集懒创建一个 CanvasProject。绑定键必须同时包含项目和剧集：

```text
drama-lab-canvas:<dramaProjectId>:episode:<episodeId>
```

服务端先校验用户拥有该短剧项目和剧集，再解析或创建绑定画布。不能只用短剧项目 ID，否则会把多个一级剧集错误地放到同一个画布。

首选继续复用现有 CanvasProject 的幂等 `sourceHandoffId` 机制，以减少数据库和上游 Canvas 代码改动。若未来该字段语义不适合承载绑定，再迁移为专用绑定表；路由和节点 ID 不变。

### 4.2 路由约定

进入一级剧集画布：

```text
/drama-lab/:dramaProjectId/canvas?episodeId=:episodeId&shotId=:shotId
```

`episodeId` 是必需的；`shotId` 用于进入后定位当前分镜。返回短剧工作台：

```text
/drama-lab/:dramaProjectId?episodeId=:episodeId&stage=storyboard#shot-:shotId
```

刷新、浏览器前进后退、从普通 Canvas 列表重新打开绑定画布，都必须保留项目、剧集和分镜上下文。

## 5. 一级画布中的业务投影

每个一级画布只投影：

- 当前一级剧集的剧本、剧集节点、分镜、分镜文字和分镜媒体。
- 当前项目的角色、场景、道具主参考图，作为该剧集分镜的可引用资产。
- 当前剧集的真实角色/场景/道具关联边。
- 当前剧集的批量工作流分组。

项目级资产可以出现在多个一级画布中，但它们只是同一真实资产的投影，不是复制出多个业务资产。

V 画布当前没有 L 的专用节点类型，因此复制版使用 V 已有文本、图片、视频、音频和连线节点组成清晰区块：

```text
剧本 / 剧集
  -> 分镜 1 -> 分镜文字 -> 首帧/关键帧/尾帧 -> 视频/音频
角色、场景、道具
  -> 连接至当前剧集使用它们的分镜
```

节点使用包含项目和剧集的稳定 ID，避免不同一级画布之间冲突：

```text
dl:<dramaProjectId>:episode:<episodeId>:character:<characterId>
dl:<dramaProjectId>:episode:<episodeId>:scene:<sceneId>
dl:<dramaProjectId>:episode:<episodeId>:prop:<propId>
dl:<dramaProjectId>:episode:<episodeId>:script
dl:<dramaProjectId>:episode:<episodeId>:shot:<shotId>
dl:<dramaProjectId>:episode:<episodeId>:shot:<shotId>:frame:first
dl:<dramaProjectId>:episode:<episodeId>:shot:<shotId>:video
```

连线只能根据 `DramaShot.characterIds`、`sceneId`、`propIds` 和真实分镜/媒体 ID 建立，绝不通过名称匹配。

## 6. 数据同步与回写边界

### 6.1 短剧到一级画布

`DramaProject` 仍是剧本、资产、分镜、短剧生成状态的唯一真源。

- 首次进入一级画布时投影系统节点和业务关系。
- 短剧内容变化后提供“同步当前剧集”动作。
- 同步只更新当前剧集相关系统节点，保留自由节点、自由媒体、会话、用户连线和用户布局。
- 资产新增或分镜新增时使用真实 ID 增量添加节点。
- 同步失败必须明确提示，不能静默覆盖旧数据。

### 6.2 一级画布到短剧

画布自由生成结果默认保存在当前一级 CanvasProject，不自动覆盖短剧业务数据。

只有用户明确执行以下动作时才回写：

- 将图片保存为角色、场景或道具主参考图。
- 将图片应用为指定分镜的首帧、关键帧或尾帧。
- 将视频应用为指定分镜的视频结果。
- 将文本或提示词应用到指定分镜字段。

回写请求必须携带项目 ID、剧集 ID、分镜 ID、资产 ID 和目标字段，并做版本校验；不能按显示名称推断，也不能自动创建幽灵资产。

## 7. 复制版必须保留的 V Canvas 能力

短剧 Canvas 副本以作者 Canvas 的已验证版本为基础，不能做功能阉割。必须保留：

- 无限画布、缩放、小地图、主题、自动布局、选择、多选、复制粘贴、撤销重做。
- 文本、图片、全景、视频、音频、配置、Brief、Task、Brand Kit 节点及连线引用。
- 文生文、生图、生视频、生音频、模型配置、比例/质量/时长、参考图、首尾帧和镜头控制。
- 任务恢复、重试、停止、审核、日志和计费链路。
- 上传、素材库、提示词库、IP 引用、下载、导入导出。
- 裁剪、蒙版编辑、智能分层、去背景、表情编辑、超分、多角度和反推提示词。
- Agent、多会话、节点引用、任务规划和节点/连线产出。

短剧适配只负责一级剧集上下文、真实 ID 投影、返回定位和明确回写，不替换通用 Canvas 能力。

## 8. 上游更新与同步流程

每次作者更新 Canvas 时执行：

1. 从 upstream 拉取并合并到普通 Canvas 区域。
2. 只在普通 Canvas 上做上游回归和功能验证。
3. 记录通过验证的源 commit，例如 `CANVAS_RUNTIME_SOURCE_COMMIT`。
4. 执行同步脚本，将上游镜像文件更新到短剧 Canvas 副本。
5. 重新运行短剧适配层测试，处理只属于短剧的少量差异。
6. 通过普通 Canvas 和一级短剧 Canvas 的双向烟雾测试后再部署。

同步脚本的规则：

- 上游镜像文件由普通 Canvas 生成，不能在副本中手工改出不可追踪差异。
- 短剧适配器、投影器、绑定服务、回写服务和测试不被覆盖。
- 新增的上游文件自动进入副本；删除文件必须报告并要求人工确认。
- 同步失败时保留上一份可运行副本，不允许半更新状态上线。

因此作者后续更新不会“自动无条件”进入短剧，而是经过普通画布验证后，再以可回滚、可审计的方式同步。这正是隔离方案的安全边界。

## 9. 画布删除和普通 Canvas 边界

普通 `/canvas` 保留，不能因为短剧功能而删除或改成短剧页面。

删除某个一级绑定画布时：

- 只能删除该一级画布的 Canvas 节点、布局、会话和自由创作内容。
- 绝不能删除短剧项目、剧集、角色、场景、道具、分镜或短剧媒体。
- 再次进入该一级剧集时，可以重新创建绑定画布并重新投影当前短剧数据。
- 短剧画布和普通 Canvas 的删除确认文案必须明确区分。

## 10. 首期开发范围

确认后第一轮开发按以下顺序进行：

1. 建立按“项目 + 一级剧集”的稳定绑定和权限校验。
2. 搭建普通 Canvas 到短剧 Canvas 的可重复同步机制，并记录源 commit。
3. 将 L 的资产/剧本/分镜真实 ID 投影到当前一级画布。
4. 接入 V Canvas 的全部现有节点、生成、任务、图片工具、素材库和 Agent 能力。
5. 实现从短剧进入、返回、剧集筛选和分镜精确定位。
6. 实现“同步当前剧集”，不覆盖用户自由内容和布局。
7. 覆盖绑定、投影、同步、返回、删除隔离以及普通 Canvas 不回归测试。

图片/视频/文本结果逐项“应用到短剧资产或分镜”的回写动作，在上述基础稳定后按目标字段接入；首期不做隐式双向回写。

## 11. 验收标准

1. 同一短剧的两个一级剧集进入后得到两个不同的 CanvasProject，互不覆盖布局、自由节点和会话。
2. 进入时能定位当前剧集和分镜，返回后仍回到原剧集和分镜。
3. 角色、场景、道具、剧本、分镜和媒体节点全部可追溯到真实 ID，改名不影响关联。
4. 短剧 Canvas 副本具备已验证版本的 V Canvas 全部通用能力。
5. 普通 `/canvas` 的行为、项目、任务、Agent、日志和计费不受短剧适配影响。
6. 上游 Canvas 更新可以先在普通 Canvas 验证，再通过脚本同步到短剧副本并回归通过。
7. 同步当前剧集不会删除自由节点、自由媒体、会话、用户连线或用户布局。
8. 没有明确“应用到短剧”的操作时，DramaProject 业务数据不改变。
9. 删除一级绑定画布不会删除短剧项目及任何短剧业务数据。

## 12. 已确认决策

以下默认值已于 2026-08-25 确认并作为实现基线：

1. **粒度:** 每个一级剧集一个专属画布，而不是整个短剧项目共用一个画布。
2. **隔离:** 普通 Canvas 与短剧 Canvas 采用复制运行时，短剧代码不反向影响普通 Canvas。
3. **同步:** 作者更新先合并、验证普通 Canvas，再通过脚本同步到短剧复制版；保留源 commit 和回滚能力。
4. **资产:** 角色、场景、道具是项目级真实资产，可投影到多个一级画布，但不复制业务资产。
5. **回写:** 画布结果默认留在当前一级 CanvasProject，只有明确“应用到...”才回写短剧。
6. **普通入口:** `/canvas` 保留，继续作为独立通用创作入口。
