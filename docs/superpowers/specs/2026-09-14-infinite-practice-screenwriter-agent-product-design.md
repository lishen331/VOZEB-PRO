# 无限练习剧本 Agent 产品设计方案

> 日期：2026-09-14
> 状态：方案基线，供后续实现执行
> 范围：仅 VOZEB-PRO「无限练习 → 剧本」模块
> 长期记忆：本期明确不实现

## 1. 产品目标

把“点击多个阶段按钮、等待一次性 JSON”的工具改造成一个面向创作者的持续对话 Agent：

```text
用户新建剧本
→ 右侧与剧本 Agent 对话
→ Agent 理解创意并补齐必要信息
→ 形成创作定位并等待确认
→ 自动生成故事/剧本/审核/分镜
→ 用户只确认关键节点
→ 编辑、恢复、导出最终成果
```

最小闭环为：创意 → 创作定位 → 故事大纲/完整小说体故事 → 改编策划 → 分集剧本 → 监督审核与自动修正 → 文字分镜 → 人物/场景/道具文字提示词。

## 2. 范围边界

### 本期包含

- 短故事和长篇小说两种模式；
- Vlog、TVC、地点种草、产品种草等短片创作规则；
- 项目级主对话、项目 CRUD、历史恢复；
- 统筹 Agent + 专业执行 Agent + 监督 Agent 的内部编排；
- 公开 SSE 进度和可读正文增量；
- 阶段确认、严格顺序、失败项重试；
- 剧本块和分镜行的选区编辑建议；
- 版本、导出、长篇章节 1–5 章生成；
- 后台真实模型、Agent、Skill、Tool 配置。

### 本期明确不包含

- 跨项目、跨会话个人长期记忆或用户画像；
- 图片、视频、音频、配音、音乐、成片生成；
- RunningHub 七个媒体工作流和商业闭源模块；
- 商业积分扣除或生产渠道；
- 多人协作、评论、Loro、Supabase、独立 WebSocket；
- 430px 移动端专项适配。

## 3. 产品原则

### 3.1 对外只有一个 Agent

用户始终看到“剧本 Agent”。内部角色只作为公开阶段标签：

```text
剧本 Agent · 理解创意
剧本 Agent · 整理故事结构
剧本 Agent · 编写剧本
剧本 Agent · 监督审核
剧本 Agent · 拆分镜头
```

不得要求用户理解或选择内部 Agent。

### 3.2 Skill 自动组合

用户只输入自然语言，不选择 Skill。服务端按以下优先级推断：

```text
已确认项目参数 > 本轮明确表达 > 当前文本识别 > 安全默认值
```

自动识别载体、目的、视角、同行关系、时长、题材和风格。Skill 只用于服务端提示与校验，不出现在用户端、公开消息和导出文件。

### 3.3 项目上下文不等于长期记忆

项目内可以保存标题、载体、时长、人物、世界观、确认成果、用户本项目内的修改要求、当前版本和阶段状态。新项目不得读取旧项目这些数据。未来长期记忆必须另立设计，包含授权、查看、修改、删除和用户隔离。

## 4. 用户流程与状态机

### 4.1 新建剧本

按钮和弹窗统一叫“新建剧本”。创建操作必须建立一个项目、一个唯一主 Chat Session 和绑定该 Session 的首次 Run。删除必须二次确认，删除项目时级联清理消息、Run、事件、Artifact、版本和项目成果。重命名不在本期。

表单只保留剧本名、短故事/长篇、初始载体、目标时长和创意输入；不显示 Skill ID、Skill checkbox 或内部模型配置。

### 4.2 首轮理解

Agent 先抽取目标、载体、受众、人物、地点/产品、视角、同行关系、时长、冲突和结尾。缺少不影响方向的信息可以采用默认并说明；会改变作品方向的信息必须追问，一次只问必要问题。公开回复是创作摘要，不是思维链。

示例：

```text
我理解这是一个 3 分钟以内、第一人称、朋友同行的游乐园 Vlog，目标是通过一次具体体验完成地点种草。我会先整理创作定位，再生成完整故事。请确认，或告诉我需要调整的地方。
```

确认后才写入项目参数并进入下一阶段。

### 4.3 阶段顺序

短故事：

```text
创作定位 → 完整短故事 → 改编策划 → 分集剧本 → 剧本审核 → 导演规划 → 文字分镜 → 资产提示词
```

长篇：

```text
创作定位 → 世界观/人物 → 总纲/卷纲/章纲 → 选择 1–5 章正文 → 改编范围/策略 → 分集剧本 → 审核 → 导演规划 → 分镜 → 资产提示词
```

服务端状态机是唯一门禁；前端按钮只是展示。上游修改后下游标记 stale，禁止静默使用旧版本。分集生成、审核、导演规划、分镜可以在节点内部自动执行；用户只确认重要节点。

## 5. 三栏工作台

桌面端保持左目录、中成果、右对话。430px 不验收。

### 左栏

显示当前剧本、阶段树、真实状态和下一步，不显示 Skill。状态包括未开始、生成中、草稿、待确认、已确认、部分完成、失败、待复核。支持新建剧本、项目切换、删除（二次确认）和失败项重试。

### 中栏

显示创作定位、故事正文、标准剧本、审核报告、文字分镜和资产提示词。结构化 JSON 只存服务端；中栏只能显示清洗后的 Markdown/表格/剧本块。解析失败显示明确错误和恢复操作。

### 右栏

显示同一项目的用户消息、Agent 公开回复、当前阶段、公开进度、停止、断线恢复和失败重试。普通对话不能创建媒体任务，也不能跳过状态机。

## 6. Agent 编排

```text
决策层：统筹 Agent
  理解创意、识别参数、追问、决定下一阶段
执行层：策划/小说/编剧/导演/分镜 Agent
  读取已确认成果，生成当前阶段结构化结果
监督层：监督 Agent
  检查结构、格式、连续性、时长、明显问题并自动修正
```

监督 Agent 可自动修正格式、重复、明显错别字、时长和连续性问题；涉及主线、结局、核心人物设定的修改只能列为待用户决定。

模型调用内部携带项目上下文、确认成果、Skill 快照、结构化 schema 和 Tool 约束；公开只发送自然语言、正文片段、阶段进度和质量检查结果。

## 7. 流式协议

公开事件统一为：`run_started`、`agent_started`、`progress`、`assistant_delta`、`artifact_delta`、`item_progress`、`artifact_saved`、`stage_waiting_confirmation`、`run_completed`、`error`、`heartbeat`。

`assistant_delta` 只进入右侧对话；`artifact_delta` 只进入中栏可读成果。禁止把 JSON 片段直接显示为正文。事件使用 `runId + sequence` 去重，刷新/断线从最后序号恢复。创建后先发送公开“已收到/正在理解”状态，不增加无依据的固定延迟、轮询次数或输出上限。

## 8. 创作质量规则

三分钟短片必须满足：总时长不超过目标且不超过 180 秒；开头 3–8 秒有钩子；快速交代人物、地点、目标；中段用行动和互动推进；至少一次具体因果转折；结尾回收情绪、卖点或行动号召；旁白不重复画面；每个镜头服务于剧情、信息或情绪。

Vlog：第一人称体验、自拍/跟拍、口播、自然停顿、同期声和真实反应；地点信息通过可拍摄细节呈现，不凭空编造。

TVC：明确受众、需求/阻力、产品或地点介入、体验改变、品牌记忆点、行动号召和片尾信息；卖点通过动作、对比和结果呈现。

标准格式：场景标题 `INT./EXT. + 地点 + DAY/NIGHT`；动作块；角色名；对白；`(V.O.)`；`SFX/同期声`；独立转场。文字分镜是一条镜头一行，包含画面、景别、角度、构图、运镜、动作、情绪、时长和资产引用。

## 9. 编辑、版本和导出

选中剧本块或分镜行后，用户提出重写、扩写、润色、强化冲突、连续性或格式检查；Agent 返回修改前/修改后建议，不直接覆盖。用户接受后以 `baseVersionId` 创建新版本；版本过期返回冲突。后续再增加拆分/合并镜头、锁定设定和受影响分镜重生成。

导出必须读取已保存成果，不重新调用模型。剧本页面、历史恢复、文本/Fountain/FDX 导出内容一致；分镜页面、Markdown/CSV 导出一致；不包含 Skill、提示词、模型和内部 JSON。

## 10. 权限和计费

所有接口使用当前 Session 和 `open-source-practice` 执行档案，项目/会话/Run/Artifact/版本按学校和用户隔离。调用方不得提交并信任 `schoolId`/`ownerUserId`。剧本 Agent 不写媒体任务表，不扣商业积分。后台模型、Agent、Skill、Tool 配置保存后下一次 Run 立即生效并脱敏返回。

## 11. 验收

固定案例：`我和两个朋友去蓝湖游乐园拍一支三分钟 Vlog，第一人称，要有一次小意外，最后让观众知道值不值得去。`

必须验证自动识别、首轮理解、确认门、完整故事、改编、分集剧本、审核、导演规划、文字分镜、时长、JSON 清洗、SSE 首字节、断线恢复、项目隔离、删除二次确认、剧本/分镜下载和零媒体任务。

错误场景必须覆盖未配置模型、非法结构、断线、重复请求、跳步、版本冲突、删除后访问、权限撤销和跨用户读取。

## 12. 后续顺序

```text
1. Agent 理解/追问 + 项目 CRUD
2. 公开流式输出和断线恢复
3. 三分钟短片质量与格式化
4. 选区编辑、版本和上下游联动
5. 历史/导出一致性及长篇 1–5 章
6. 资源足够后另立长期记忆设计
```
