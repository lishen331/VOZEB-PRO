# VOZEB Current 组件库设计

日期：2026-10-13

## 目标

为 VOZEB PRO 的创作工作台建立一套有自身识别度的前端组件视觉层，第一阶段围绕 `/create` 的创作流程验证设计与交互，再逐步扩展到其他页面。视觉以深色工作台、蓝青色品牌强调、安静清晰的信息层级为基础，并从现有 VOZEB 连续双环 Logo 延展出专属流线表达。

## 项目现状

- 前端使用 Next.js App Router、React、TypeScript、Tailwind CSS 4、Zustand。
- Ant Design 6 已用于全站表单、后台、导航和弹窗；Radix 提供部分低层交互。
- 项目已安装 `lucide-react` 和 `motion`，本阶段不增加组件或动效依赖。
- 全站已有浅色/深色主题、Ant Design token 与 Tailwind CSS token；当前通用主色以中性黑白为主。
- `/create` 已包含创作输入、附件、Skill、逻辑模型、智能规划、媒体结果、会话历史等业务流程。本阶段的视觉组件不得替换或削弱这些已有能力。
- `web/src/components/ui/` 是现有共享 UI 组件目录；页面专属业务组件仍留在页面目录。

## 设计原则

1. 先沿用项目现有依赖与状态管理；视觉组件不自行访问服务端 API。
2. Ant Design 继续承载成熟的业务交互；VOZEB 组件层用于统一视觉表面、状态反馈、复合创作控件和展示样例。
3. 蓝色表达主动作与选择，青色表达生成、连接和流动状态；高亮限制在交互焦点和必要的过程状态。
4. Logo 的连续双环结构延展为 `Current Rail`：由细蓝青流线表达当前选择、焦点和生成进度，不将其变成持续闪烁的装饰。
5. 页面布局和交互可以研究成熟产品，但不得逐像素复制其品牌、文案、图标、字体、素材或专有视觉 token。
6. 所有关键控件支持键盘和触控；悬停只提供补充信息；动效尊重 `prefers-reduced-motion`。

第一阶段的 Token 建议值：

| Token | 值 | 用途 |
|---|---|---|
| `--vozeb-night` | `#07111F` | 创作工作区背景 |
| `--vozeb-panel` | `#0D1C2D` | 主面板 |
| `--vozeb-elevated` | `#11263B` | 弹层与浮起表面 |
| `--vozeb-blue` | `#2F7CFF` | 主动作、选中与链接 |
| `--vozeb-cyan` | `#47E7D0` | 生成状态、流线高光 |
| `--vozeb-ice` | `#DDFBFF` | 高对比细节与焦点光 |

Token 只在 VOZEB 组件作用域内使用；不在本阶段切换全站 Ant Design 主色，不影响后台既有主题。组件样式同时提供浅色适配，确保用户切换主题时内容仍可阅读。

## 组件与文件边界

组件入口：`web/src/components/ui/vozeb/`。样式 Token 位于 `web/src/app/styles/global-vozeb-tokens.css` 并由 `globals.css` 引入。动效常量位于 `web/src/lib/vozeb-motion.ts`，纯视觉辅助函数位于同目录的 `vozeb-theme.ts`。

首版组件：

| 组件 | 职责 | 业务连接边界 |
|---|---|---|
| `VozebSurface` | 面板、卡片和浮层表面 | 仅接收内容、尺寸和视觉变体 |
| `VozebButton`、`VozebIconButton` | 主次动作与图标动作 | 通过标准按钮事件交由调用方处理 |
| `VozebStatusPill` | 排队、生成中、完成、失败、待检查状态 | 只呈现传入状态，不推断业务状态 |
| `VozebBreadcrumb` | 层级导航，支持窄屏折叠 | 接收调用方提供的标签与导航回调 |
| `VozebTicker` | 状态公告、横向流动信息 | 内容仍可访问；支持暂停和 reduced motion |
| `VozebFloatingPreview` | 桌面悬浮/聚焦预览、移动端点击预览 | 只渲染调用方提供的预览内容，不负责取数 |
| `VozebComposer` | 创作输入区的视觉和控件布局样板 | 以 props 与回调连接现有 `/create` 状态，不创建第二套业务状态 |
| `VozebStreamMessage` | 增量消息文本与提交、流式、完成、失败、停止状态 | 消费稳定消息标识和调用方提供的状态/回调，不模拟网络流 |
| `VozebMediaResultCard` | 图片/视频结果、元信息和操作位 | 消费现有结果数据；媒体尺寸与交互规则沿用业务契约 |

组件导出统一由 `index.ts` 提供。简单的单层样式不另建转发组件；仅在可复用视觉职责清晰时创建文件。

## 展示与迁移

首阶段增加一个仅供内部评审的组件展示页，展示浅色/深色、桌面/窄屏和各交互状态；不加入主导航，也不放入线上业务入口。完成组件验证后，再以独立后续任务接入 `/create` 的输入区、消息流和结果卡片。

业务接入必须保留现有 `/create` 的附件、Skill、逻辑模型、智能规划、Agent/图片/视频/音频类型、媒体结果、会话历史、失败重试、持久化与恢复行为。若组件 API 无法承载现有流程，应调整组件接口，不应删除业务能力来适配视觉方案。

## 关键交互要求

### 流式消息

- 消息由真实 Agent/SSE 状态驱动，按稳定 `messageId` 累积内容。
- 组件表达 `submitted`、`streaming`、`ready`、`error`、`aborted` 状态。
- 停止、恢复、重试由父级业务逻辑处理，组件仅发出回调。
- 自动跟随仅在用户仍靠近消息底部时发生；用户浏览历史时保留其滚动位置。

### 跑马灯

- 不使用废弃的 `<marquee>` 元素；内容复制只用于无缝视觉衔接并从辅助技术树隐藏。
- 支持暂停和手动阅读；reduced motion 下关闭自动位移并展示静态内容。
- 容器不得造成视口级横向溢出。

### 悬浮预览

- 桌面支持 hover 与键盘 focus，触屏通过点击打开。
- 预览根据可用空间调整方向，支持 Escape 与焦点管理。
- 核心操作和必要信息不能只存在于 hover 内容中。

### 动效

- 优先使用 `transform` 与 `opacity`，避免不必要的布局和尺寸动画。
- 统一提供轻量状态切换与入场节奏；高亮动效仅用于当前状态或真实进度。
- reduced motion 下停用非必要的持续动画和位移。

## 验收

- 390px、430px、1440px 与宽屏下组件布局可读，页面和内部滚动区域没有横向溢出。
- 组件展示页能切换浅色/深色并展示默认、hover、focus、pressed、loading、empty、error、disabled 状态。
- 键盘可完成核心操作，焦点样式清晰，纯图标按钮具有可访问名称。
- 跑马灯、悬浮卡片、流式消息在移动触控、键盘和 reduced motion 下有定义明确的行为。
- 流式视觉不使用定时器伪造输出；视觉组件不新增 API 请求或持久化。
- `/create` 业务流程的接入在独立迁移任务验收，须证明现有入口、附件与重试等行为仍可用。
- 相关 Vitest、TypeScript 类型检查、项目要求的全量质量门禁与浏览器回归均通过后，才可宣称组件库阶段完成。

## 不在本阶段范围

- 全站整体换肤或将 Ant Design 全部替换。
- 重做 `/create`、Canvas、短剧、后台等完整页面布局。
- 新增业务 API、模型/任务状态或全局状态管理。
- 新增自绘品牌 Logo、图标包或第三方运行时依赖。
- 为组件展示编造真实业务数据；样例仅用于视觉评审并明确标记。
