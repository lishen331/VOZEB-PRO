# 短剧工作流需求基线

## 目的

本文整理已在对话中达成的短剧工作流产品共识，作为后续开发和验收的基线。

- 不把当前代码结构当作产品需求。
- 不把未确认的 UI 位置、数据库字段或成员数据结构写成既定结论。
- “内容审核”和“团队审批”是两个独立能力，不能互相替代或混用名称。

## 一、总体流程

用户侧制作工作流保持为：

```text
剧本 -> 资产准备 -> 分镜 -> 镜头生成 -> 内容审核 -> 成片导出
```

- 剧本生成或导入后，进入资产准备，而不是先进入团队审核。
- 内容审核位于成片导出之前。用户可以根据审核结果回到前面的资产、分镜或镜头环节修改。
- 内容审核后续演进为 AI 审核，可评估风险、剧情完整性、角色/场景/道具质量、视觉图片与分镜视频质量，并给出评分和定位问题的能力。
- 模型渠道与模型选择不属于本轮协同功能范围；默认跟随后台渠道配置。

## 二、一键全流程

一键全流程服务于个人创作，默认由 AI Agent 连续推进提示词、生图、生视频，不要求用户逐项确认。

### 执行终点

1. 生成到资产：完成角色、场景、道具及其提示词准备后停止。
2. 生成到分镜图：在资产基础上完成分镜提示词和分镜图后停止。
3. 生成完整视频：继续完成镜头视频、内容审核和可选导出。

### 配置与反馈

- 可选当前集或全部剧集。
- 可配置画面比例、单镜头时长、输出语言、视觉风格、是否导出。
- 默认使用后台渠道；用户后续可获得渠道选择能力，但不是本轮重点。
- 失败策略以跳过失败项并汇总为默认；完成后应能通过消息定位失败的阶段或素材。

### 与团队协作的关系

- 个人创作可以直接一键推进。
- 协作项目处于严格审批模式时，一键流程不得绕过提示词确认与上游阶段审批。
- 协作项目处于并行模式时，成员可继续下游工作，提交仅代表交接而不是阻塞。

## 三、内容审核（AI 审核）

内容审核是统一的 AI 审核能力，不区分 C 端、B 端或协作端。

- 当前阶段只做前端演示，不接入真实 AI 审核请求、评分、保存或扣费。
- 后续结果应覆盖剧本、资产、视觉图片和镜头视频，并能定位回对应制作阶段。
- 内容审核不等同于项目组长审批，也不承担成员权限或阶段解锁职责。

## 四、团队协作与团队审批

团队协作是可选能力。个人独立创作不必创建项目组、不必提交审批，也不应被协作规则阻断。

### 团队角色与职责

- 项目组长负责统筹、任务分配、阶段审批和打回。
- 团队成员可分别承担编剧、资产提示词、视觉图片、分镜视频等工作；一个成员也可以承担多个阶段。
- 项目组长应能调整成员角色、阶段责任和项目模式。
- 两人团队（组长 + 成员）必须可用；多人专业分工也必须可用。
- 所有成员复用统一 VOZEB PRO 账号。教师/学生是账号附带身份，普通 C 端用户也可以受邀加入项目组，不建立另一套协作账号体系。

### 团队审批链路

团队审批链路独立于 AI 内容审核：

```text
剧本 -> 资产提示词 -> 视觉图片 -> 分镜视频 -> 成片
```

| 审批点         | 包含的交付物                                                       |
| -------------- | ------------------------------------------------------------------ |
| 剧本审核       | 故事梗概、分集剧本、人物和情节表达。                               |
| 资产提示词审核 | 角色、场景、道具设定及提示词；包含分镜提示词的可审查、可修改内容。 |
| 视觉图片审核   | 角色/场景/道具图片与分镜图片的视觉一致性和可用性。                 |
| 分镜视频审核   | 镜头视频、节奏、动作衔接和可用性。                                 |
| 成片审核       | 导出前的最终成片版本。                                             |

项目组长在项目创建或项目设置时自由选择哪些节点需要审批；未启用的节点不形成门禁。每个已启用节点至少需要支持：成员提交、项目组长通过、项目组长打回并附带反馈、成员修改后再次提交，以及可追溯的状态与记录。

### 两种协作模式

#### 严格审批

- 上游审批通过前，下游阶段不能继续执行或提交。
- 提示词确认不能被一键流程绕过。
- 适用于两人团队，避免成员在未经确认的上游基础上浪费后续制作成本。

#### 并行协作

- 提交代表交接，不阻塞下游成员继续制作。
- 上游后来被打回或产生新版本时，相关下游内容标记为“基于旧版本，需确认”。
- 下游内容不能被自动删除；负责人决定继续沿用、重新确认或重新制作。
- 项目组长可在项目设置中切换模式。已有进行中的提交不被破坏，切换只影响后续阶段的执行规则。

### 反馈、通知与导出

- 项目组长可按项目决定打回时是否必须填写反馈、是否通知相关成员、是否允许附件；第一版不实现 `@成员`、截止时间和任务管理。
- 若项目启用了审批，所有已启用的审批节点通过后，解除成片导出按钮的审批限制；不自动开始导出。
- AI 内容审核保持独立于团队审批。本轮 Demo 不将 AI 审核结果作为团队协作导出门槛；后续真实业务可单独增加项目级审核门槛配置。

### 界面位置

- 协同面板位于短剧制作工作台右侧，与左侧“剧集”面板对称。
- 桌面端可展开、收起；窄屏通过右侧 Drawer 打开。
- 右侧面板包含项目组、成员职责、协作模式、可选审批节点、节点状态、反馈设置和反馈记录。
- 每个可审批制作阶段内都有当前阶段的提交状态和提交审核入口。

## 五、本轮交付范围：三个前端 Demo

本轮先验证交互和工作流，不接入真实协同业务。

| Demo           | 当前状态  | 明确不做                                                                                                    |
| -------------- | --------- | ----------------------------------------------------------------------------------------------------------- |
| 一键全流程     | 已完成    | 不创建生成任务、不保存配置、不调用渠道、不消耗额度。                                                        |
| 内容审核       | 已完成    | 不调用 AI、不保存审核结果、不产生真实评分或拦截。                                                           |
| 团队协作与审批 | 前端 Demo | 不创建真实项目组，不读取教师/学生身份，不保存成员/角色/审批记录，不发送通知，不实施真实权限或服务端阶段锁。 |

协同 Demo 需要验证的前端交互是：右侧可收起协同面板、团队开关、严格/并行模式、模拟成员与职责、可选审批点、五个审批点的提交/通过/打回、反馈和状态变化、并行模式的“基于旧版本，需确认”提示，以及审批完成前的导出限制。

## 六、Demo 后的真实业务待办

1. 持久化项目组、成员、职责、协作模式和审批记录。
2. 与现有教师/学生、项目组长和学校组织能力建立真实身份与授权边界。
3. 为每个审批提交保存不可变版本快照、上游依赖版本和变更原因。
4. 在服务端实现严格模式的阶段门禁，并在并行模式实现旧版本确认规则。
5. 接入成员通知、待办、审核反馈和从消息定位到具体资产/分镜/视频的能力。
6. 接入真实 AI 内容审核、评分、风险识别与回流修改。
7. 接入真实一键编排、生成任务、失败汇总、重试、成本与额度处理。

## 七、后续单独确认

1. 真实 AI 内容审核是否应增加为可配置的导出门槛，以及评分/风险项的明确口径。
2. `@成员`、截止时间、任务看板和附件存储的具体交互与权限。
3. 多成员并发修改同一资产、分镜或镜头时的锁定、冲突解决和版本合并规则。
