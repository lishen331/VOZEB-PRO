# RunningHub 工作流自动发现与轻量测试设计

## 1. 文档定位

本文档是对既有 RunningHub 无限练习接入设计的收敛版本，适用于 2026-09-02 之后的产品和开发实现。

本版以真实调通的图片和视频工作流为依据，解决两个问题：

1. 运维人员不需要理解 RunningHub 的底层协议和节点 JSON，也能完成工作流接入。
2. 平台可以从 RunningHub 拉取工作流 JSON，自动生成业务配置，并通过一次真实样例任务证明工作流可用。

本文档替代旧设计中“运维手填完整协议字段、节点映射 JSON”和“面向运维的正式版本管理”这两部分。短剧实验室、本地模型中台、机房 GPU 调度和正式生产工作流不在本文档范围内。

## 3. 一期目标

- 平台管理员可以配置 RunningHub 渠道：名称、地址和 API Key。
- 平台管理员可以新建一个工作流并填写名称、Workflow ID/链接、能力类型和业务用途。
- 平台服务端可以调用 RunningHub 工作流 JSON 接口并返回节点摘要。
- 系统自动识别提示词、图片/视频/音频、时长、枚举、默认值和输出节点候选。
- 运维人员只确认业务字段和节点候选，不手写 `nodeInfoList` 或完整映射 JSON。
- 系统能检测默认文件依赖并提示需要上传替代素材。
- 后台可以做连接检查和真实样例测试。
- 测试成功的当前配置可以启用，并绑定到无限练习业务 code。
- 无限练习继续复用现有文本、图片、视频、音频任务和结果展示。

## 4. 一期明确不做

- 不做面向运维的正式版本列表、版本切换、复制版本和回滚。
- 不做节点图可视化编辑器。
- 不做本地模型中台、显卡调度、队列优先级或机房管理。
- 不允许运维修改 RunningHub 官方接口路径、请求方法或 API Key 字段位置。
- 不把 RunningHub 的内部 Workflow ID、节点 ID、请求模板暴露给学校、老师或学生。
- 不把短剧实验室替换当前短剧生产模块的配置接入无限练习。
- 不自动猜测并静默保存不确定的节点映射。

## 5. 核心原则

### 5.1 三层配置

```text
渠道配置：如何连接 RunningHub
工作流配置：这个业务能力使用哪个远端工作流
测试证据：当前配置是否真实跑通过
```

工作流配置不再承载底层协议编辑器。协议由 RunningHub provider 固定实现；异常协议仅进入折叠的高级配置。

### 5.2 业务标识和上游标识分离

平台内部业务标识、逻辑模型标识和 RunningHub 远端 Workflow ID 必须分开保存：

```text
VOZEB 逻辑模型：workflow-minimax-h3-base
RunningHub Workflow ID：2090436199843454978
无限练习业务 code：storyboard-video
```

Workflow ID 可以由完整链接解析得到，但不能使用平台别名替代。

### 5.3 自动识别必须经过确认

系统采用：

```text
读取 JSON → 自动推荐 → 运维确认 → 生成业务配置
```

无法确定时显示候选列表和原因，不直接选择第一个节点作为生产映射。

## 6. 配置对象

### 6.1 渠道配置

运维可见字段：

- 渠道名称
- Base URL
- API Key
- 启用状态
- 渠道用途：无限练习/共享

系统固定字段：

- 创建路径：`/task/openapi/create`
- 查询路径：`/openapi/v2/query`
- 创建方法：`POST`
- 查询方法：`POST`
- 创建体 API Key 注入位置
- 查询体：`{ "taskId": "..." }`
- 官方任务状态和结果解析
- 媒体上传接口

API Key 只在服务端加密保存，禁止进入工作流请求模板、浏览器响应、日志和测试结果。

### 6.2 工作流配置

快速配置字段：

- 工作流名称
- 所属 RunningHub 渠道
- Workflow ID 或工作流链接
- 能力类型：图片、视频、音频、文本
- 业务用途：文生图、参考生图、文生视频、参考生视频、配音、音乐等
- 是否需要参考素材
- 当前启用状态
- 备注

系统生成或维护的字段：

- `workflowKey`
- `businessCode`
- `inputSchema`
- `nodeMappings`
- `outputMappings`
- `workflowJsonFingerprint`
- `lastTestAt`
- `lastTestResult`
- `lastTestError`
- `lastTestConfigFingerprint`

现有数据中的 `version` 字段暂时保留为内部兼容字段，统一为当前配置的序号，不在页面显示，也不提供复制、切换和回滚操作。已有版本 API 不删除，以避免破坏已部署数据；新页面不再链接这些 API。

### 6.3 测试证据

测试证据不是版本控制，仅用于判断当前配置是否真实可用。

每次成功或失败测试保存：

- 测试时间
- 当前 Workflow ID
- 工作流 JSON 指纹
- 当前输入/节点/输出映射指纹
- taskId
- 上游状态
- 结果类型和结果 URL 摘要
- 脱敏错误原因
- 执行管理员

当工作流配置或 JSON 指纹发生变化时，显示“配置已修改，请重新测试”。旧的测试记录可以作为排障历史，但不作为当前可用证明。

## 7. 从 RunningHub 拉取 JSON

### 7.1 操作入口

工作流新建或编辑页提供按钮：

```text
读取工作流
```

服务端使用当前渠道密钥调用官方工作流 JSON 接口。浏览器不直接访问 RunningHub，也不提交 API Key。

### 7.2 读取结果

返回结果分成四类：

1. 工作流基本信息：Workflow ID、工作流类型、节点数量。
2. 输入候选：文本、图片、视频、音频、数字、布尔、枚举。
3. 输出候选：图片、视频、音频、文本。
4. 风险提示：默认文件、不可访问 URL、缺失输出、无法判断用途的节点。

原始 JSON 只在平台管理员的“高级信息”区域按需查看，默认不展示大段 JSON。

### 7.3 识别规则

系统根据节点类型、字段名、节点标题、输入类型和默认值生成候选：

| 业务角色 | 识别信号 | 用户可见名称 |
| --- | --- | --- |
| 提示词 | 文本输入、`prompt/text/value` 等字段、文本编码节点 | 提示词 |
| 参考图片 | `LoadImage`、图片 URL/文件输入 | 参考图 1、参考图 2 |
| 参考视频 | 视频加载或视频 URL 输入 | 参考视频 |
| 参考音频 | 音频加载或音频 URL 输入 | 参考音频 |
| 时长 | 数字输入，字段或标题包含 duration/时长 | 视频时长 |
| 输出 | `SaveImage`、视频合成、音频输出或结果 URL 节点 | 输出图片/输出视频/输出音频 |

识别结果必须带候选置信度或“需要确认”标记。业务能力和业务用途仍由运维选择，不由节点名称自动决定。

### 7.4 默认文件依赖

当节点默认值是文件名、私有路径或无法验证的外部资源时，系统标记：

```text
发现默认文件依赖，正式调用时需要用户上传替代素材
```

如果该输入在业务配置中是必填，样例测试表单必须要求上传；没有替代素材时不得提交任务。

## 8. 后台页面

### 8.1 工作流列表

入口继续放在：

```text
上游配置 → 模型渠道 → RunningHub → 工作流
```

列表展示：

- 工作流名称
- 能力和业务用途
- Workflow ID
- 输入/输出摘要
- 当前配置状态：草稿、已停用、已启用
- 最近测试结果
- 配置是否需要重新测试
- 更新时间

操作列固定在右侧，桌面端无需横向拖动；移动端使用卡片底部操作区。操作为：

- 编辑配置
- 读取工作流
- 测试运行
- 启用/停用

不再展示“复制版本”“版本切换”“回滚”。

### 8.2 快速配置页

页面默认只显示：

1. 基础信息
2. RunningHub 工作流 ID/链接
3. 读取工作流
4. 业务输入确认
5. 输出确认
6. 测试运行

高级配置折叠展示，仅用于排查特殊工作流。高级区域可以查看系统生成的节点映射和协议摘要，但不能在普通流程中要求运维手写。

### 8.3 测试页

测试面板根据确认后的输入契约生成表单：

- 文本输入
- 参考图片/视频/音频上传
- 时长、比例、枚举和开关
- 提交样例测试
- 查询状态
- 结果预览
- 原始响应展开

测试结果复用现有图片、视频、音频和文本结果组件。

连接检查与样例测试分开：

- 连接检查：读取工作流 JSON，不创建 GPU 任务，不消耗生成额度。
- 样例测试：真实创建任务，可能消耗 RunningHub 额度，验证完整链路。

## 9. 状态与启用规则

工作流启用状态只保留：

- 草稿
- 已停用
- 已启用

最近测试单独显示：

- 未测试
- 测试中
- 测试成功
- 测试失败
- 配置已修改，请重新测试

新建工作流默认停用。启用前必须满足：

- Workflow ID 已读取成功。
- 输入和输出映射已确认。
- 必填默认文件已经配置替代输入，或明确不需要该输入。
- 当前配置存在成功样例测试证据。
- 最近成功测试的配置指纹与当前配置一致。

停用工作流仍可以编辑、读取 JSON 和测试。停用不会删除配置或测试记录。

## 10. 运行链路

无限练习前端只提交稳定的业务 code、提示词和业务素材引用：

```text
无限练习
  → 服务端按业务 code 找到已启用 RunningHub 工作流
  → 按 inputSchema 校验输入
  → 按 nodeMappings 生成 nodeInfoList
  → provider 注入 API Key 并提交任务
  → 复用现有查询、落盘、失败和结果展示
```

客户端不能覆盖 channelId、Workflow ID、节点映射、请求模板或 API Key。

提交任务时记录当前 Workflow ID、配置指纹和输入摘要，保证后续工作流变化不会改变历史任务解释。

## 11. 安全和隔离

- 只有拥有 `upstream.manage` 的平台管理员可以读取、保存、测试和启用工作流。
- 学校管理员、老师和学生不能访问工作流配置 API。
- 管理员测试使用 `admin-workflow-test` 身份。
- 测试不创建学校项目、正式作品、学生记录或积分流水。
- API Key、完整请求体和完整上游响应不进入普通前端 DTO。
- 测试结果 URL 使用现有媒体代理和落盘策略，不能把临时上传 URL 当作永久素材。
- RunningHub 失败原因要保留可执行提示，例如“默认参考图无法访问，请上传替代素材”。

## 12. 兼容与迁移

- 现有 `modelConfigs` 继续读取。
- 现有工作流 JSON 中的 `version` 字段不删除，服务端继续接受旧数据。
- 旧的自定义创建/查询路径在高级兼容模式下继续可用。
- 新建或重新读取的官方 RunningHub 工作流默认使用固定官方协议，不再要求运维填写路径。
- 已启用且没有测试指纹的旧工作流不强制立即下线；当运维编辑、重新读取或切换为快速配置后，必须完成一次成功样例测试才能再次启用。
- 不重建持久化表，不删除已有字段；新增指纹和发现摘要字段使用幂等升级。

## 13. 验收标准

### 后台配置

- 运维只填写渠道、名称、Workflow ID/链接、能力和业务用途即可开始读取。
- 点击“读取工作流”能看到输入、输出和默认文件依赖摘要。
- 常规工作流不需要填写创建路径、查询路径、任务 ID 字段、状态字段、结果字段或 JSON 模板。
- 不确定节点必须由运维确认，系统不能静默猜测。

### 真实测试

- 连接检查不会创建上游任务。
- 样例测试能真实返回 taskId。
- 样例测试能完成状态查询、结果读取和本地预览。
- 参考素材工作流必须验证上传素材替换默认文件。
- 测试失败显示 RunningHub 原因和可执行修改建议。

### 无限练习

- 启用后的工作流按业务 code 被无限练习调用。
- 前端不显示 API Key、Workflow ID、节点 ID 或请求模板。
- 图片、视频、音频和文本结果继续使用现有任务结果组件。
- RunningHub 工作流配置不会进入正式生产或短剧实验室路由。

### 响应式和操作可见性

- 桌面端操作列固定可见。
- 390px、430px 移动端可以完成读取、保存、测试和启用。
- 抽屉和测试面板不横向溢出。

## 14. 后续扩展预留

本期不实现，但数据边界应允许后续增加：

- 工作流配置差异比较
- 多个工作流候选和故障切换
- 本地模型 provider
- 更精确的节点依赖分析
- 运行统计和额度成本分析

这些扩展只能复用业务输入/输出契约、任务上下文和 provider 接口，不能要求前端重新理解上游节点协议。
