# 无限练习与灵感发现制作流程设计

## 1. 背景

平台进入学校后，学生需要大量练习剧本创作、画面设计、视频生成和短剧制作。直接使用生产模型会产生较高算力费用，因此新增“无限练习”模块，使用 RunningHub 开源模型接口作为首期练习模型来源，后续可切换到本地部署模型。

无限练习和正式生产必须是两种独立的项目身份。学生可以从空白练习开始，也可以从平台公开作品复制初始内容，但不能在同一个 Canvas 或短剧项目中切换“正式生产”和“练习模式”。

平台同时利用现有公开作品建设拉片能力。拉片不是新的作品上传体系或独立导航页面，而是灵感发现中对已公开 Canvas/短剧作品提供的只读制作流程展示和练习复制入口。

## 2. 目标

- 学生可以在独立的无限练习项目中反复使用平台配置的开源模型。
- 复用现有 Canvas 和短剧编辑器、生成服务、媒体资产和项目持久化能力。
- 现有作品上传、审核、作品广场和首页精选继续作为拉片内容来源。
- 被平台管理员设置为拉片项目的公开 Canvas/短剧作品可以在灵感发现中浏览成片，并查看只读制作流程。
- 学生可以从拉片作品创建新的无限练习项目，不修改原作品。
- 后台可以复用现有模型渠道和协议配置，区分正式生产模型与开源练习模型。
- RunningHub 是首期上游，后续本地模型只替换执行路由，不改变前端练习入口。

## 3. 已确认的产品决策

### 3.1 无限练习项目

- 无限练习是独立项目身份，不是现有项目的模式开关。
- 正式项目和练习项目不能在同一个项目内互相切换。
- 练习项目可以从正式项目或公开作品复制初始内容，复制后形成独立快照。
- 不提供 Canvas 与短剧之间的项目转换。
- 复制后的项目继续使用现有 Canvas/短剧组件，只改变模型执行策略。
- RunningHub 接入复用现有模型渠道后台，但首期只绑定无限练习模型池，不改变正式生产默认模型。
- 拉片项目不是公开作品的自动状态，只有平台管理员可以在作品审核详情中设置。

### 3.2 无限练习首页

首页采用卡片入口：

- 两个大卡片：Canvas 无限练习、短剧无限练习。
- 若干小卡片：剧本编写、分镜图生成、分镜视频生成、配音制作、音乐制作等单项练习。

大卡片创建完整的独立项目，小卡片创建独立的单项练习记录。单项练习不改变正式项目，也不自动转换为 Canvas 或短剧项目。

“无限”表示学生不按平台积分或学校额度逐次扣费；平台仍可以根据管理员配置执行队列、并发、供应商和资源保护策略。

### 3.3 拉片来源

灵感发现中的拉片能力只接入现有公开作品中被平台管理员设置为拉片项目的两种来源：

- Canvas
- 短剧

素材类作品和普通视频作品仍可以在作品广场正常展示，但不显示制作流程，也不提供复制到练习的拉片操作。

剧本、分镜不是独立的拉片入口。短剧作品中的剧本、角色、场景、分镜、镜头和配音属于短剧制作流程的内部内容。

### 3.4 拉片入口

- 不新增“拉片库”顶层导航。
- 不在“资产”分组下增加拉片入口。
- 拉片入口位于现有“广场 → 灵感发现”的作品卡片和作品预览中。
- “灵感发现”继续复用现有作品分类、标签、搜索、精选和公开作品预览。
- 拉片是公开作品的一种查看能力，不建立第二套作品内容库。
- 作者不能自行设置或取消拉片状态。

## 4. 现有系统调查结论

当前作品发布体系已经具备以下能力：

- `WorkPublicationSourceType` 已包含 `media`、`canvas`、`drama`。
- 作品发布支持标题、说明、公开提示词、分类、标签、作者展示和图片/视频媒体。
- 公开作品接口和作品广场已经能查询作品基本信息、公开提示词、标签、媒体、浏览量和精选状态。
- Canvas 来源项目保存节点、连接、会话和生成媒体引用。
- 短剧来源项目保存角色、场景、集数、镜头、分镜图、视频、配音和生成状态。
- 现有作品发布记录包含版本和审核状态，适合在发布版本上建立拉片快照。

当前公开作品接口不会直接返回 Canvas 节点关系或短剧项目结构。因此拉片需要在作品发布版本上补充一份“公开制作流程快照”，不能让公共页面直接读取创作者正在编辑的私有项目。

## 5. 页面与交互

### 5.1 灵感发现中的拉片内容

灵感发现继续作为统一的公开内容列表页，复用现有作品卡片、作品广场查询和媒体预览模式，不新增独立拉片库页面。

灵感发现仍然可以展示图片、视频、Canvas 和短剧等公开内容。平台管理员设置为拉片项目的 Canvas/短剧作品在卡片或作品详情中标记为支持制作流程。卡片显示：

- 封面或成片缩略图。
- 作品标题。
- Canvas/短剧来源标签。
- 作者和作品标签。
- 查看作品入口。
- 对于有公开流程快照的 Canvas/短剧作品，显示“制作流程”标识。

平台精选作品继续沿用现有 `isFeatured` 机制，并可以在首页或灵感发现首屏突出展示。精选只影响推荐位置，不改变作品是否具备拉片能力。

### 5.2 成片预览

点击灵感发现中的作品后，沿用现有公开作品预览界面，不新增一套复杂详情页：

- 左侧继续使用现有图片/视频媒体浏览器。
- 视频提供明确的播放、暂停和进度控制。
- 右侧继续展示标题、说明、作者、分类、标签和公开信息。
- 作品来源为平台内 Canvas/短剧项目、已被管理员设置为拉片项目且存在公开流程快照时，显示“制作流程”按钮。
- “复制到练习”作为固定操作，在成片预览视图中始终可见。

素材类公开作品、普通视频作品、没有结构化来源项目的媒体作品和未被管理员设置为拉片项目的 Canvas/短剧作品不显示“制作流程”和“复制到练习”的拉片操作。

### 5.3 制作流程

点击“制作流程”后，在同一个作品预览中切换为只读流程视图，不打开正式编辑器，不创建生产项目。

流程视图提供：

- “返回成片”操作。
- 当前作品来源和版本信息。
- 只读的制作步骤和公开媒体。
- 始终可见的“复制到练习”操作。

Canvas 流程展示画布结构、节点顺序/关系、引用资产、节点生成结果和最终成片。短剧流程展示角色与场景、集数、镜头顺序、分镜图、镜头视频、配音/音频和最终成片。

流程视图不提供编辑节点、修改脚本、重新生成、删除资产、查看私有会话或查看模型密钥等能力。

### 5.4 复制到练习

“复制到练习”在成片预览和制作流程两个视图中都可用。

- Canvas 作品复制为新的 Canvas 无限练习项目。
- 短剧作品复制为新的短剧无限练习项目。
- 使用当前公开作品版本的快照，不跟随原作品后续修改。
- 新项目归当前学生或用户所有，后续输出归新项目所有。
- 新项目保留来源作品、来源版本和作者署名信息。
- 复制失败时不创建半成品练习项目，并返回明确的中文错误。

## 6. 公开制作流程快照

灵感发现中的制作流程展示数据来源于作品发布版本和管理员启用拉片时生成的快照，而不是实时读取源项目。

概念上，发布版本需要关联以下信息：

```ts
type PublicProcessSnapshot = {
    sourceType: "canvas" | "drama";
    sourceProjectId: string;
    sourceProjectVersion?: string;
    capturedAt: string;
    payload: unknown;
};
```

具体存储方式沿用现有 PostgreSQL repository 和项目 JSON 版本机制，由实现计划阶段确定。快照必须支持：

- 与作品发布版本一一对应。
- 作品新版本发布后生成新快照。
- 原作品编辑不会改变已经公开的快照。
- 复制练习时可以根据快照重建独立 Canvas/短剧项目。

## 7. 公开内容规则

公开到作品广场的 Canvas/短剧作品不会自动成为拉片项目。平台管理员必须在作品审核详情中主动设置“拉片项目”，系统才会开放制作流程和复制到练习。平台只记录一次整体的拉片资料开放状态，不做剧本、提示词、节点、镜头等逐项权限配置。

拉片设置使用现有平台管理员的 `content.manage` 职责权限。学校管理员、老师、学生和普通用户不能设置或取消拉片项目。拉片状态与首页精选状态独立：精选只影响推荐位置，拉片只影响制作流程和复制入口，两者可以分别开启。

拉片状态绑定当前公开版本。作品发布新版本后，新的公开版本默认未设置拉片，管理员需要重新确认；作品下架、撤回或公开版本失效时，拉片流程和复制入口同步失效。

公开流程只来自已审核的当前发布版本。系统不公开：

- 未发布项目。
- 其他用户的私有会话。
- API Key、渠道密钥和内部执行配置。
- 与当前作品无关的用户资产。
- 未被公开版本引用的临时媒体。

平台与创作者在线下沟通公开制作流程的业务原因和内容范围。线上仍使用发布版本、审核状态和下架机制，作品下架后拉片预览、流程快照和复制入口同步失效。

## 8. 模型与后台配置

后台继续复用现有模型渠道、协议注册表、逻辑模型和生成任务配置，不在无限练习前端直接暴露 RunningHub 模型选择。

RunningHub 是模型渠道/上游平台，不单独建立一套模型后台。后台结构保持为：

```text
上游配置
├── 模型渠道
│   ├── 现有生产渠道
│   ├── RunningHub 渠道
│   └── 后续本地开源模型渠道
├── 协议中心
└── 逻辑模型
    ├── 正式生产模型池
    └── 无限练习模型池
```

渠道增加用途标记：`production`、`open-source-practice` 或 `shared`。首期 RunningHub 渠道只绑定 `open-source-practice`，正式生产模型的默认绑定保持不变。后续本地部署模型接入同一练习模型池，前端入口和任务协议不变。

RunningHub 模型目录只有在供应商官方目录接口已验证时才提供同步；没有可验证目录时，由管理员手动配置官方模型 ID，不根据任务路径猜测模型目录。

新增的是执行策略概念：

- `production`：正式生产模型和现有计费规则。
- `open-source-practice`：RunningHub 开源模型或后续本地部署模型，不按学生任务扣除现有积分。

前端只选择练习模块和练习项目类型。服务端根据执行策略和任务能力路由到文本、图片、视频、音频或音乐模型。后续接入本地模型时，保持同一任务协议和前端卡片入口。

## 9. 后台拉片设置

拉片设置复用现有“内容运营 → 作品管理 → 作品审核/作品详情”，不新增独立后台菜单。

作品详情中增加：

```text
拉片状态：未设置 / 已设置为拉片项目
操作：设为拉片项目 / 取消拉片项目
```

只有满足以下条件时才允许“设为拉片项目”：

- 当前作品已审核通过并处于公开状态。
- 来源类型是 Canvas 或短剧。
- 当前公开版本存在可读取的结构化项目内容和公开媒体。
- 系统可以为该版本生成公开制作流程快照。

启用操作需要在同一服务端事务中完成版本校验、快照创建和拉片状态写入，并记录管理员审计信息。取消操作立即撤销前端制作流程和复制入口，但不删除原作品、原项目或原始媒体。

后台列表可以增加“拉片”状态列和快捷操作；详情 Drawer 提供完整状态、公开版本号和快照可用性。精选按钮继续独立保留。

## 10. 非目标

本阶段不建设：

- 独立剧本拉片库。
- 独立分镜拉片库。
- Canvas 与短剧互转。
- 正式项目切换练习模式。
- 拉片流程编辑或再次生成。
- 创作者逐个流程节点的复杂公开权限编辑器。
- 新的作品上传、作品审核或社区系统。
- 学校结算、积分分配或财务功能。

## 11. 验收条件

### 灵感发现与拉片

- 不新增资产下的拉片入口或独立拉片库页面。
- 灵感发现可以展示公开图片、视频、Canvas 和短剧内容。
- 只有平台管理员设置为拉片项目的公开 Canvas/短剧作品会出现制作流程入口。
- 普通视频和素材作品不会出现制作流程入口。
- 卡片可以打开现有成片预览。

### 后台模型与拉片设置

- RunningHub 可以作为现有模型渠道接入。
- RunningHub 渠道可以绑定到无限练习模型池。
- 无限练习前端不要求学生选择 RunningHub 或具体上游模型。
- `content.manage` 平台管理员可以在作品详情中设置或取消拉片项目。
- 学校管理员、老师、学生和普通用户不能设置拉片项目。
- 拉片状态与首页精选状态可以独立开关。
- 新公开版本默认需要管理员重新确认拉片状态。

### 成片预览与流程

- 视频可以播放、暂停和拖动进度。
- 成片预览中可以进入“制作流程”。
- 制作流程只读，不出现编辑或生产生成操作。
- 制作流程可以返回成片预览。
- 成片预览和制作流程中都可以点击“复制到练习”。

### 复制练习

- Canvas 作品只能创建 Canvas 练习项目。
- 短剧作品只能创建短剧练习项目。
- 复制结果与原作品独立，原作品后续修改不会影响练习项目。
- 练习项目使用 `open-source-practice` 执行策略。
- 复制失败不会留下半成品项目。

### 兼容性

- 现有作品上传、审核、作品广场、Canvas 和短剧生产流程继续可用。
- 正式 Canvas/短剧项目不会出现模式切换入口。
- Canvas 与短剧之间不会出现转换入口。
