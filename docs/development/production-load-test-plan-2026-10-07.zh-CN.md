# 生产环境压测实施计划（2026-10-07）

> 目标：验证生产环境在课堂账号规模下的登录、画布与任务接口稳定性，重点定位“多人登录频繁”问题；真实图文只做受控小阶梯，视频真实调用为0。账号密码仅存在本机脱敏运行目录，不写仓库/报告。

## 1. 范围与安全边界

- 目标域名：`https://gammatv.gammablue-x.com/`。
- 账号来源：顺职大A/B班提供的生产测试账号；仅统计脱敏别名和账号总数。
- 不修改生产配置、限流、模型绑定、积分或数据库；不清理生产历史任务。
- 不进行真实视频生成；视频如需覆盖只使用隔离fixture，不接生产域名。
- 真实文本/图片：先1人冒烟，再5→10→20的小阶梯；每档结束并完成积分/任务对账后才能进入下一档。默认不直接进行80人真实生图。
- GitHub不推送、不合并、不部署。

## 2. 核心问题与通过标准

| 问题 | 证据标准 |
|---|---|
| 多人登录是否被错误限流 | 记录80账号60秒登录成功率、429数量、Retry-After、响应p50/p95/p99、设备/账号/IP维度可见证据；不伪造IP |
| 登录后使用是否稳定 | 复用成功会话，不重复登录；session、项目列表、详情接口p95/p99和HTTP错误 |
| 生产平台是否稳定 | live/ready持续200；5xx、OOM、重启、DB锁等待、Worker心跳、磁盘/内存 |
| 真实文本/图片是否可用 | 每档任务终态、上游request/task ID、扣费/退款、needs_review、未知结果；图片结果读取可用 |
| 是否存在跨账号风险 | 交叉读取项目/任务/媒体必须拒绝，不能探测非测试业务对象 |

## 3. 前置P0门禁

P0-1：核对生产live/ready；记录运行版本/镜像（只读）。
P0-2：读取两个Excel账号清单，统计总数、重复账号、空密码、班级分组；密码不输出。
P0-3：每班随机抽取少量账号登录验证，不先批量登录。
P0-4：确认生产账号积分、模型默认值、真实图文成本；没有负责人明确预算时只执行接口和1人冒烟。
P0-5：确认生产与staging key/数据库隔离，不读取或输出密钥原文。
P0-6：启动生产只读资源监控：CPU、内存、磁盘、容器、DB连接/锁、Worker、ready；无法采集的指标标记缺失。
P0-7：建立唯一`runId`、停止文件和脱敏JSONL；任何未知任务不自动重试。

## 4. 子Agent分工

- **Agent A：登录/接口**：账号清单脱敏、登录限流对照、会话复用、80人只读画布接口；不得启动真实生成。
- **Agent B：资源/证据**：生产SSH只读监控、版本、CPU/RAM/磁盘/DB/Worker/日志和限流证据；不得改配置。
- **Agent C：真实图文**：只执行获准的小阶梯文本/图片，逐任务记录扣费、退款、上游ID和媒体读取；不得自动扩大到80人。
- **主控**：统一runId、账号白名单、场景顺序、停止条件、报告；Agent不得各自叠加压力。

## 5. 场景顺序

| 场景 | 负载 | 结果 |
|---|---|---|
| P0 | 健康、版本、账号、资源只读 | 通过后进入S0 |
| S0 | 1人登录+session+项目列表+项目创建/读取 | 不生成，确认脚本和权限 |
| S1 | 80账号60秒登录；不重复登录 | 专项定位429/登录频繁 |
| S2 | 80已登录会话，10分钟画布列表/详情/保存（不生成） | 平台接口稳定性 |
| S3 | 生产真实文本1→5→10→20人，每人1任务 | 小阶梯真实上游、退款、request ID |
| S4 | 生产真实图片1→5→10→20人，每人1张；每档排空 | 图片渠道、扣费、结果读取 |
| S5 | 登录失败/刷新/重复登录对照；不修改限流 | 登录错误归因 |
| S6 | 生产收尾：任务清空、账务对账、资源快照 | 报告闭环 |

## 5A. 画布功能与接口专项（补充）

生产压测必须覆盖画布真实业务链路，不能只测登录、session和项目列表。

### C0 画布冒烟

1. 使用单个生产测试账号创建独立Canvas项目；
2. GET项目列表、GET项目详情；
3. 写入一个文本节点、一个图片节点和一个视频fixture节点；
4. 保存节点位置、节点配置和节点之间的连接；
5. 刷新后重新读取项目，确认节点、连线和提示词仍存在；
6. 不调用真实视频生成，视频节点只验证平台状态/fixture路径。

### C1 画布接口并发

| 接口 | 场景 | 指标 |
|---|---|---|
| `GET /api/canvas/projects` | 80个已登录账号循环读取 | p50/p95/p99、HTTP错误、响应体大小 |
| `POST /api/canvas/projects` | 每账号独立创建一个压测项目 | 创建成功率、重复项目、耗时 |
| `GET /api/canvas/projects/{id}` | 并发加载详情 | 跨账号必须404/403，不得泄露 |
| `PATCH /api/canvas/projects/{id}` | 节点/连线/viewport连续保存 | 200/409比例、版本冲突、保存耗时 |
| `POST /api/text-tasks` | 画布文本节点真实生成 | taskId、终态、回写、扣费/退款 |
| `POST /api/image-tasks` | 画布图片节点真实生成 | 单图/第二图、准入429、上游ID、媒体读取 |
| `GET /api/*-tasks/{id}` | 刷新/重连后轮询 | 状态一致、未知结果不重建 |
| `POST/PATCH /api/reference-assets` | 画布参考图上传/引用 | MIME、权限、存储和节点引用映射 |

### C2 画布保存与并发冲突

- 同一账号同一 `expectedUpdatedAt` 并发保存两次：允许一成功、一409，不能静默覆盖；
- 同一 `clientRequestId` 同参数重复生成：只产生一个任务和一笔消费；
- 同一请求标识更换正文/模型：按契约返回409或明确拒绝，不能复用旧结果；
- A账号项目ID被B账号读取或保存：必须拒绝；
- 生成任务完成后重新加载画布，确认结果媒体和节点状态可见；
- 浏览器刷新、断线、重新进入画布后，未完成任务仍能恢复查看。

### C3 画布生产压测分档

- C0：1账号完整画布冒烟，不产生视频费用；
- C1：80个账号同时打开各自画布，持续10分钟，只读详情+保存轻量节点；
- C2：80个账号每人提交1文本+1图片到各自画布，真实生产小阶梯前必须先完成1→5→10→20档；
- C3：80个账号每人追加第二张图片，单独统计平台429、渠道拒绝、任务成功和扣费，不把第二张失败混成上游失败；
- C4：20个账号执行刷新/断线/任务轮询恢复，验证结果回写；
- C5：全流程结束后清点测试项目、任务、媒体引用和未决状态，不删除非测试生产数据。

### C4 画布通过标准

- 80账号画布列表/详情/保存无平台5xx、无跨账号泄露；
- C1保存冲突符合版本契约，一成功一409，不出现静默覆盖；
- 画布内真实文本/图片任务的终态与数据库、扣费、媒体读取一致；
- 第二张图片必须明确区分：平台入口429、用户在途并发拒绝、上游失败或真实成功；
- 刷新/断线后任务和结果可恢复；
- 视频节点真实出站和真实扣费始终为0。
## 6. 停止条件

出现生产非测试业务影响、跨账号泄露、真实视频出站、未知任务重复创建、重复扣费、OOM/重启、ready失败、DB锁等待>30秒、磁盘低于10%/5GB、5xx持续>5%、费用超过已批准额度，立即停止新增请求并排空。登录429本身记录后继续已登录只读场景，不自动重试登录。
