# 材料 4：当前状态、改法与优先级

> 状态基于 2026-10-10 仓库源码和既有测试/文档证据；本次本地 PostgreSQL `127.0.0.1:5433` 未连接，未完成最新登录态与真实供应商验收。**“已有基础”不等于 10/22 可现场承诺。**

## 先按“能不能卖这套解决方案”判断现状

我们的产品状态要同时过三道门：

1. **可销售**：客户能听懂买什么、谁使用、解决什么问题、为什么不是买一个单点 AI 工具。
2. **可交付**：学校能配置课程和角色，教师能带课，学生能实训，作品能评价/交付。
3. **可复制**：换一所高校/职校，仍能用课程模板、师陪流程、平台配置和项目模板快速上线。

只通过第一道门的功能不能写成“方案已落地”；只在单个演示账号能运行的能力不能写成“可规模复制”。

## 优先级口径

- **P0**：不做就无法把 10/22 主展示讲清并稳定跑通。必须有负责人、真实数据、浏览器证据和失败兜底。
- **P1**：影响试点交付或制作效率，但可在推广会用清楚的设计方案说明，不能冒充现有能力。
- **P2**：需要客户验证或依赖较大，推广会不承诺上线时间。

## 10/22 推广会应该卖的不是功能清单

建议现场销售一句话：

> **我们为高校和职校提供一套 AIGC 人才培养与内容生产平台：学校有课程，教师有师陪，学生有实训，企业有项目，最后沉淀成可评价、可展示、可交付的作品。**

现场证据顺序：

1. 学校课程包和教师培训方案。
2. 教师从课时布置 AIGC 实训任务。
3. 学生用无限练习/画布/故事板完成角色、分镜和视频。
4. 教师反馈和学生修改。
5. 企业题目进入商单实训，学生提交候选成果。
6. 作品、版本、验收和后续就业/项目展示。

模型名称、后台渠道、内部规划提示词和积分实现只作为必要说明，不作为主叙事。

### 创作工具竞品不会自动改变我们的 P0

即梦、可灵、通义万相、海螺、LiblibAI、芒果灵创等工具越强，越需要 VOZEB 证明“为什么学校要买方案”：工具能力被放进课程目标和专业工作流；教师能布置、查看、批改和反馈；学生有过程记录和作品集；企业能提供题目并验收版本；学校能管理账号、额度、版权、数据和实施服务。

因此 10/22 不建议扩展“再增加更多模型/工具入口”的 P0；优先把已有图片、视频、画布和故事板能力做成可教学、可交付的完整路径。

| 作品广场 | 分类/标签、精选/最新/热门、作品详情、作者主页、点赞关注、审核治理 | 有社区基础，但缺少“作品如何证明课程和生产价值”的展示结构 | **内容结构改版** | 案例卡展示专业/课程/项目/能力标签；详情展示制作过程与版本，但不泄露内部提示词 | 内容运营+售前，P0 |
| 商单实训与交付 | 商单要求、候选成果、正式交付、反馈、验收状态 | 真实端到端环境和客户审阅方式仍需验收 | **路径改版** | 任务要求和媒体版本并排；状态从候选到验收可追溯；先不扩展独立门户 | 售前+制作，P0 |
| 统一 Agent | 文本/图片/视频/音频、参考素材、规划、历史和重试 | 对高校学生容易过于自由，对课程目标约束不足 | **场景化改版** | 课程/任务进入时带目标和允许能力；普通自由 Agent 保留；不让学生先挑模型 | 教研+产品，P1 |
| 导航与角色 | 普通用户、学校角色、练习、创作、项目、资产、社区入口均有 | 入口多，学校用户和生产用户看到的导航不够任务化 | **角色改版** | 学生/教师/制作/售前展示不同首页任务；模型/系统设置不进入第一层 | 产品+设计，P0 |

## 当前阶段结论

## 中国高校/职校客户视角的现有功能评估

中国市场的“现有功能是否要改版”不能只看页面是否能打开，还要问它能否进入学校采购、教师使用和企业实训。按中国平台常见结构重新检查：

| 客户期待 | VOZEB 当前对应功能 | 现状判断 | 改版/补齐动作 | 优先级 |
| --- | --- | --- | --- | --- |
| 学校有一套可复制的专业课程 | 平台课程、章节、课时、资料、学校分配 | **已有骨架，缺专业化内容** | 先交付动漫/AIGC 样例课，补专业、岗位能力、课时目标、课件、练习、作业和评价标准 | P0 |
| 教师课前/课中/课后组织教学 | 教学中心、课程、作业、提交、反馈 | **功能有，流程分散** | 改成教师待办工作台；课前资料、课中练习、课后作业/反馈一条路径 | P0 |
| 学生有明确学习下一步 | 学习中心、课时、作业、实训、反馈 | **入口有，任务优先级弱** | 首页按待完成/需修改/已通过排序，从课时直接进入无限练习并回传成果 | P0 |
| 学校需要资源与版权治理 | 课程资料、素材库、媒体登记、作品治理 | **底层有，页面口径不足** | 展示平台/学校/学生来源、授权、可见范围、引用关系；不把临时模型素材当课件 | P0 |
| 教师看教学成效 | 作业状态、提交、批改；暂无面向院校的完整教学分析页 | **待改版** | 10/22 先展示任务完成/作品提交/反馈状态；班级进度与能力数据列 P1 | P0/P1 |
| 学校要有管理员治理 | 学校成员、班级、课程安排、权限 | **已有基础，需售前验收** | 准备学校管理员演示账号和跨校数据隔离证据；补部署、培训、数据导入导出口径 | P0 |
| AIGC 要服务专业实训 | 无限练习、Canvas、短剧、统一 Agent | **创作能力多，课程上下文弱** | 课程/作业带目标和允许能力进入练习；学生不先选模型，结果回到任务 | P0 |
| 企业要参与项目评价 | 商单任务、候选成果、正式交付、反馈/验收 | **模型有，真实校企链待验收** | 以一个动漫任务跑通学校/教师/学生/企业反馈；突出版本和验收标准 | P0 |
| 学校要购买服务而非单点工具 | 师陪、平台、课程的概念已有，采购口径未冻结 | **售前方案未定** | 组合成“课程共建 + 平台空间 + 教师培训/陪跑 + 项目实训”三档试点包 | P0 |
| 平台要能规模化运营 | 任务、媒体、积分、模型渠道、备份、审计 | **工程基础较多，现场价值难见** | 售前只展示稳定结果、数据边界和服务能力；后台模型/支付细节下沉 | P1 |

### 中国市场下的直接取舍

- **不与国家智慧教育、智慧职教、超星正面比资源规模**：VOZEB 应突出“动漫/AIGC 专业实训 + 真实内容生产 + 校企任务交付”。
- **不与雨课堂正面比课堂互动工具**：VOZEB 重点补齐课堂课件之后的创作练习、作品提交、教师反馈和企业验收。
- **不与学堂在线正面比高校课程数量和学分生态**：先做可复制的专业样例课、校内项目和作品结果。
- **不把学堂 AI 或 EduAI 的 AI 入口原样搬来**：VOZEB 的差异应是“课程任务驱动的生成、画布/故事板产出、教师评价、企业交付”。
- **不把校企合作写成一句口号**：必须有一个真实企业题目、学生成果、教师反馈、企业验收和版本记录。

### 已有基础（可进入真实验收）

- 学校租户、成员、班级、课程分配和课程树。
- 学生学习中心、教师教学中心、作业提交与批改状态。
- 无限练习入口与练习模块，Canvas 节点式生成基础，短剧项目和分镜实体。
- 作品广场、作品详情、创作者主页、作品审核治理。
- 商单任务、候选成果、正式交付和反馈状态模型。

### 必须先做真实验收再写“已支持”

- 真实高校样例课件的展示、权限、资料预览和版权口径。
- 课程进入练习、练习结果回到作业/作品的完整链路。
- Canvas 真实图片/视频质量、刷新恢复、失败重试和结果归属。
- 分镜图→视频、批量任务、部分失败、成片合成和生产环境媒体。
- 商单端到端学校/教师/学生/企业角色流转。
- 中国高校/职校最小采购证据：样例课、学校管理员、教师任务、学生作品、企业反馈、版权与数据边界。

### 明确属于改版或新增

- 高校角色化首页与课程任务首页。
- 课件/能力目标/练习/评价标准的统一课时页面。
- 多分镜图推故事的独立产品契约和交互。
- 白模推进动画的定义、样片和实现方案。
- 社区作品与课程能力/生产案例的关联展示。
- 面向高校/职校的课程包、教师培训、师陪服务、校企实训组合方案。

### 建议的 10/22 版本冻结顺序

1. **先冻结高校样例课和一条真实教学闭环**：没有课件、目标、任务和评价标准，学校部分不进入 P0 视觉改版。
2. **再冻结制作案例**：角色/场景/3–5 镜分镜/至少一段视频，确认画布和短剧现有链路能跑通。
3. **再改入口顺序和页面文案**：让客户先看到课程任务和真实结果，模型参数下沉。
4. **最后补社区案例和售前价值页**：只放已授权、已验证、能回到项目/课程来源的作品。

任何新增功能若没有输入、输出、状态、真实证据和失败兜底，不进入 10/22 的“平台已支持”口径。

## 10/22 前的最小交付包

1. **一门课**：课程、课时、课件、任务、评价标准由教研签字。
2. **一个故事**：有授权的角色、场景、3–5 个分镜图、至少一段真实视频，由制作签字。
3. **一条平台路径**：学生练习与提交、教师反馈、作品展示或商单交付，由产品/研发真实验收。
4. **一套售前口径**：师陪、平台、课程、内容生产各自提供什么价值和采购方式，由售前签字。
5. **一份彩排证据**：桌面投屏尺寸和移动端查看、浅深主题、刷新恢复、失败兜底、模型/网络波动记录。

## 会上需要立即改变优先级的条件

- 若画布或视频上游无法在真实账号稳定产出，先保 P0 主路径与预生成平台结果，暂停依赖实时视频的 UI 扩展。
- 若教研拿不出课程内容和评价标准，课程视觉改版不进入 P0；先完成样例内容。
- 若制作确认“多图推故事”是核心销售承诺，需要先定可验收输入输出和上游能力，再重排 P0，而不能只画效果图。
- 若白模推进已有可用制作样片和真实技术方案，可重新评估交付优先级；否则它是需求定义，不是已完成能力。
