# VOZEB PRO 需求对齐会与 10 月 22 日动漫集团推广会准备方案

> 文档状态：会前工作稿
> 
> 建议会议主持：产品负责人
> 
> 建议会议对象：产品、教研、内容制作、销售；研发/设计列席记录可行性与依赖
> 
> 计划使用日期：2026-10-10 起，服务 2026-10-22 动漫集团推广会

## 1. 会议结论先行

本次会议不是把所有想法逐条过一遍，而是完成四个决策：

1. **确定 10 月 22 日现场要展示的单一闭环**：学校/教师进入平台，学生完成一次无限练习，形成可交付内容，教师或企业角色完成反馈/验收，最后展示作品与平台价值。
2. **确认产品改版、前端改版、新功能的优先级**：按 P0（推广会和核心销售闭环）、P1（推广会后首个版本）、P2（验证后再做）分层，并为每项指定负责人和验收标准。
3. **确认教育业务与内容生产业务的关系**：课程是教学载体，无限练习是能力训练，商业模型需要在会议中明确是“平台收费/积分/套餐”还是“商单实训/商业生产”，也可能是两者都要覆盖。
4. **冻结推广会展示口径与 UX 原则**：现场展示什么、不展示什么、遇到失败如何降级、销售如何描述，不再由现场临时发挥。

### 建议的现场主叙事

> **平台把课程、练习、教师指导和真实内容生产连成一条链。学生学完能练，练完能交付，教师能教能评，学校能管理，企业能看到结果。**

这条叙事比“我们有很多模型和工具”更适合高校、职校和动漫内容制作方，也能把无限练习与商业生产放到同一个业务闭环中。

## 2. 已知业务逻辑与需要确认的词义

### 2.1 当前业务假设

| 业务层 | 当前理解 | 会议需要确认 |
| --- | --- | --- |
| 客户 | 对接高校、职业院校；学校购买或使用平台与课程，教师组织教学，学生完成训练 | 主要付费主体是学校、企业还是个人；是否允许混合采购 |
| 师陪 | 通过教师、教研或平台服务陪伴学习与生产 | 是“师资陪跑服务”、教师工作台，还是另一个独立产品包 |
| 平台 | 提供账号、学校租户、课程、教学任务、作品、素材、模型和运营能力 | 交付的是 SaaS 账号、私有化部署、服务包，还是组合方案 |
| 课程 | 平台标准课程可分配到学校；学校安排班级和教师；教师布置课时、作业和实训 | 课程是否按专业/岗位/项目制组织；是否需要证书或学分记录 |
| 无限练习 | 学校成员使用的免费创作练习，包含剧本、角色、场景、道具、分镜图、分镜视频、音频，以及无限画布/短剧项目 | “无限”是额度免费、模型免费，还是只表示练习入口不限制次数；哪些模块是推广会重点 |
| 商业模型 | 目前存在两种合理解释：平台套餐/积分/支付的商业化模型；学校中的商单实训/商业内容生产模型 | 本次会议必须先定词义和展示对象，避免销售、教研、产品各说一套 |

### 2.2 现有系统能力事实

仓库当前已具备以下业务链路，可作为会议的事实底座：

- 统一创作 Agent：文字、图片、视频、音频、参考素材、智能规划、逻辑模型和历史恢复。
- 无限练习：独立练习模块、无限画布、无限短剧、剧本练习、角色/场景/道具/分镜图/分镜视频/音频模块、练习历史。
- 学校教学：平台课程、章节/课时、学校课程分配、班级与教师安排、教师创建作业、学生提交成果、教师批改与退回修改。
- 商业实训：商单要求、验收标准、参与学生、候选成果、正式交付、平台反馈和状态流转。
- 内容生产：Canvas 节点式编排、短剧剧本/审核/分镜/镜头生成/音频/合成、素材库、提示词库、作品发布。
- 商业运营：套餐、积分、订单、支付、退款、用户、模型渠道、存储和审计后台。

内部依据：`README.md`、`docs/content/docs/overview/features.mdx`、`docs/content/docs/overview/page-gallery.mdx`、`web/src/app/(user)/practice/`、`web/src/app/(user)/learning/`、`web/src/app/(user)/teaching/`。

## 3. 外部对标调研

以下正式对标只记录本次通过浏览器核验的公开页面。EduAI 的部分教学入口需要登录，未登录状态只能核验入口与工作流列表，不能据此断言课内流程已经实现。产品建议是我们的取舍判断，不等于竞品已有同样能力。竞品的品牌、文案、图标、字体和视觉 token 不直接复制到 VOZEB PRO。

### 3.1 对标结论表

| 系统 | 公开可见的功能/UX证据 | 可借鉴到 VOZEB PRO | 不建议直接照搬 |
| --- | --- | --- | --- |
| **EduAI 工作流** | 侧边栏按“教学 / 创作 / 探索”分组；教学下有 AIGC 学堂、素材广场、工作流、模型广场、教程专区、我的资产；创作下有 ComfyUI 工作流、创作工具、时空画布；探索下有创作任务、AIGC 赛事、合作院校。工作流页支持搜索、专业筛选、分类筛选、标签筛选，专业覆盖动漫制作、影视制作、短剧、数字媒体等。 | 用业务分区帮助学校用户理解平台；用“专业 → 工作流 → 作品”组织内容；为动漫/数字媒体专业提供可复用工作流和示例。 | 不把导航扩成大量平铺入口；不为了看起来丰富而先建设赛事、模型广场等非核心模块；不让用户先理解模型再开始任务。 |
| **Google Assignments / Workspace for Education** | 官方强调在 LMS 中分发、分析和批改学生作业；支持模板副本、集成量规、评论库、原创性报告、隐私和 LTI 集成。 | 教师工作台应围绕“布置 → 提交 → 反馈 → 修改 → 再提交”闭环；把验收标准结构化，而不是只存一段文字；推广会展示教师如何节省批改时间。 | 不在本期自建完整 LMS 或原创性检测；先把创作成果引用、版本、反馈和状态做好。 |
| **Runway Creative** | 官方将图片、视频、音频生成和编辑放进一个云端 Creative Suite；同时提供 Agent、Workflows、Enterprise 和模型/API 入口，按个人、团队、企业分层。 | 保持“一个创作入口 + 多种生产能力”；把复杂模型选择隐藏在规划和能力匹配后；把企业销售看到的团队协作、工作流和可交付结果放在前面。 | 不把平台改成单纯模型广场；不同时展示所有模型参数；不承诺未被真实业务验证的模型能力。 |

**延伸参考，尚未完成本次页面核验**：Canva for Education 可用于讨论“模板降低学生上手成本”，Frame.io 可用于讨论“媒体审阅与版本反馈”，Moodle / Open edX 可用于讨论“课程与学习进度的信息架构”。这些方向暂不作为本次对标的事实结论，也不据此提出 P0 需求。

### 3.2 对标后的产品判断

1. **主导航应按角色和任务组织，不按模型组织**：学校用户先看到课程、班级、练习、作品和任务；模型是后台能力，不是首页的第一层信息。
2. **核心价值是教学与生产的闭环**：无限练习不能只是工具集合，至少要能从课程任务进入、保存成果、提交给教师或企业验收。
3. **统一 Agent 的价值是降低选择成本**：现场演示不应花时间解释模型目录、协议、通道或内部规划。
4. **教学反馈要可见、可追踪**：状态、截止时间、反馈、修改和最终通过应形成清晰的状态链。
5. **商业价值要由结果证明**：销售材料应展示“学校如何开课、学生如何练、教师如何评、企业如何验收”，而不是只展示生成速度。

## 4. 本次会议要对齐的用户路径

### 路径 A：教师组织一门动漫实训课

1. 选择平台课程或本校课程。
2. 选择班级、教师和课时/作业/商业实训任务。
3. 给出任务说明、参考素材和验收标准。
4. 查看学生提交的图片、视频、画布或短剧成果。
5. 用结构化反馈退回修改或确认通过。

### 路径 B：学生完成一次无限练习

1. 从课程课时或教师作业进入无限练习。
2. 选择角色、场景、道具、分镜或短剧工作流。
3. 使用平台默认能力生成或编辑，不要求先理解模型。
4. 保存成果到素材/作品库。
5. 从作业或实训任务中引用成果并提交。
6. 收到反馈后修改、再次提交，形成作品记录。

### 路径 C：销售向动漫集团展示平台价值

1. 用一个真实动漫内容案例说明客户问题。
2. 展示学校课程如何配置到班级和教师。
3. 展示学生从练习到作品的最短路径。
4. 展示教师反馈和企业验收如何进入系统。
5. 展示作品、版本和交付结果。
6. 最后再说明平台部署、课程服务、师陪服务和商业化方案。

## 5. 10 月 22 日推广会展示范围

### 5.1 建议的 12–15 分钟演示脚本

| 时间 | 演示内容 | 观众应得到的结论 |
| --- | --- | --- |
| 0:00–1:00 | 动漫集团真实/脱敏案例：从课程训练到内容交付 | 这是产教融合生产平台，不是单点 AI 工具 |
| 1:00–2:30 | 以学校教师身份进入，看到课程、班级、任务和待处理事项 | 教师能组织教学，不需要自己拼系统 |
| 2:30–5:30 | 从一项课时/实训任务进入无限练习，选择一个动漫工作流，生成角色/场景/分镜成果 | 学生能在任务上下文中完成创作练习 |
| 5:30–7:00 | 保存成果并提交；展示任务状态、素材引用和版本 | 成果可追踪，不是生成后散落在本地 |
| 7:00–9:00 | 教师查看提交、给出反馈、退回修改或通过 | 教师有明确的教学闭环和评价依据 |
| 9:00–11:00 | 以商业实训/企业任务展示要求、参与人、候选成果、交付和反馈 | 学生训练能连接真实生产，学校能承接项目 |
| 11:00–13:00 | 展示作品/版本/成片和可复用课程工作流 | 平台能沉淀作品和课程资产 |
| 13:00–15:00 | 说明师陪、平台、课程的合作方式与下一步试点 | 销售能把产品能力转成采购方案 |

### 5.2 P0：推广会前必须稳定的内容

- 一套脱敏且可重复执行的学校账号、教师账号、学生账号和企业/管理员视角。
- 一条从“课程任务 → 无限练习 → 成果保存 → 提交 → 教师反馈 → 修改/通过”的真实链路。
- 一个动漫相关的工作流或短剧/分镜案例，使用已准备好的参考素材和已验证的模型能力。
- 结果页能清楚展示：作品、任务状态、版本、反馈、下一步动作；不展示内部规划提示词或模型推理。
- 演示过程有明确的加载、失败和降级方案，不能依赖临时手工改库或现场输入长提示词。
- 所有展示数据已脱敏，媒体版权、人物肖像、字体和品牌使用范围已确认。
- 销售能用一页话术解释：学校买什么、学生得到什么、教师省什么时间、企业得到什么结果。

### 5.3 P1：推广会后首个产品版本

- 角色化首页：学生、教师、学校管理员、企业/销售看到不同的下一步任务。
- 课程模板与动漫专业工作流模板，可复制到班级和作业。
- 结构化验收标准、评分维度、反馈模板和版本对比。
- 作品/成果的统一交付页，支持查看引用来源、版本和最终状态。
- 教师侧的班级进度与任务汇总，销售侧的试点数据摘要。
- 商业模式确认后的套餐、积分、学校采购或商单结算页面。

### 5.4 P2：先不承诺日期的能力

- 完整模型广场、开放工作流市场、赛事体系和社区运营。
- 完整 LMS、学分/证书、原创性检测和复杂教务系统。
- 大规模企业协作、复杂审批、自动排产和跨校数据分析。
- 尚未经过真实上游和真实学校场景验证的模型、参数或自动化承诺。

## 6. 会议议程（建议 120 分钟）

| 时间 | 环节 | 主持人 | 必须产出 |
| --- | --- | --- | --- |
| 00–10 分钟 | 目标、范围和决策规则 | 产品 | 确认今天只决定需求、优先级和 10/22 展示，不现场发散实现细节 |
| 10–25 分钟 | 业务模型复述 | 产品 + 销售 | 确认师陪、平台、课程、无限练习、商业模型的定义和购买关系 |
| 25–45 分钟 | 三类用户路径 | 教研 + 产品 | 画出教师、学生、销售/企业各自的关键路径和断点 |
| 45–60 分钟 | 现有系统能力演示 | 产品/研发 | 对照现有页面确认“已有、半成品、缺失、不可现场承诺” |
| 60–75 分钟 | 竞品与 UX 取舍 | 产品 | 对 EduAI、Google Assignments、Runway 形成借鉴/不借鉴清单；延伸案例仅作提问素材 |
| 75–95 分钟 | 10/22 展示脚本定稿 | 内容制作 + 销售 | 冻结案例、角色、素材、操作路径、演示时长和兜底方案 |
| 95–112 分钟 | 需求分级 | 全体 | 每项需求定 P0/P1/P2、负责人、依赖、验收标准 |
| 112–120 分钟 | 决议复述与行动项 | 产品 | 输出决策日志、待确认问题、截止时间和下一次检查会 |

### 会议主持规则

- 先问“服务哪个用户、解决哪个业务问题、10/22 是否需要”，再讨论页面长什么样。
- 没有用户、场景、结果和验收标准的想法先进入待澄清区，不直接进入 P0。
- “竞品有”不能直接成为需求；必须说明对 VOZEB 的业务价值、成本和展示价值。
- 任何影响现场稳定性的改版，优先保证演示闭环和可回退方案。
- 争议超过 5 分钟时，记录为 A/B 方案、负责人和验证方式，不在会上靠职位拍板。

## 7. 四个部门的准备材料与发言重点

### 产品部门（主持）

- 带一张现有能力地图：课程、练习、创作、提交、反馈、作品、商业运营。
- 带一份待改版/待新增清单，提前标出依赖、风险和预计工作量区间。
- 准备 10/22 演示脚本的可点击路径、账号、数据和兜底。
- 现场逐条确认决策，不替其他部门猜业务规则。

### 教研部门

- 提供 1 个动漫相关课程/课时/作业样例，包含学习目标、步骤、参考素材和验收标准。
- 明确学生应练什么能力：角色设定、场景设计、分镜、视频镜头、配音还是完整短剧。
- 明确教师需要看什么：过程、结果、版本、提示词、素材引用、协作记录还是岗位能力。
- 定义“合格、需修改、不合格”的最小评价标准。

### 内容制作部门

- 准备一套可公开展示或已获授权的角色、场景、道具、分镜、视频和音频素材。
- 确认现场案例的视觉风格、画幅、时长、成片版本和下载/播放方式。
- 提供“初稿 → 反馈 → 修改稿 → 最终稿”的对照材料。
- 标记哪些内容是演示固定素材，哪些内容必须现场实时生成。

### 销售部门

- 提供动漫集团及高校/职校客户最常问的 5 个问题和采购阻力。
- 明确客户购买对象：师陪、平台、课程、模型额度、内容制作服务或组合包。
- 给出现场必须出现的价值证据：培训效率、教师工作量、学生作品、企业交付、部署方式、价格口径。
- 不能把尚未确认的功能、模型、效果、交付周期和合规能力写成承诺。

## 8. 需求优先级与决策模板

### 8.1 优先级规则

| 等级 | 判断标准 | 处理方式 |
| --- | --- | --- |
| P0 | 不做就无法完成 10/22 核心演示，或会让客户误解平台价值；且能在演示前验证 | 立即进入展示版本，冻结范围，指定单一负责人 |
| P1 | 明显提升学校试点和首个交付版本价值，但不影响 10/22 主链路 | 排入推广会后版本，先做方案和验收标准 |
| P2 | 对长期规模化、生态或运营有价值，但当前无客户验证或依赖较重 | 建立候选池，不承诺日期，不占用 P0 资源 |

### 8.2 会议现场逐条填写

| 字段 | 说明 |
| --- | --- |
| 需求 ID | 如 EDU-P0-001 |
| 提出部门/负责人 | 只保留一个最终业务负责人 |
| 用户 | 学生、教师、学校管理员、企业、销售、内容制作等 |
| 触发场景 | 在什么任务、页面或客户沟通中发生 |
| 当前问题 | 现有系统哪里断、慢、难理解或无法验收 |
| 目标结果 | 用户完成什么动作，平台留下什么证据 |
| 竞品参考 | 参考哪个系统的哪种模式，为什么适用 |
| 10/22 是否展示 | 是/否；如是，放在哪个演示步骤 |
| 优先级 | P0/P1/P2 |
| 依赖与风险 | 数据、模型、媒体、权限、版权、研发或设计依赖 |
| 验收标准 | 页面状态、操作成功、结果字段、演示时长和失败兜底 |
| 截止时间 | 设计冻结、开发完成、联调、彩排、最终验收 |

### 8.3 建议的量化判断

当多个需求都声称 P0 时，用四项各 1–5 分打分：

- 客户价值：是否直接影响学校/动漫集团是否理解并认可方案。
- 演示必要性：是否属于主叙事不可替代步骤。
- 可验证性：能否在 10/22 前用真实账号、数据和操作证明。
- 交付风险：依赖越少、回退越明确，分数越高。

总分只用于排序，不能替代业务判断；有安全、版权、数据隔离或客户承诺风险的事项，即使分数高也不能直接进入现场。

## 9. 需要在会议上明确拍板的问题

1. “商业模型”本次是指平台收费/积分/套餐、商单实训/内容交付，还是两者都要；若两者都要，10/22 先展示哪一条。
2. 10/22 的主要观众是动漫集团管理层、内容制作人员、院校负责人、教师，还是混合 audience；谁是第一决策人。
3. 现场是否必须实时生成，还是允许使用预生成结果；哪些步骤必须实时操作才能证明平台价值。
4. 演示采用一个课程实训案例，还是同时展示课程、商单和自由创作三个入口。
5. 学生提交成果时，教师需要看到哪些过程证据；企业验收是否需要独立状态、版本和反馈记录。
6. 师陪服务交付什么：教师培训、课程共建、课堂陪跑、项目导师、内容制作服务，还是上述组合。
7. 学校采购按账号、学校、课程、服务期、生成额度、项目交付还是组合包计价。
8. 哪些模型、媒体、IP、人物和课程资料已取得展示授权；哪些只能内部演示。
9. 现场失败时的降级顺序是什么：预生成结果、备用模型、静态截图、录屏或讲解。
10. 推广会后首个版本的发布日期、负责人和验收会议是什么时间。
