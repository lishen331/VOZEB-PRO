# RunningHub 工作流编号核验与运维配置手册

## 1. 这份手册解决什么问题

这份手册把四个 RunningHub Workflow ID 的核验结果和上线后的后台操作步骤固定下来。验收时必须区分以下三个状态：

| 状态 | 证明了什么 | 是否能作为“平台可调用”结论 |
| --- | --- | --- |
| 已读取 JSON | ID 存在，当前 API Key 有权读取工作流定义 | 不能 |
| 已保存平台配置 | 平台知道如何把业务输入映射到节点 | 不能 |
| 真实样例任务成功 | 创建、查询、结果解析和媒体下载均成功 | 可以 |

当前核验只做了第一层：四个 ID 均能从当前 RunningHub 渠道成功读取 JSON。由于没有为这四个工作流提交真实样例任务，因此它们目前不能标记为“已跑通”。真实可调用结论必须在完成第 6 节的样例测试后再下。

## 3. 四个工作流的接入注意事项

### 3.1 `2079446871415808002`：分镜视频生成

这是一个包含 LTXV 图生视频、可选音频分支和视频保存节点的工作流。JSON 中存在默认图片文件和默认音频文件，文件只在原作者的 RunningHub 环境中可见，不能直接作为平台用户输入。

首次接入建议只开启“无音频视频”路径：

1. 将 `373.value` 映射为“提示词”。
2. 将 `269.image` 映射为“参考图”，样例测试必须上传真实图片并覆盖默认文件名。
3. 将 `380.value` 保持为 `false`，先不暴露参考音频输入。
4. 将 `355.value` 作为“视频时长”候选；宽高节点 `366`、`353` 是否开放，需根据自动识别结果由运维确认。
5. 将 `75` 的视频结果设为主输出。

如果后续确实要开放视频内置音频，再单独把 `386.audio` 识别为“参考音频”，上传真实音频并重新做样例测试。不要为了让任务提交成功而保留原作者的文件名。

### 3.2 `2090436770948272130`：分镜台词音频合成

这是 IndexTTS 多角色合成工作流，默认包含十个角色槽位，其中部分槽位是 `None`，部分槽位引用了原作者的示例音频。它不是单个“输入一段文字就结束”的简单工作流。

一期建议配置为：

1. 将 `87.text` 映射为“台词文本”，保留工作流原有的角色标记格式（例如 `[s1]`）。
2. 对外只开放实际要使用的角色槽位，例如 `s1`、`s2`；每个槽位对应一个“参考音频”上传项。
3. 未使用的角色槽位保持关闭或使用工作流默认的空值，不能让用户误以为必须上传十个文件。
4. 将 `90` 作为主音频输出，`86` 仅作为预览候选。
5. 样例测试必须使用平台上传的真实参考音频，不能引用 JSON 中的示例文件。

如果后台自动识别无法判断角色数量，运维必须在候选列表中手动确认“需要几个参考音频”，而不是修改整段节点 JSON。

### 3.3 `2090436537182932994`：分镜图/多参考图生图

该工作流有一个提示词节点和多个 `LoadImage` 节点，并通过 ReferenceLatent 参与图像生成。`13`、`20`、`24` 当前都有默认文件名，`48` 为空；因此应按“多张参考图”处理，而不是误判成纯文生图。

接入顺序：

1. 将 `35.text` 映射为“提示词”。
2. 让自动识别器列出 `13.image`、`20.image`、`24.image`、`48.image`，由运维确认哪些是必填参考图、哪些是可选参考图。
3. 样例测试至少覆盖确认后的全部必填图片槽位，且每个槽位都替换为本次上传的真实图片。
4. 将 `29` 作为主图片输出。
5. 工作流中固定的 `1080×1920`、`1920×1920` 是上游节点参数，不应在后台强行改写成平台统一尺寸；是否开放为用户参数由工作流实际支持情况决定。

### 3.4 `2090436220538150914`：道具主视图/参考图编辑

这是相对简单的单图编辑工作流：`35.text` 为文本，`13.image` 为参考图，`67` 为输出图片。它适合作为第一个新增图片工作流的真实样例。

配置时：

1. 将 `35.text` 映射为“编辑提示词”。
2. 将 `13.image` 映射为“参考图”，测试时上传实际图片。
3. 将 `67` 设为图片主输出。
4. `65` 中的 `720×1280` 仅作为上游默认值；用户没有锁定尺寸时，不要在平台层统一覆盖比例。

## 4. 执行前检查

开始配置前，平台管理员准备：

- 一个有 `upstream.manage` 权限的管理员账号。
- 当前 RunningHub 渠道的有效 API Key。密钥只在后台输入，不能写进工作流备注、请求模板或测试数据。
- 一张可公开上传给 RunningHub 的 PNG/JPG 测试图，用于图片和视频工作流。
- 至少一段 WAV/MP3 参考音频，用于配音工作流；多角色工作流按已确认的角色数量准备多段音频。
- 一段短的中文提示词或台词，便于快速定位失败原因。

测试素材要有明确文件名，例如 `rh-test-reference.png`、`rh-test-voice-s1.wav`，不要使用工作流 JSON 中的默认文件名。

## 5. 后台一步一步配置

以下流程以完成自动发现方案后的后台界面为准。普通运维人员不需要填写创建路径、查询路径、任务 ID 字段、状态字段、结果字段或完整 `nodeInfoList` JSON。

### 5.1 配置一次 RunningHub 渠道

1. 登录平台管理员后台。
2. 进入“上游配置 → 模型渠道”。
3. 新建或打开 RunningHub 渠道。
4. 填写“渠道名称”，例如“RunningHub 开源练习”。
5. 填写 Base URL：`https://www.runninghub.cn/`。
6. 协议选择 RunningHub；用途选择“无限练习”或“共享”。
7. 粘贴 API Key 并保存。保存后页面只显示脱敏状态，不回显完整密钥。
8. 点击“连接检查”。连接检查只调用工作流 JSON 接口，不创建 GPU 任务，不消耗生成额度。
9. 看到“渠道可用”后再进入工作流配置。如果连接检查失败，先修复地址、密钥或网络，不要继续填写节点映射。

官方协议由系统固定：

| 用途 | 方法和路径 |
| --- | --- |
| 读取工作流 | `POST /api/openapi/getJsonApiFormat` |
| 创建任务 | `POST /task/openapi/create` |
| 查询任务 | `POST /openapi/v2/query` |
| 上传媒体 | `POST /openapi/v2/media/upload/binary` |

这些路径不能由普通运维人员修改。

### 5.2 新建一个工作流配置

每个工作流 ID 建一个独立配置。四个 ID 按以下顺序接入，建议先做 `2090436220538150914`，再做 `2090436537182932994`、`2079446871415808002`，最后做多角色配音。

1. 在 RunningHub 工作流列表点击“新建工作流”。
2. 填写平台显示名称，例如“道具主视图”“分镜多参考图”“分镜视频（LTXV）”“分镜台词配音”。
3. 选择刚配置的 RunningHub 渠道。
4. 粘贴纯数字 Workflow ID。也可以粘贴完整 RunningHub 工作流链接，由系统提取数字 ID；不要填写 `workflow-boogu-image-edit` 这类平台逻辑模型名代替上游 ID。
5. 选择能力类型：图片、视频或音频。
6. 选择业务用途。业务用途由运维确认，不由节点标题自动决定。
7. 点击“读取工作流”。
8. 等待页面展示工作流摘要：节点数、输入候选、输出候选、默认文件依赖和警告。
9. 在“业务输入确认”中确认每个字段：用户可见名称、类型、是否必填、默认值和参考素材角色。
10. 在“输出确认”中选择主输出。一个工作流至少要有一个可解析的图片、视频或音频输出。
11. 检查默认文件警告。凡是 `LoadImage`、`LoadAudio` 等节点带有原作者文件名的，都必须改为“测试时上传替代素材”，不能直接保存为永久输入。
12. 点击“保存草稿”。保存后列表状态应为“已停用/草稿”，不能直接进入前端。

### 5.3 保存前的最小确认清单

每个工作流都必须逐项确认：

- Workflow ID 是当前要接入的数字编号。
- 能力类型与真实输出一致。
- 提示词字段只选择一个明确候选；存在多个候选时不能静默选第一个。
- 所有必填图片、视频和音频槽位都有用户可上传的替代输入。
- 输出节点能映射到图片、视频或音频结果。
- 默认文件、私有路径和失效外部链接已被标记。
- 页面没有要求运维手写完整 JSON。

### 5.4 提交真实样例测试

1. 在工作流列表找到刚保存的配置，点击“测试运行”。
2. 按确认后的输入契约填写样例数据：提示词、参考素材、时长、角色音频等。
3. 对每一个参考素材使用“上传本地文件”，不要填写 JSON 中的默认文件名。
4. 点击“提交样例测试”。这一步会真实创建 RunningHub 任务，可能消耗上游额度。
5. 看到平台返回 `taskId` 后，等待测试面板显示上游状态。
6. 任务完成后检查：状态为成功、结果 URL 存在、平台可以下载或预览、结果类型与能力类型一致。
7. 视频额外检查能播放并显示合理时长；图片额外检查能显示真实宽高；音频额外检查能试听。
8. 测试失败时只根据面板的可执行建议修改输入或映射，然后重新提交一次测试。不要直接改协议路径。
9. 只有出现“样例测试成功”才允许启用工作流。

### 5.5 启用并绑定到无限练习

1. 测试成功后点击“启用”。
2. 系统检查当前配置存在成功测试证据；没有成功证据时拒绝启用。
3. 将工作流绑定到对应的逻辑模型和业务 code：
   - 图片工作流绑定到图片练习或 Canvas 对应的逻辑模型。
   - `2079446871415808002` 绑定到“分镜视频练习”的视频逻辑模型。
   - `2090436770948272130` 绑定到“配音练习”的音频逻辑模型。
4. 如果同一能力有多个已测试工作流，每个工作流使用独立逻辑模型名称，前端让用户在支持的模型列表中选择；不要用一个逻辑模型覆盖多个不同工作流。
5. 从列表确认状态为“已启用”，最近测试为“成功”。
6. 如果停止使用，点击“停用”。停用只阻止新的业务调用，仍可编辑、重新读取 JSON 和测试，不删除测试记录。

## 6. 前端完整验收：从点击到结果

后台样例测试成功后，还必须用实际学校账号走一遍前端，因为这一步能发现逻辑模型绑定、业务 code、权限和结果展示问题。

### 6.1 分镜图练习

1. 使用已绑定学校的老师或学生账号登录。
2. 进入“项目 → 无限练习 → 分镜图练习”。
3. 选择刚启用的图片逻辑模型。
4. 输入一段明确的画面描述。
5. 按工作流契约上传所需的参考图；没有参考图的工作流不应强制显示上传槽位。
6. 点击“开始练习”。
7. 检查任务进入现有结果组件，状态从处理中转为成功或明确失败。
8. 成功时检查图片可预览、可下载、宽高信息正常；失败时检查错误信息能指向输入、上游或映射问题。

### 6.2 分镜视频练习

1. 进入“项目 → 无限练习 → 分镜视频练习”。
2. 选择已绑定的 `2079446871415808002` 视频逻辑模型。
3. 上传一张真实参考图，输入短视频提示词，设置工作流允许的时长。
4. 点击生成。
5. 检查平台创建的请求包含提示词和本次上传图片，不包含原作者的默认文件名。
6. 检查状态查询成功，最终结果为 MP4 或工作流声明的实际视频格式。
7. 检查页面能播放视频，播放控件、时长和结果下载入口可用。
8. 刷新页面或重新打开练习记录，确认结果仍由现有任务结果组件恢复，而不是只存在于浏览器临时状态。

### 6.3 配音练习

1. 进入“项目 → 无限练习 → 配音练习”。
2. 选择已绑定的音频逻辑模型。
3. 输入带角色标记的短台词，并上传已确认角色的参考音频。
4. 点击生成。
5. 检查任务状态和音频输出，点击试听。
6. 若工作流暂时只开放 `s1`、`s2`，页面不能要求上传 `s3` 到 `s10` 的文件。

## 8. 常见失败与处理顺序

| 现象 | 优先检查 |
| --- | --- |
| 读取 JSON 返回 401/403 | 渠道 API Key、渠道地址、RunningHub 权限 |
| 读取成功但测试提交失败 | 必填输入是否都已上传，节点映射是否确认 |
| 提交成功但很快失败 | 默认文件未替换、节点依赖缺失、工作流本身在 RunningHub 不可运行 |
| 返回 taskId 但一直没有结果 | 查询路径和状态字段解析、上游任务实际状态 |
| 结果状态成功但页面无媒体 | 输出节点或结果字段映射错误、媒体 URL 解析失败 |
| 视频能生成但无声音 | `380` 音频开关、`386` 参考音频和音频分支是否被确认 |
| 多角色配音缺少角色声音 | 台词角色标记与已上传参考音频槽位不一致 |
| 前端显示模型但任务走错工作流 | 逻辑模型、业务 code 与 Workflow ID 绑定错误 |

排障顺序固定为：读取 JSON → 检查输入映射 → 检查上传替换 → 检查提交响应 → 检查查询响应 → 检查结果映射 → 检查前端绑定。不要先修改协议路径或复制一份工作流来掩盖映射问题。

## 9. 一期边界

- 不做面向运维人员的正式版本列表、复制版本、切换和回滚。
- 不做本地模型中台、显卡调度和队列优先级。
- 不让学校、老师或学生看到 Workflow ID、节点 ID、API Key 或完整请求 JSON。
- 后台只负责读取、分析、测试、启用和监控；无限练习继续复用现有任务创建、查询、落盘和结果展示。
