# 画布参考图用途多选与原始参考语义约束对齐

**日期：** 2026-09-08
**范围：** VOZEB 统一画布与短剧专属画布中的图片直连生成配置。
**状态：** 需求已对齐，待实现。

## 一、需求结论

参考图用途不是平台自动推断出来的固定提示词，而是用户对每张输入图片的显式控制。

每张参考图默认使用“原始参考”。用户可以主动为同一张参考图选择多个用途；服务端只根据用户实际选择的用途追加对应语义约束。

## 二、原始参考的定义

“原始参考”表示：

- 将图片作为真实视觉输入发送给图片模型；
- 不追加身份、脸部、发型、体型、服装、肤质、姿态、构图、风格、场景、光线等任何语义约束；
- 保留用户自己输入的提示词原意；
- 保留画布现有 `@` 引用及其正常序列化结果；
- 不因为存在图片就自动改变生成类型、自动切换到视频或自动进入 Agent 提示词优化路径。

如果一张图片没有选择其他用途，最终上游提示词不得因为该图片自动增加任何创作语义。

## 三、参考图用途选项

首批用途包括：

1. 原始参考
2. 身份参考
3. 服装参考
4. 肤质参考
5. 风格参考
6. 动作/姿态参考
7. 构图/镜位参考
8. 场景/背景参考
9. 光线/色彩参考
10. 商品结构参考
11. 道具参考

这些选项是用户主动选择的语义角色，不是平台对参考图的自动识别结果。

## 四、多选规则

每张参考图允许同时选择多个用途。例如：

```text
图片 1：身份参考 + 服装参考
图片 2：肤质参考
图片 3：风格参考 + 光线/色彩参考
```

“原始参考”是特殊用途，规则如下：

- 默认每张图片都是“原始参考”；
- 选择“原始参考”表示该图片不添加任何语义约束；
- 选择任意其他用途后，自动取消该图片的“原始参考”状态；
- 如果取消该图片的全部其他用途，则自动恢复为“原始参考”；
- “原始参考”不能与其他语义用途同时生效；
- 平台不能在用户未选择时自动补充其他用途。

## 五、界面位置与显示条件

入口放在画布中间的生成配置节点参数行，也就是用户确认的红框位置：

```text
模型 | 参考图用途 | 画幅/画质 | 镜头参数 | 开始生成
```

交互要求：

- 只有当前生成节点存在图片输入时显示“参考图用途”；
- 纯文字输入时隐藏该入口；
- 点击后在当前生成配置节点附近打开用途选择面板；
- 面板按连接顺序列出“图片 1、图片 2……”；
- 每张图片单独维护自己的多选用途；
- 当前选择需要在按钮或面板中清晰可见，不得缩成用户无法识别的小图标；
- 普通画布与短剧画布使用相同的入口位置、选项和交互规则。

## 六、服务端契约

生成任务必须保存每张参考图的用途选择，至少能够表达：

```ts
type ImageReferenceRole =
  | "original"
  | "identity"
  | "clothing"
  | "skin"
  | "style"
  | "pose"
  | "composition"
  | "scene"
  | "lighting"
  | "product"
  | "prop";

type ImageReferenceRoles = Record<string, ImageReferenceRole[]>;
```

其中 key 是参考图或输入节点的稳定 ID，value 是该图片实际选择的用途数组。

服务端必须遵守：

1. 参考图仍然以真实图片输入发送给上游图片模型；
2. 未选择语义用途的图片只作为原始参考，不追加语义约束；
3. 只为用户明确选择的用途生成对应约束文本；
4. 不根据图片内容、文件名、图片数量或模型类型自动猜测用途；
5. 最终保存的 `upstreamPrompt` 必须反映实际生效的用途；
6. 图片节点复制按钮复制实际发送给上游的最终提示词；
7. 普通画布直连生成不经过 Agent 提示词优化；
8. 不改变透明背景、分层抠图、全景等既有特殊能力。

## 七、验收标准

### 8.1 默认行为

- 连接一张或多张图片但不选择额外用途；
- 最终上游提示词不出现平台自动追加的身份、服装、姿态、风格、构图或场景约束；
- 图片仍按画布连接顺序真实发送给上游。

### 8.2 多选行为

- 图片 1 选择“身份参考 + 服装参考”；
- 图片 2 选择“肤质参考”；
- 服务端只为图片 1、图片 2 追加各自明确选择的约束；
- 图片 1 的约束不扩散到图片 2，图片 2 的约束也不扩散到图片 1。

### 8.3 原始参考互斥行为

- 默认状态为“原始参考”；
- 选择任意其他用途后，“原始参考”自动取消；
- 取消全部其他用途后恢复“原始参考”；
- 不允许“原始参考”和其他语义用途同时生效。

### 8.4 无图片输入

- 纯文字输入时不显示“参考图用途”；
- 生成链路保持文生图或普通文本链路的既有行为；
- 不因为用途配置组件存在而改变生成类型。


### 8.6 最终提示词追溯

- 图片生成后点击复制按钮；
- 复制内容与实际发送给图片上游的 `upstreamPrompt` 完全一致；
- 能够明确区分用户原始提示词、`@` 引用结果和用户主动选择的参考图用途约束。

## 九、明确不做的事情

本次不做：

- 不自动识别图片用途；
- 不根据图片内容自动选择身份、风格、姿态或构图；
- 不自动追加人物一致性提示词；
- 不把参考图自动转成图生视频；
- 不改 Agent 的规划、提示词优化或技能调用逻辑；
- 不改短剧实验室其他非画布业务；
- 不把用途选择扩展为平台全局的素材分类系统。

## 十、实施顺序

1. 将参考图用途数据结构从单值扩展为每张图片的多值数组；
2. 在统一画布和短剧画布的同一生成配置参数行提供用途入口；
3. 实现“原始参考”与其他用途的互斥规则；
4. 将用途选择从配置节点可靠传入实际图片任务；
5. 按用途生成明确、可追溯的最终上游提示词；
6. 验证复制按钮与 `upstreamPrompt` 一致；
7. 对默认原始参考、单用途、多用途和无图片输入进行回归测试。

---

**本次对齐结论：** 参考图可多选用途；“原始参考”代表只传真实图片、不添加任何语义约束；用户自己的提示词是生成意图的主体。
