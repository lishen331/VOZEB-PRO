# 短剧实验室增量分镜与任务栏同步方案

## 需求

- 分镜提取过程中，服务端按模型已经解析出的完整分镜增量保存。
- 前端在任务运行期间自动发现 checkpoint，并立即显示新增分镜，无需手动刷新。
- 已完成、已取消的任务不继续占用任务栏；失败的工作流保留重试入口。
- 任务栏只同步必要的任务状态和进度，不重复读取完整项目或媒体数据。
- 任务结束、失败或取消后停止高频同步；页面刷新后仍可恢复未完成任务。

## 实现边界

本阶段沿用 LocalMiniDrama 的“流式模型响应 + 增量持久化 + 受控短轮询”，不引入 SSE。SSE 可作为未来多实例部署下的优化，但不是本次必需条件。

## 服务端

分镜提取的 `onPartial` 每次保存后同步更新工作流子任务 checkpoint，包括剧集 ID、已保存分镜数量、恢复数量、截断状态和更新时间。工作流查询接口将这些信息作为任务状态的一部分返回。

## 前端

分镜页只在提取任务运行期间轮询工作流；当 checkpoint 的已保存数量增加时执行一次静默项目读取，追加显示最新分镜。任务完成、失败、取消或组件卸载时停止轮询。

任务栏使用 `visible` 任务集合：运行中、待审核和可重试任务可见，成功或已取消任务不再显示。活跃任务存在时约每 2 秒同步；无活跃任务时不保持高频轮询，仅由任务创建事件触发一次即时读取。

## 性能与一致性

- 单个任务只有一个轮询循环。
- 页面隐藏时暂停高频同步，重新可见时立即补同步。
- checkpoint 同步不会替换用户正在编辑的表单状态，只刷新服务端项目快照。
- 最终成功或失败仍执行一次完整读取，保证最终状态一致。
- 若模型被截断，已保存的有效分镜继续保留，并显示部分结果。

## 验收标准

1. 点击“从剧本提取分镜”后，第一个已保存分镜无需刷新即可出现。
2. 后续分镜生成过程中逐步出现，任务栏显示真实运行状态。
3. 任务成功后轮询停止，任务栏不再显示成功记录。
4. 任务失败或取消后轮询停止；失败工作流仍可重试。
5. 页面刷新后，未完成任务仍能重新出现在任务栏并继续同步。
