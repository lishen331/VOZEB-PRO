# Create Agent 与短剧实验室：已确认需求

日期：2026-09-05  
状态：已确认，待实现  
范围：仅涉及 Create Agent 和短剧实验室。Canvas、账户、角色以及用户体系不在本次范围内。

## 当前问题

1. Create 智能模式在用户明确要图片时可能规划成视频。用户无法查看实际调用的 Skill、规划的产物类型或最终提示词。
2. 短剧实验室的分镜提取失败缺少证据、重试和重新检查操作。
3. 短剧实验室的活动任务会挤占侧边栏导航，任务不会立即出现，已完成或已取消的任务仍然显示在活动列表中。
4. 功能修复完成后，需要单独说明 Agent 的上下文和历史媒体参考如何帮助保持同一主体（例如同一只猫）的一致性。

## 第一性原理：附件不是输出类型

图片、视频、音频和文字都是输入媒介，不能单独决定输出类型。用户附加了一张图片，绝不能因此自动把请求转换成图生视频。

智能模式必须先理解当前请求的语义意图，再综合输入内容、所选 Skill 的能力以及模型能力做决策。

| 输入与用户意图 | 正确任务 |
| --- | --- |
| 文字：生成一张猫咪电商主视觉图 | 文生图 |
| 文字：写电商标题和卖点 | 文生文 |
| 图片 + 文字：把它制作成白底电商图 | 图文生图 |
| 图片 + 文字：制作一个五秒商品视频 | 图文生视频 |
| 只有图片：解释这个图片任务为什么失败 | 多模态理解，输出文字 |
| 只有视频：解释这个视频任务为什么失败 | 多模态理解，输出文字 |
| 只有视频：把视频延长三秒 | 视频生视频 |

只有图片或只有视频的请求，也可能是分析、诊断、解释或普通对话。输入模态只是上下文，不是输出指令。

## Skill 能力契约

Skill 不是单一的图片或视频输出标签，而是一组允许的能力组合。同一个 Skill 可以支持文字、图片、视频，或支持多种输入与输出组合。

系统必须持久化并校验“输入模态 + 输出模态”的组合，不能只保存一个图片/视频标签。例如，电商 Skill 可以允许：

~~~ts
[
  { inputs: ["text"], outputs: ["image"] },
  { inputs: ["image", "text"], outputs: ["image"] },
  { inputs: ["text"], outputs: ["video"] },
  { inputs: ["image", "text"], outputs: ["video"] },
  { inputs: ["image", "text"], outputs: ["text"] }
]
~~~

- 用户语义决定本次请求想要的输出。
- Skill 决定该输入/输出组合是否允许。
- 模型决定自己是否具备执行该组合的能力。
- 附件可作为参考、理解或编辑输入，但不能暗示输出类型。

当前风险：规划器可以返回 image、video、audio 或 text，但服务端创建任务时没有强制执行 Skill 的输入/输出契约。修复必须在服务端 fail-closed（默认拒绝不兼容组合），不能只依赖前端文案或规划提示词。

## 智能模式规则

1. 先识别语义意图：对话/分析、文本、图片、视频、音频、编辑或续写。
2. 识别明确输入：文字、图片、视频、音频、附件，以及允许使用的历史素材。
3. 形成候选任务，例如文生图、图文生图、图文生视频、视频与文字生视频，或多模态理解生文。
4. 根据所选 Skill 的能力矩阵和模型能力校验候选任务。
5. 只有在意图明确且能力兼容时才执行。
6. 意图不明确时，询问用户需要文字、图片、视频还是其他结果，不能静默提交生成任务。
7. 意图、Skill 能力或模型能力发生冲突时，显示确认/解决弹窗，不能静默改变用户要生成的产物。

示例：

- 用户要视频，但 Skill/模型只支持图片：提供兼容的 Skill/模型、移除不兼容 Skill，或取消操作，不能静默生成图片。
- 用户要图片，但规划器决定生成视频：服务端拒绝该规划并显示冲突，不能排入视频任务。
- 一个多能力 Skill 同时支持图片和视频：依据用户本次语义选择，不能依据 Skill 名称或已有附件推断。

## Create 执行链路透明度

提交后，在用户消息和结果之间显示一个可折叠的执行卡片。必须展示：

1. 实际调用的 Skill（可多个）。
2. 已确定的输入/输出组合，例如“参考图 + 指令 -> 图片”。
3. 使用的模型。
4. 最终提示词摘要，并支持查看完整提示词。
5. 实际发送给任务的参考图和历史素材。
6. 任务状态、实际错误，以及取消、重试、重新检查操作。

发送后选择器可以清空，但历史消息/运行记录必须保留实际使用的 Skill。执行卡片展示的是可审计的决策和参数，不展示模型内部思维链。

## 上下文与主体一致性

同一主体的一致性既不是模型永久记忆，也不是系统无条件保证的行为。实际流程是：

1. 规划器接收对话摘要和最近上下文。
2. 当用户明确表达“继续”“保持同一主体”“做变体”或“修改”等语义时，规划器可以选择符合条件且成功完成的对话素材。
3. 服务端解析真实的历史媒体，并将其作为参考发送给下游模型。
4. 模型把参考素材与当前文字结合，从而提高主体一致性。

执行卡片必须披露是否复用了历史素材以及具体使用了哪个资源。用户可以移除该素材；历史素材不能在用户不可见的情况下成为隐式输入。

## 短剧实验室任务栏

侧边栏必须有两个互相独立的滚动区域：

~~~text
侧边栏
|- 上半区：剧集/分镜导航（独立滚动）
|- 下半区：运行中 / 失败 / 待检查任务（独立滚动）
   |- 实际状态和错误
   |- 取消
   |- 重试
   |- 重新检查
~~~

规则：

1. 创建成功后，立即将任务 upsert 到当前项目的任务列表；后续轮询只负责同步最新状态。
2. 活动列表只显示运行中、失败和待检查任务。已完成/已取消任务应从活动列表移除，但保留在历史记录中。
3. 任务区域必须有边界和独立滚动条。任务增多不能挤开剧集/分镜导航。
4. 取消操作使用短剧实验室工作流自身的取消行为。
5. 重试操作恢复失败的短剧实验室工作流步骤，不能复用通用 Create Agent 重试接口。
6. 重新检查只同步已有的上游任务 ID，绝不再次提交生成请求。

## 短剧实验室分镜提取

HTTP 202 只能证明工作流任务已创建，不能证明提取成功。根因必须来自证据链，不能靠截图猜测：

~~~text
目标项目与剧集
-> extract-storyboards 请求/响应
-> 持久化的工作流任务错误
-> 工作流步骤/子任务错误
-> 服务端日志
-> 上游模型请求/响应
-> JSON 解析、资产 ID 校验、数据库持久化
~~~

分镜提取必须返回并使用项目内真实的 sceneId、characterIds 和 propIds。不能按名称猜测，也不能生成幽灵资产。

## 实现与验收顺序

1. 增加 Skill 多能力契约，将约束传给规划器，并在任务标准化和直接调用模型的路径上执行服务端 fail-closed 校验。
2. 增加冲突载荷和前端确认弹窗。
3. 持久化并展示 Create 执行卡片，包含实际 Skill、任务类型、模型、提示词摘要和参考素材。
4. 实现短剧实验室双区域滚动侧边栏、任务即时插入、活动任务过滤，以及专用重试/重新检查操作。
5. 获取真实日志，修复分镜提取的具体根因。
6. 在真实界面验证：文生文、文生图、图文生图、图文生视频、视频诊断、视频续写、意图不明确、能力冲突，以及短剧实验室任务创建/失败/重试/重新检查/分镜提取。
7. 单独编写面向用户的说明，解释 Agent 上下文、Skill、历史媒体复用和任务执行过程。

## 明确不在本次范围内

- 不把每个图片/视频附件都当成生成请求。
- 不因为 Skill 名称而将其限制为单一输出类型。
- 不展示模型内部推理，只展示可审计的决策、参数和执行事实。
- 不为短剧实验室工作流复用通用 Create Agent 重试接口。
- 不改变 Canvas、账户、角色或用户体系的行为。
