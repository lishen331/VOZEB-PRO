# 短剧实验室项目风格闭环修复方案

日期：2026-09-11
范围：仅 `VOZEB-PRO/web` 短剧实验室；不修改 Canvas、Agent、普通短剧、资产服务公共协议、任务服务公共协议或成片逻辑。

## 已确认问题

短剧实验室同时存在三类“风格”输入：

1. 项目视觉风格 `project.style`：应当决定角色、场景、道具、分镜图、帧图和分镜视频的视觉风格。
2. 故事生成风格 `storyStyle`：只决定剧本文字/叙事表达，不应冒充视觉风格。
3. 一键全流程 `visualStyle`：当前会被保存到 workflow options，但执行快照和后续步骤仍主要读取 `project.style`，存在“界面已选择、运行未使用”的断链。

## 目标闭环

- `project.style` 是短剧实验室唯一权威视觉风格来源。
- 一键全流程启动时，如果传入 `visualStyle`，先将其持久化到项目，再创建 workflow；后续所有步骤从项目读取同一风格。
- 预置风格继续通过 `resolveDramaLabStylePrompt` 展开为完整中英文正文；自定义风格保留原文。
- 资产提取、分镜提取、首/关键/尾帧文本规划、分镜图和分镜视频都必须继续读取这份完整风格正文。
- 手工编辑镜头提示词只能补充镜头内容，不能使项目视觉风格从最终生成请求中消失。
- 视频链路若使用已有 `videoPrompt`，服务端在最终可见提示词中补充项目完整风格上下文，避免旧数据/手工提示词绕过项目风格。
- 不改变故事生成的 `storyStyle` 语义，不把故事文风强行写入图片/视频提示词。

## 具体实现

1. 在 workflow 启动入口解析并持久化 `visualStyle` 到项目，保证创建快照前已生效。
2. workflow 的 `inputSnapshot.style` 固化本次运行的视觉风格，便于恢复与审计。
3. 生成视频的最终提示词使用项目完整风格正文；保留已有镜头提示词和参考图合同。
4. 增加服务层回归测试，覆盖：
   - workflow 的临时 visualStyle 会写回项目并进入快照；
   - 视频准备结果包含预置风格正文；
   - 故事风格不会被误当成视觉风格。

## 验收标准

- 选择“恐怖/写实/电影感”等项目风格后，短剧实验室后续资产、分镜图、帧图和视频请求均能看到对应完整风格语义。
- 一键全流程选择临时视觉风格后，不刷新、不重新选择，所有步骤使用该风格。
- workflow 恢复后仍使用启动时固化的风格，不受之后项目下拉框变化影响。
- 现有短剧实验室以外模块测试不受影响。

## 非本次范围

- 不改 Canvas 的原始多模态提示词策略。
- 不改 Agent 的技能路由、提示词优化或上下文策略。
- 不改后台模板管理、图片/视频供应商协议及公共任务状态机。
- 不新增管理员配置项，不重构项目数据模型。
