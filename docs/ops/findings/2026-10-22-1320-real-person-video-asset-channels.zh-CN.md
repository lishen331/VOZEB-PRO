## 兔子：令牌没有可用的素材渠道

应用日志今天每次带图的兔子视频都有：

```
[tuzi-seedance] asset ingest failed, falling back to direct reference: 兔子素材上传失败：当前 Token 没有可用的素材渠道
```

用生产兔子令牌直接上传一张 64×64 灰色方块（不是人像）到 `POST /v1/seedance/assets`：

```
HTTP 200 {"message":"当前 Token 没有可用的素材渠道","success":false}
```

- 测试环境和生产用的是**同一个令牌**（指纹 `f1a314f09a15`），所以两边都不行
- 素材上传失败后，按设计退回直接传图。非真人图能出片，真人图被上游拒绝：`The request failed because the input image 'content[1]' ... may contain real person`
- 时间线：10-20 出现过 5 次 `素材适配器配置已变更，请重新上传素材`，说明兔子那边 10-20 改过素材适配器配置。之后令牌所在分组就没有素材渠道了
- 今天兔子真人相关失败 12 次

**15:30 第二次热更新也已撤回**

15:15 上线后两条真实任务都失败，报 `素材地址未返回可下载文件`：

| 任务 | 时间 | 模型 | 结果 |
|---|---|---|---|
| `3ec45071` | 15:24 | doubao-seedance-2-0-260128 | 提交 `POST /v1/videos` 同步返回 HTTP 400 `素材地址未返回可下载文件` |
| `60caad29` | 15:25 | doubao-seedance-2-5-260628 | 同上 |

- 这两条任务里有的参考图审核通过（用 `asset://`），有的重新提交 3 次仍"素材审核未通过"（退回直接传图），同一个请求里两种混用
- 错误是提交时同步返回的 400，上游没有建任务，应该不扣费
- 这条报错不在我们代码里，是兔子返回的。今天热更新之前没有出现过，只要请求里有 `asset://` 就出现。10-10（9 次）、10-20（1 次）也出现过，当时也是素材库刚能用的时候
- 结论：素材审核通过后，用 `asset://` 提交视频，兔子那边拿不到素材文件。这一步我们改不了
- 15:30 恢复原文件（备份 `bak-20261022-151545`）。撤回后行为回到：非真人图能出片，真人图被拒

需要兔子回答：审核 `active` 的 `asset://` 引用，提交 `/v1/videos` 时为什么报"素材地址未返回可下载文件"；和上传用的域名（`api.tu-zi.com` / `apius.tu-zi.com`）有没有关系。

**15:15 处理：上传带 model + 审核失败自动重新提交（热更新已上生产，15:30 撤回）**

兔子回复：火山那边审核会失败，有些素材需要二次提交。实测（3 张 640×480 非人像图，带 model 上传）：

| 素材 | 第 1 次审核 | 第 2 次 | 第 3 次 |
|---|---|---|---|
| #1 | failed（素材适配器已变更或不可用） | **active** | |
| #2 | failed | failed | **active** |
| #3 | failed | **active** | |

结论：同一素材重新调 `POST /v1/seedance/assets/{id}/compliance` 就能通过，不用重新上传。

改动（源码在本地分支 `hotfix/tuzi-asset-model`，基于 v0.8.14；生产先热更新）：
1. 上传带 `model`（当前任务的上游模型）和 `name`
2. 缓存 key 加上 model
3. 审核结果为 `failed` 时，等约 3 秒后重新提交审核，最多 3 次，仍在原 3 分钟总时限内；都失败才退回直接传图

热更新：15:15 写入 `vozeb-pro` 和 `vozeb-pro-generation-worker` 的 `src_1nmpcnr._.js`，语法检查通过，重启 app 后 healthy。备份 `src_1nmpcnr._.js.bak-20261022-151545`。容器重建（发版、回滚）后热更新会消失，正式修复要随版本发布。

单测 63/63 通过（新增：上传带 model/name、按模型分缓存、失败后重新提交、3 次后放弃），tsc 0，prettier 通过。

**14:55 再更正（已被 15:15 的处理替代）：补 model 只修好了上传，审核这一步在兔子那边坏了，仍需兔子处理。**

- 14:20 热更新（上传带 `model` + `name`），上传全部成功，但审核都失败：`素材适配器已变更或不可用，请重新上传素材`，或 `素材审核未通过`
- 用 512×512 渐变图（非人像）在两个域名对比：不手动调 compliance 时，90 秒都是 `pending`、`compliance_started=false`，不会自动开始审核；手动调 compliance 后 5 秒内 `failed`，`素材适配器已变更或不可用`
- 热更新后兔子视频改报 `素材地址未返回可下载文件`（14:33～14:35 共 3 次），今天之前没有这个错。可能和上传了但没审核通过的素材有关，原因未查明
- 14:55 已撤回热更新，恢复原文件（备份 `src_1nmpcnr._.js.bak-20261022-142017`）
- 需要兔子确认：令牌上传成功后，审核为什么报"素材适配器已变更或不可用"；示例里说的"上传后自动审核"为什么没有开始

源码改动（上传带 model）保留在本地分支 `hotfix/tuzi-asset-model`，没有提交、没有推送。等兔子修好审核后，再和这个改动一起验证。

~~修复需要兔子那边处理~~（14:10 更正，已被上面推翻）：令牌本身有素材权限。按兔子给的示例，上传时带上 `model=doubao-seedance-2-0-260128` 和 `name`，同一个令牌返回 `success:true` 和 `asset://` 引用；再调 compliance 后审核正常开始。根因是我们上传时没传 `model`，兔子现在按 `model` 选素材渠道。修复方案见 [开发文档](../../superpowers/specs/2026-10-22-tuzi-asset-upload-model-field.zh-CN.md)。
