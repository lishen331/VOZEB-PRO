二、节点与输入输出

文本节点

文生文文生图文生视频文生音频

输入：节点文本/提示词 + 上游文本。输出：文本内容或媒体结果节点。

不自动追加视觉创作风格；但会执行连接文本拼接。

图片节点

图生图图文生图图片节点重生成

输入：当前图片（若已有内容）或上游图片；可带上游文本。

参考图数量 > 0 时请求类型为 edit，否则为 generation。

视频节点

文生视频图生视频视频生视频多模态参考

输入：图片、视频、音频参考及文本 prompt。由视频模型能力决定可接受的参考类型。

配置节点 / Composer

支持 @[node:节点ID] 选择上游节点，按引用顺序组装文本和媒体；未写标记时使用全部输入。

全景节点

普通文字/参考图之外，会追加 2:1、360°水平覆盖、180°垂直覆盖、无缝边缘等全景约束。

音频节点

输入文本 prompt，调用音频任务接口；不注入图片风格或镜头约束。

四、Prompt 是否被注入

场景是否追加追加内容
只有文字 → 文生图否（无通用隐藏创作提示词）用户 prompt；若连文本节点，拼接上游文本；公共任务层仍会做尺寸/能力/安全/计费处理。
只有文字 → 文生视频否（无通用隐藏创作提示词）用户/上游拼接后的 prompt。
连接图片/视频/音频会媒体作为真实 references 传入，不等于把媒体描述成文字；图片会先 hydrate 为 dataUrl/可上游 URL。
开启镜头控制会[Camera direction] + 相机、镜头、焦段、光圈、景深和保持主体不变约束。
全景节点会[全景输出约束] + 2:1、360°/180°、边缘无缝等技术约束。
参考图角色标记会影响参数referenceRoles 传入图片任务；它是结构化参数，不是自动追加用户 prompt。
Agent 路径另一路径只有显式进入 Agent 才会经过 Agent 规划/技能/多模态模型选择；普通画布按钮不自动走 Agent。

五、图片上游 payload 示意

POST /api/image-tasks { "kind": "generation" | "edit", "config": { "model": "逻辑图片模型", "size": "16:9", "quality": "..." }, "prompt": "effectivePrompt（用户 prompt + 必要的平台技术追加）", "references": [{ "id": "node-id", "dataUrl": "...", "url": "...", "storageKey": "..." }], "referenceRoles": { "node-id": ["identity", "style", "product"] }, "context": { "surface": "canvas", "projectId": "...", "clientRequestId": "..." } }

六、视频上游 payload 示意

POST /api/video-generation-tasks { "config": { "model": "逻辑视频模型", "size": "16:9", "videoSeconds": "5", "vquality": "..." }, "prompt": "effectivePrompt", "references": [ { "type": "image", "role": "reference", "url": "..." }, { "type": "video", "role": "reference", "url": "..." }, { "type": "audio", "role": "reference", "url": "..." } ], "context": { "surface": "canvas", "projectId": "..." } }

七、最终结论

你问的重点答案：
只有文字时，普通文生图和文生视频不会被画布偷偷注入“身份一致性、服装、风格、构图”等通用创作提示词。

但“原样 prompt”也不是绝对成立：连接的上游文本会被拼接；全景节点会加全景合同；镜头控制会加 Camera direction；公共任务服务还会根据模型协议处理尺寸、参考图、能力校验、计费、任务状态和安全约束。

因此，判断一次请求是否被改写，要同时查看：effectivePrompt、references、referenceRoles、config、context，以及服务端任务记录中的最终 prompt。
