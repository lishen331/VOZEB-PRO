### P1-01：只浏览视频参数页签，会把后续纯文字请求强制导向视频

3. 输入：`请只回复：语义验收通过。不要生成图片、视频或音频。` 并发送。
4. 页面仍显示Agent模式，但创建请求与服务端run包含 `generationPreferences: { mode: "video" }`。
5. 任务被规划为 `type: video`，标题“语义验收通过视频”，模型doubao-seedance-2-0；提示词变为白底字幕视频。

验收要求：区分“浏览/设置某类参数”与“显式要求生成某类产物”；冲突不得静默执行。本次只记录缺陷，修复需独立回归。

## 三、上一版计划的对抗性审查：需要修正的12点

1. 源码契约不是线上验收证据；必须固定环境、部署SHA、身份和测试配置。本次已为IP测试环境补齐。
2. 独立新会话用例过多，遗漏“正常浏览参数后继续对话”这种连续操作。已实测造成错误视频生成。
3. “出现completed”不能验证任务目标完成；缺少“我会分析”但不给答案的空交付检测。
4. 图片/视频理解没有盲测基准与上游真实媒体输入证据，可能把文本URL当成视觉输入。需固定素材答案且隐藏在文件名之外。
5. 原计划没有对应线上所有参数控件：自定义像素、输出页签、自定义清晰度、自定义数量、声音/水印开关需各自正反例。
6. Skill用泛称代替线上5个具体Skill，遗漏角色设定、快捷入口与分类导航；每项都应有实际验收案例。
7. 缺少“最近生成”与“灵感发现”的作品复用路径，不能只测上传与全局素材库引用。
8. 资产面板并非只有素材；“我的提示词”“提示词库”的插入/加载更多/跨会话内容范围需要单列。
9. 历史只有刷新测试不足：需新建、返回/前进、批量管理、长历史分页、运行中切换与隔离。
10. 没明确多选模型与数量的组合语义。总数不应凭测试者猜测，各模型结果与重试范围必须能核对。
11. 缺少失败发生层级区分；本次额度错误实际来自被误选的视频任务，归为“文本模型失败”会导向错误修复。
12. 少了配置快照、普通账号成本、取消中的供应商状态、全局设置不可随意修改等验收边界；登录管理员成功不能替代普通用户闭环。

## 四、新增必须执行的正向/逆向用例

| ID | 操作链路 | 通过标准 |
|---|---|---|
| R01 | Agent→浏览视频参数→关闭→只问普通问题 | 仍是对话；不暗中固定video |
| R02 | Agent→浏览音频参数→关闭→请求1张图片 | 不能因浏览音频而TTS；无默默改写 |

| R07 | 视频声音/水印开关、时长、清晰度→发送 | 请求字段与成片匹配；不支持明确提示 |
