## 一、结论

当前**尚未完成全部测试计划**，因此还不能宣布 Agent 全量验收通过；但已完成高风险任务状态链路和主要 Skill 正向/逆向验证，并已定位两个需要优先修复的产品缺陷：

## 四、修复计划

### Fix-1：解除参数页签对 Agent 模式的隐式污染

- 将“打开/浏览参数页签”和“显式选择生成模式”分离。
- Agent 模式下，只有用户明确选择图片/视频/音频创作类型或请求中明确要求媒体时，才写入对应 generation preference。
- 若 UI 当前参数与文本意图冲突，发送前显示确认，而不是静默覆盖。
- 回归 R01、R02、R03，并核对 run 的 `generationPreferences`、tasks 类型和计费调用。

### Fix-2：修复视觉输入的标准多模态传输与空交付

- 规划阶段对视觉模型使用标准 multimodal message/content，不以素材 ID、标题或文本 URL 描述替代图片内容。
- 服务端记录实际引用资产 ID、媒体类型和模型能力，但不泄漏密钥或私密思维链。
- 盲测任务必须满足：读出实际字段；无法读取时明确失败/无法识别。
- 增加相同文件名不同内容回归，防止模型只看标题或历史上下文。
- 回归 R17、R18，并检查上游请求类型、任务状态和助手消息内容。

### Fix-3：补齐混合工作流验收

- 文案→图片→视频按依赖顺序执行。
- 视频任务必须绑定本轮生成图片的 asset ID。
- 部分失败只允许重试失败子任务；成功资产不重复生成。
- 刷新、离开再返回、取消和恢复后状态必须一致。

### Fix-4：补齐 UI/输入边界验收

- 完成参数边界、上传竞态、提示词插入、历史切换、灵感复用和移动端 430px 测试。
- 只修复实测缺陷，不通过增加延时、重试次数或吞错掩盖问题。

### Fix-5：音频配置单独处理

- 暂不接入新第三方服务。
- 后续若配置正式音频模型，只新增受限测试渠道，完成 TTS 生成/下载后再将音频标为通过。

## 五、发布门禁

只有 Fix-1、Fix-2 完成并通过同一盲测回归，且 P1 核心链路有执行证据后，才能宣布 Agent 完整验收通过。当前结论应标记为：**高风险状态链路已通过，完整能力验收未完成，存在两个待修复产品缺陷，音频为环境阻断。**
