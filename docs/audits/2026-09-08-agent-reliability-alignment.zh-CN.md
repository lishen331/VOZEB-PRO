# 画布 Agent 可靠性：需求与验收草案

> 更新：2026-09-08。状态：待用户确认，尚未开始业务修复开发。
> 用户已明确：本会话只管画布右侧 Agent。主 Agent（/create）由其他会话负责。

## 1. 范围边界

- 仅检查与修复 `/canvas/[id]` 右侧聊天 Agent 的实际业务闭环。
- 不修改主 Agent 的页面、参数交互、能力介绍和专属逻辑，不接管其他会话的报告与任务。
- 不把主 Agent 的测试结果计入画布 Agent 的通过清单。
- 共享后端若必须改动，优先采用 `surface=canvas` 限定；确实涉及公共契约时先说明影响并与负责会话协同，不擅自改变主 Agent 行为。
- 底部工具仅作对照与复用来源，不将“一键整理按钮可用”算作聊天 Agent 已具备整理能力。
- 不顺带改短剧实验室、专属复制画布、教育用户体系或后台渠道配置。

## 2. 第一性原理：用户要的是什么

用户要求整理、改写或生成时，要的是画布上的真实结果，而不是一句操作承诺。

`理解意图和目标 → 生成可执行计划 → 校验权限/范围/版本 → 执行 → 持久化 → 展示结果 → 如实反馈`

必须满足：
1. 问答不改画布；生成与结构编辑分开。
2. “读取全画布”不等于“可修改全画布”；自动选中结果不等于用户明确指定下一轮引用。
3. 整理由程序执行真实布局，不能用文字说明替代。
4. 一个编辑目标对应一份结果，多选不能只处理第一个。
5. 正文来自明确写入内容或生成成品，不能从内部执行提示中正则猜取。
6. 图片理解必须传真实可读图片，不以节点名称、旧提示词或URL字符串冒充视觉输入。
7. 页面关闭也能保存结果，回来补齐未应用的结果；重复恢复不重复节点或扣费。
8. 成功、部分成功、失败、取消都如实结束状态。任务completed不等于画布操作完成。
9. 操作可追踪、可撤销；遇到并发修改不能静默覆盖用户新内容。
10. 能力介绍以实际已接入操作为准，不夸大未接入功能。

这些是样例证据，不等于所有组合与所有模型均通过。

## 4. 需要继续做对抗性审查吗？

需要，但不必等所有供应商全部付费测试后才开始修复已证实的问题。

- 保留前次有效证据，不无差别重复测试。
- 补齐画布 Agent 独有的正向流程、逆向流程和回写恢复边界。
- 修复需求可以先形成本文供确认；确认后生成开发任务文档。
- 代码修复后必须重新执行受影响的原失败用例，再进行完整约定范围的正向闭环与逆向回归。
- 未执行、额度不足、环境受阻分别标记，不能写成通过。

## 5. 方案选择

### 方案一：只补提示词或关键词快捷响应
改动小，但解决不了缺少操作契约、错误正文写入和离页丢结果，不推荐。

### 方案二：受控操作契约 + 复用已有画布能力（推荐）
模型负责理解意图、定位目标与规划；程序校验和执行。布局复用现有算法，正文编辑用结构化内容，媒体沿用既有任务链；可靠保存后按实际变化反馈。不重建画布，不另造生成系统。

### 方案三：重写全能Agent/画布框架
影响大且没有必要，不属于本次修复范围。

## 6. 待确认需求

### 6.1 整理与结构操作
- “整理画布”默认只调整位置，不改正文、不删节点、不改连线、不生成媒体。
- “整理选中节点”只调整选中范围，同时避免覆盖其他节点位置。
- 明确移动、对齐、重命名为独立可执行操作；删除、断线、覆盖内容先展示对象与变更确认。
- 分组不等于写分类说明。先核对现有分组数据契约再决定接入，不默认扩展成另一套分组系统。
- 非破坏性明确整理可直接执行并撤销；反馈列出实际变更数量及保存状态。

### 6.2 文本创作与编辑
- 明确指定正文时使用独立content字段；翻译/改写时由模型产出正文。
- 不让文本模型承担“操作程序文件/创建节点”的职责。
- 多选每个目标独立结果，不串原文；部分失败逐项显示。
- 非空文字不等于有效成品；“我会去做”“没有画布”等不能作为整理已成功的证据。

### 6.3 上下文与多模态
- 分开用户明确引用、自动选中、只读理解范围及可修改目标。
- 问全画布问题时可读取必要全局信息，但修改仍受明确目标限制。
- 已选图片接入真实多模态输入；只传需要的图片，不无条件加载全画布所有原图。
- 图片理解与图生图分别验收；视频/音频理解没有可用协议时明确说明，不能用生成能力冒充理解能力。
- Skill、模型、参数按画布入口自身逻辑测试；不导入其他入口的结论。显式模式与语义冲突时生成前确认。

### 6.4 结果保存与状态
- 服务端可靠保存画布变更，或持久化待应用操作并记录确认游标；前端不能成为唯一保存者。
- 重进画布补齐已完成未应用结果；稳定操作ID去重。
- 目标版本变化时提示冲突，不直接覆盖；撤销按一次业务操作组织。
- completed/partial_success/failed/cancelled统一收尾；只重试失败项。
- 暂停/取消区分本地调度与上游实际状态，不声称供应商已取消除非确认。

## 7. 画布 Agent 正向/逆向验收矩阵

| 功能 | 正向 | 逆向/边界 | 当前状态 |
|---|---|---|---|
| 对话/理解 | 普通问答、总结全画布文本 | 不新增节点、空输入、选中但问其他节点 | 部分通过，范围缺陷待修 |
| 布局 | 整理→位置改变→保存→刷新 | 单节点、空画布、循环连线、只整理选中、撤销 | 工具通过；聊天未接入 |
| 文本 | 新建、替换、翻译、扩写、多选 | 保留原意、不漏目标、无操作说明、修改期间冲突 | 已有明确缺陷 |
| 看图 | 盲测识别内容/文字/颜色 | 同文件名不同图、缺图、过期/无权限、无视觉模型 | 已复现失败；边界待补 |
| 文生图 | 请求→单图→预览→保存→刷新 | 不误生视频、无模型、额度不足 | 单图生成及保存通过样例 |
| 图生图 | 一图/双图职责→编辑→结果复用 | 换图、删引用、多选、旧图不被错用 | 隔离部分，完整付费待补 |
| 视频生成 | 文生/图生/首尾帧→播放→保存 | 缺帧、模式冲突、提交不确定、比例时长不一致 | 接口历史证据不代替聊天链，待补 |
| 音频 | 配音→音色格式语速→播放保存 | 无模型、只分析不生成、不支持的输入 | 执行链有代码，真实验收待补 |
| 模型/Skill | 指定模型、智能、已选Skill约束 | 移除不残留、多模型数量、能力冲突 | 隔离部分；逐项UI/生成待补 |
| 批量/依赖 | 文→图→视频及多产物 | 部分失败、只重试失败项、停止后不新增 | 部分终态已发现缺陷 |
| 任务控制 | 暂停→刷新→继续→取消 | 双击、网络断开、离页完成、再次进入 | 规划控制通过；终态恢复失败 |
| 历史 | 新会话、切换、定位产物 | 旧结果不污染新会话、流事件不串会话 | 基础通过，引用范围待修 |
| 保存/权限 | 合法目标→保存成功 | 他人节点、过期版本、重复应用、重进去重 | 越权读取样例通过，其余待补 |
| 结果使用 | 预览、下载、再次引用 | 坏媒体、签名过期、重复引用 | 需逐出口测试，不能只看任务成功 |
| 移动端 | 390/430宽度、长消息、弹窗 | 软键盘、按钮遮挡、触控拖动 | 基础尺寸通过，全交互待补 |

不承诺任意上游模型/网络条件都零Bug。验收目标：约定配置和矩阵内无未关闭阻断缺陷，异常能清楚恢复，不丢内容、不假成功。

## 8. 建议开发顺序

1. 防数据错误和丢结果：正文误提取、多选目标、离页结果、部分成功终态。
2. 整理操作真正接入，复用已有布局与撤销。
3. 文本成品契约、读取/编辑范围、真实多模态输入。
4. 画布Agent媒体、Skill、多模型、批量完整正向及逆向回归。

确认本草案后才生成实现分工、文件边界、共享模块影响、回滚与验收细则的开发任务文档。此处不承接主Agent功能。
