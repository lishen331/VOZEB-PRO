## 三、已确认缺陷与根因

### F1：整理没有操作契约，却显示任务完成（P0）
原任务 agent-0gB4JNZLm8_Gt_4aMcMYf 计划的是 canvas-organization-note，type=text。
本轮 agent-_xU8NQokantwZ23N40mkX 明确要求“不新增整理说明”，仍变成 layout-canvas/type=text；新增正文竟是“当前未提供可操作的画布或 canvasSnapshot，无法执行节点布局整理”。Run 状态 completed，聊天显示“已完成”。
底部工具对照确实将 a/b 从重叠位置移动到不同列，保留 ID/正文/原连线并保存。

根因：agent-run-validation.ts / agent-run-execution.ts 的交付契约只有 text、image、video、audio；surface-policy 却声称可删除、移动、连接节点。底层 canvas-agent-ops.ts 虽有 update/delete/connect，聊天计划并不向其下发这些结构操作。另有 use-canvas-local-agent-bridge.ts，不是当前聊天入口。
布局快照还没有 position、分组等布局事实，不能据此判断重叠。

### F2：把执行指令当成文字成品（P0/P1）
任务 agent-KCD_bQNP83miQRWC4IpRb 要求三句故事。确实新增节点，但其中混入多次“扫描文件树”“定位数据结构”等内容。
根因：把“新增节点、写入……”的操作要求交给文本模型执行；结果验证只要求非空文本，最终直接写入节点。非空文本不代表满足用户要的成品。

### F3：翻译被正则误提取；多选只保留第一个目标（P0）
任务 agent-U_Nfzw-NVFrL2L3g1T7YC 的 snapshot.selectedNodeIds 为 [audit-a,audit-c]。服务端只保留 audit-a 的一个任务，写入“中文并原位保存”，而不是译文。
- normalizeCanvasPlanForSelection 用 find 取第一个文本/图片，重建单条 deliverable，丢失其他目标。
- directCanvasTextContent 对拼接后的 task.prompt 猜测正文，误将统一创作目标“将选中的文本内容转换为中文并原位保存”解析成明确内容，绕过文本模型直接保存。
隔离测试已分别证明返回错误字符串、以及两个目标变成一个目标。

### F4：结果自动选中造成下一轮上下文被悄悄缩小（P1）
有选中结果时问 Story A 的颜色（agent-laJkUbua-AU976c9PPmOe），答不存在。snapshot 实际只保留上一条输出节点。刷新清除选中后同问（agent-jFzOLkkfetDBYaQU-6GIE），正确回答红猫、蓝狗，且不新增节点。
这不是泛化的“模型记忆差”。当前把自动选中/用户明确引用/问题读取范围混在一起；已选节点优先编辑可以成立，但不应据此否认全画布其他节点存在。

### F5：选中图片没有真正进入多模态规划（P0/P1）
agent-ETrERKw3iIT7aWxqWZxzf 对已选 audit-visual 问分格/服装，回答仅有节点元数据。测试图片清除了原 prompt，以免模型只背提示词。
Canvas 提交 assetIds=[]，图片走 snapshot；executor 的 requiresMultimodal 只看 referencedAssets，不看 snapshot 图片；planningInput 又只有 JSON 字符串，没有 image_url/input_image 等真实媒体块。切换到名义上的视觉模型也不能替代传图。

### F6：离页期间完成，画布不补结果（P0）
agent-vPyn3k09Ahlgm86uyfDjg 提交后离开画布，后台 completed；项目里没有对应输出节点。再进入后仍没有，聊天仍为“收到，我会结合当前画布处理”。
前端靠 SSE ops 改节点并由前端保存；重新进入只请求 activeOnly 的 Run，已完成但尚未应用的 Run 被漏掉。必须把任务完成和画布结果落库分开核对。

### F7：部分成功没有正确结束（P0/P1）
后端明确写 partial_success 并发 run.partial_success；画布 watchCanvasAgentRun 未监听该事件，快照/重连也不处理该终态；SSE 路由终态集合亦缺此状态。
隔离事件测试：发 run.partial_success 后 watcher.closed=false，未交付回复。不是泛称“可能转圈”，已经有可执行失败测试。

## 五、建议需求（待用户确认，非已开发）

### 原则
Agent 的任务是理解意图、选中正确操作，然后由程序执行。模型说完成不算完成，必须检查画布的实际变化与持久化。
现有生成和编辑能力分别登记，界面介绍与操作契约使用同一份能力清单；不允许介绍未接入的功能。

### A. 结构操作
- “整理画布”调用现有布局算法，默认只调位置，不改正文、不生成媒体、不删节点、不擅自断线。
- 先支持布局、移动、对齐和重命名；分组只有在确认项目分组语义后纳入。
- 明确“整理选中”仅操作选中；明确“整个画布”作用全局。范围有歧义时展示目标范围。
- 删除、断线、覆盖正文等破坏性操作执行前展示对象并确认。
- 复用现有撤销重做；执行回执写“移动了几个节点”，不能写“完成一个文本任务”。

### B. 内容编辑
- 区分明确正文写入与模型创作，不用正则从整段执行提示里猜正文。
- 一个编辑目标一条结构化结果；多选不能收缩成第一个。
- 文本模型只产出成品内容，新增节点由程序完成；对“无法执行/寻找代码”等元话语不能判定创作验收成功。

### C. 上下文与视觉
- 区分用户明确引用、自动选中结果、只读理解范围和可修改范围。
- 选中图片按后台视觉模型配置发送真实图片内容；视频理解应有明确帧采样/视频输入协议，未接入就不宣称支持。
- 不盲目传整个画布所有原图，按本轮目标读取；布局只需要节点关系和几何数据。

### D. 结果保存与状态
- 由服务端校验项目/节点权限及版本，并可靠应用操作；或持久化待应用操作并记录确认游标，保证浏览器不在也不会漏。
- 返回页面补齐已完成但未应用的操作；按稳定操作 ID 去重，避免重复节点/重复扣费。
- completed / partial_success / failed / cancelled 全部作为明确终态处理，保留成功子结果、只重试失败子任务。
- 检查生成期间用户修改同一节点的版本冲突，不静默覆盖用户较新的内容。

### 建议实施顺序
1. 防数据错误与假成功：F3、F6、F7。
2. 真正接入整理操作：F1，复用已有算法，不重新造布局引擎。
3. 文本成品契约、上下文范围、多模态输入：F2、F4、F5。
4. 扩展媒体/Skill/多模型/批量的付费矩阵与移动端完整操作回归。
