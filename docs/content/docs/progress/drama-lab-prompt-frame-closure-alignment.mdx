# 短剧实验室提示词与三类帧闭环需求对齐

> 状态：已对齐，作为本轮开发约束。
>
> 范围：仅限 VOZEB 的“短剧实验室”模块。本文中的“全局系统配置”只表示短剧实验室内部全局，不表示 VOZEB 全平台全局。

## 一、明确范围

### 本轮要改

- 短剧实验室后台配置页及其 `/api/admin/drama-lab/*` 接口。
- 短剧实验室运行时使用的故事生成、角色提取、场景提取、道具提取、分镜拆解和三类帧提示词链路。
- 短剧实验室项目中的分镜数据、资产 ID 关联、参考图读取、任务状态和历史结果。

### 本轮明确不改

- `/drama/[id]` 剧本创作模块及其 AI 操作。
- 其他图片、视频、Canvas、Agent、练习或通用创作模块。
- VOZEB 平台其他后台配置的模板作用域和运行逻辑。
- 短剧实验室之外的通用提示词、通用图片生成和通用视频生成行为。

## 二、L 的九套系统默认模板

短剧实验室迁入 LocalMiniDrama 的九套成熟默认正文，系统键采用兼容映射，不能继续使用当前简写正文：

1. `story_expansion_system`：故事生成
2. `character_extraction`：角色提取
3. `scene_extraction`：场景提取
4. `prop_extraction`：道具提取
5. `storyboard_system`：分镜拆解
6. `storyboard_user_suffix`：分镜输出要求
7. `first_frame_prompt`：首帧
8. `key_frame_prompt`：关键帧
9. `last_frame_prompt`：尾帧

VOZEB 现有键名保留兼容层，避免旧数据或旧调用失效；运行时最终解析到上述九套短剧实验室模板。

每次调用由服务端组合：

```text
短剧实验室可编辑模板正文
+ 当前项目/剧本/剧集/风格/画幅比例
+ 当前镜头和已存在的真实资产
+ 不可编辑的结构化输出契约与安全约束
```

模板正文可编辑，但不能覆盖服务端固定的 JSON 结构、资产 ID 白名单、角色出场白名单和帧生成约束。

## 三、短剧实验室内部全局模板配置

- 管理员必须通过短剧实验室后台权限校验后才能编辑。
- 每个系统模板在短剧实验室内只能有一份全局覆盖正文。
- 运行时不再按管理员 `user_id` 选择模板，避免多个管理员导致来源不确定。
- “新增自定义模板”不参与短剧实验室运行链路，应移除或禁用；只保留九个已绑定系统模板。
- 删除系统模板覆盖记录等同于恢复 LocalMiniDrama 默认正文。
- 该作用域只影响短剧实验室，不改变平台其他模块的模板存储和读取方式。

## 四、分镜与资产闭环

分镜拆解必须返回并持久化项目内真实资产 ID：

- `sceneId`
- `characterIds`
- `propIds`

服务端逐项校验 ID 必须属于当前项目，拒绝项目外 ID，不按名称猜测，不创建幽灵资产。

分镜同时保存 L 闭环所需的镜头信息，包括景别、机位、时间、动作、结果、情绪和 `layoutDescription`。`layoutDescription` 用于记录：

- 主要角色左/中/右站位、朝向和相互关系。
- 当前镜头实际出现的道具及其真实尺度、相对比例和时代约束。
- 构图、机位距离和为 declared movement 预留的自然演化空间。

生成图片时只读取该镜头绑定的场景、角色和道具主参考图，并注入角色视觉锚点、场景空间合同和道具尺度合同。

## 五、首帧、关键帧、尾帧生成链路

三类帧统一由短剧实验室服务端驱动，前端不得继续使用通用字符串直接调用图片生成：

1. 根据 `frameType` 读取 `first_frame_prompt`、`key_frame_prompt` 或 `last_frame_prompt`。
2. 组合当前项目、剧集、镜头、资产 ID、资产视觉锚点、空间合同、画风和画幅比例。
3. 调用文本模型，只接受固定 JSON：`prompt` 和 `description`。
4. 对文本模型结果执行 L 风格生成后清洗：
   - 允许角色外貌统一引用参考图，不得脑补未提供的外貌。
   - 删除本镜未勾选角色及其站位描述。
   - 清理场景描述中混入的人物外貌。
   - 清理与时代不符的现代道具套话。
   - 清理多余标点和孤立站位片段。
5. 将清洗后的提示词和当前镜头绑定的主参考图送入图片模型。
6. 持久化帧类型、提示词、任务 ID、状态、结果地址和历史版本。

尾帧生成时优先读取首帧作为布局参考，保持核心站位、空间关系和物体尺度连续，同时允许根据运镜产生有意义的构图演化。

视频生成读取服务端已持久化的帧结果和当前镜头资产，不再由前端 `dramaLabShotPrompt()` 拼接替代服务端链路。

## 六、数据与兼容性

- 现有分镜字段和历史结果保留兼容读取。
- 新增三类帧状态、提示词、任务关联和历史版本字段时，不清空已有成功媒体。
- 旧的关键帧/分镜图字段继续可读，迁移后的新链路逐步写入明确帧类型。
- 生成失败只更新对应帧任务和错误信息，不覆盖其他帧或已有成功结果。
- 自动保存与任务回写发生版本冲突时，服务端重新读取项目并只重放任务所属镜头字段。

## 七、验收标准

- [ ] 短剧实验室后台只展示九个绑定系统模板，不能新增无绑定模板。
- [ ] 九套模板正文与 LocalMiniDrama 默认正文一致，可编辑、可恢复默认。
- [ ] 多管理员修改时，短剧实验室运行时读取同一份全局覆盖正文。
- [ ] 分镜拆解返回并保存真实 `sceneId`、`characterIds`、`propIds`。
- [ ] 项目外资产 ID 被服务端拒绝，名称不会被用于猜测映射。
- [ ] 首帧、关键帧、尾帧均先调用对应文本模板，再调用图片模型。
- [ ] 图片任务只带入当前镜头绑定的主参考图。
- [ ] 角色白名单、空间合同、道具尺度和生成后清洗均在服务端执行。
- [ ] 尾帧读取首帧布局参考，视频读取已持久化帧结果。
- [ ] 刷新、重进、失败重试和历史恢复不丢失提示词、关联和媒体。
- [ ] `/drama/[id]` 及其他模块行为保持不变。

## 八、实现顺序

1. 迁入九套 L 默认正文和固定契约，修正短剧实验室内部全局模板存储与 API。
2. 扩充分镜结构和服务端资产/空间合同。
3. 实现三类帧文本规划、清洗、图片任务和持久化。
4. 接通短剧实验室分镜工作台 UI、任务同步、重试和历史恢复。
5. 补齐测试，执行短剧实验室人工验收并提交版本。
