# Agent 全能力测试清单与可复制文本

状态：测试设计，尚未执行线上生成验收。
范围：用户端 /create Agent；不包括完整 Canvas 编辑器、短剧实验室内部生产流程或后台渠道管理。
代码基线：本地 develop，5f9ebad5。线上部署版本与配置需在正式测试前另行核对。

## 一、测试方法

不要把所有测试文本一次发给 Agent。每条用例独立执行，只有标明“同会话”的用例连续发送。
每次记录：账号、页面环境、模式、智能规划开关、实际模型、Skill、附件与引用角色、参数、runId/子任务ID/上游请求ID、开始结束时间、结果及截图。
分三层判断：语义与规划是否正确；请求与任务是否真实执行；结果是否保存并能恢复使用。
“HTTP 200”“生成任务已提交”“目录存在该模型”“前端转圈”均不等于生成成功。
先低成本对话和理解，再单张图片，最后视频和混合工作流；不一次批量执行所有付费测试。
默认普通平台测试账号；管理员与普通账号的计费/权限结果分开记录。

## 三、统一测试素材

- A：清晰产品图——白色猫爪杯，左耳有蓝色小点，杯身无文字。文件名用中性名称，不写识别答案。
- B：独立风格图——奶油黄色背景、暖光、柔和阴影，主体与A不同。
- C：同一产品另一角度图片，用来测试尾帧；不能用与A相同的图片。
- D：含明确错误码和错误内容的截图。
- E：5～10秒普通测试视频，有可辨识动作；先人工记下动作和顺序。
- F：短音频，内容与文件名无关；先人工记下实际内容。

@素材应通过页面“引用”选择对应真实资产；不要只手打一个名字而未绑定素材。

## 五、必须实际点击验证，不能只靠测试文本

1. 上传：加号、拖拽、剪贴板粘贴（仅对页面提供的入口），同文件重复、上传中发送、删除附件。
2. 输入：空文本、超限、不支持格式、一次多文件；当前代码20MiB上限；不应孤立报错或让已上传素材失踪。
3. 引用：@选择、本会话素材、素材库“引用到Agent”、删除引用、失效/无权访问素材。
4. 参数：模式、比例、质量、数量、视频时长、音色、格式、速度、首尾帧；以当前模型支持选项为准。
5. 新建任务即时显示，未刷新也有状态；双击发送不重复任务、不重复扣费。
6. 执行中刷新/离开再返回：恢复同一run，不重新启动生成；断开浏览器网络不伪装为上游失败。
7. 停止：点击后显示取消请求与最终状态；取消不能假装保证供应商一定停止/退款。
8. 失败重试：先修复失败条件再重试，明确范围，不重跑已经成功的产物；不可无原因吞掉错误。
9. 多子任务部分成功：成功结果保留，失败子任务可识别，不显示整个任务全部成功。
10. 如有暂停/继续、重新检查入口，核对实际服务端行为；没有入口按缺口记录，不用API替代UI验收。
11. 执行摘要：模型、Skill、任务阶段、最终提示词可核对；不把模型私密思维过程作为验收要求。
12. 图片放大、视频播放、音频播放、下载、复制提示词、再次引用；最终URL失效/OSS权限也要分层定位。
13. 历史分页、长会话滚动、切换会话时旧结果不串入新会话、最近生成区刷新。
14. 项目交接后返回、再次进入、避免同名重复项目；页面跳转不丢素材。
15. 普通账号的积分变动、取消/失败退款规则、权限隔离；与管理员账号分开测试。

## 六、每条用例的判定证据

| 层级 | 至少记录 |
|---|---|
| 用户输入 | 原始文本、所选模式/模型/Skill、引用资产ID、参数 |
| 规划 | intent、deliverables、tasks类型、dependencies、实际模型及最终提示词；不得泄漏密钥 |
| 执行 | runId、子任务ID、上游请求ID、上游是否接收与完成；仅200不算通过 |
| 结果 | 正确类型与数量；产品/风格/动作是否符合；可预览下载；保存后恢复 |
| 状态与计费 | 前后端终态一致、不重复扣费、重试和取消的范围明确 |

结论填写：通过 / 产品缺陷 / 上游或配置阻断 / 能力待确认 / 未执行。
上游失败不免除产品展示真实错误与保留已完成产物的责任。

## 七、建议第一轮执行顺序

A01 → A02 → A03 → A05 → E06 → B01 → B02 → B03 → B04 → E01 → C02 → C04 → D01 → F01，再补任务恢复、失败重试、历史与交接。

## 八、容易被误判为已支持的事项

- 视觉模型被选择不等于图片/视频已以可理解的形式传给模型；须检查实际请求及盲测内容。
- 上传音频不等于接了音频理解；能TTS也不等于能语音克隆。
- 图片/视频模型目录中有模型不等于生成接口可用。
- 素材主体相似不等于使用了真实参考图，要同时核对引用和请求。
- 同模型用于文本与视觉，两个测试不能合并成“回复OK即视觉通过”。

## 九、对抗性审查后的修订

本计划不再被解释为“全覆盖”或“实测通过”。已进行线上IP测试环境的入口核验、正反向文字/截图分析测试，发现参数页签污染生成模式、截图分析空交付两个高优先级缺陷。
